# 通知与聊天卡顿整改 · 2026-10-03

本轮针对连续来消息、流式气泡和聊天滚动的代码开销整改，保留原有深色外观、过渡、触摸接管与业务功能。

## 已复现的问题与修改

- 通知补位逐卡片读取位置、取消动画、启动动画，再读取下一张卡片。改为先测量整个堆叠，再统一启动动画。旧卡片使用 React.memo，预览文字按内容缓存；全局抬手事件只处理当前手势。
- 流式回复更新末段时，前面已完成的段落也创建新消息对象、重新执行气泡组件和文本清洗。拆出 memo 的 StreamingPart，消息对象按段落内容缓存；MessageBubble 的正文/引用清洗也按内容缓存。
- 历史行的多个回调每次父组件渲染都变化，导致气泡无法复用。气泡增加默认浅比较，动作回调保持稳定，并在布局效果中更新到最新已提交的会话处理函数。不忽略内容、字号、语音、收藏等真实状态变化。
- 滚动反馈事件重复读取高度，动画每帧重新读取未改变的尺寸，已到落点时仍写入 scrollTop；节点变化会重新观察所有原有节点。尺寸改为按 ResizeObserver/MutationObserver 失效更新，区分主动手势与自身滚动反馈，复用缓存、跳过相同落点，增量维护观察节点。保留延后复核和正在生成时的落点追踪。

## 浏览器测量

`scripts/verify/ui-performance.cjs` 使用真实通知、流式气泡和滚动控制器；生产 React、390 × 844 视口、Chrome、4 倍 CPU 降速。组件执行与滚动属性计数仅注入隔离验证包，生产代码不包含计数器。通知连续到达 60 帧，回复末段连续更新 60 次，随后检查高度变化、空节点插入和动画清理。

| 同一验证场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 新通知到达时，保留卡片额外渲染 | 1 | 0 |
| 60 次末段更新，已完成首段额外渲染 | 60 | 0 |
| 一次 24px 高度变化，滚动属性读取 | 139 | 30 |
| 插入不改变高度的节点，滚动写入 | 2 | 0 |
| 原有两个布局节点累计 observe 调用 | 4 | 2 |
| 动画结束后的残留活动动画 | 0 | 0 |

通知位置读写序列从 `读→写→读→写→读` 改为 `读→读→读→写→写`。同时记录 CDP 布局与脚本耗时供后续比较；这些耗时会随主机负载变化，不作为性能承诺或回归门槛。原始结果保存在 `.tmp-preview/ui-performance/baseline.json` 和 `result.json`。

上述为浏览器复现与回归，未测量 Android 真机帧率。本轮不将属性读取下降比例表述为帧率提升，也不宣称消除了所有设备上的卡顿。性能脚本自建并关闭临时服务，模拟账号，不使用真实消息或付费模型。复跑先构建生产前端，再执行对应验证脚本；仅需记录修改前基线时添加 `--record-baseline`，此选项会覆盖本地基线文件。
