# 5.1.5 发布记录（朋友圈改版）

承接 `docs/VERIFY-STATUS-5.1.4.md`（星域改造）。这一轮只动朋友圈，星域与世界层未触碰。

## 一、这一版改了什么

**朋友圈信息架构（向微信朋友圈靠齐）**

- 动态从「一叠卡片」改成**通栏列表**：头像左置 40px、名字与正文同列、条目之间只用一条细线，
  去掉卡片边框/圆角/阴影；点赞与评论合成同一个浅底块。
- 操作从「常摊的 ♡ 赞 / 评论」改成**右下角「···」气泡**，点开才浮出「赞｜评论」；
  管理入口（修改谁可以看 / 删除这条动态）改成**长按自己的动态**，别人的动态不响应。
- 互动入口常驻在**名片之下、动态流之上**（最近互动者头像 + 「N 条新互动」+ 红点），
  不再挤在右上角；没有未读时也保留，否则历史互动没有入口。
- 封面通栏、可点/下拉展开，展开时带压暗层与「更换封面 / 恢复默认」。

**朋友圈设置（⋯ → 朋友圈设置）**

| 分组 | 项 |
| --- | --- |
| 消息与提醒 | 互动消息、新互动红点开关、发布后提示开关、全部已读、清空记录 |
| 谁能看 · 我能看 | 朋友圈屏蔽（不让他看我）、**不看他（她）的朋友圈**、**允许角色查看我的历史动态** |
| 发布 | 默认可见范围 |
| 展示 | 朋友圈封面、**列表密度（宽松 / 紧凑）** |

**两项新能力（不只是设置项）**

- `momentContacts.muted`：不看他（她）的朋友圈。关系状态，跟着联系人行一起备份
  （`sync.ts` 会带上 `momentContacts`）；`blocked` 与 `muted` 是两个方向，写入互不覆盖。
- 历史可见范围：`visibleToCharacter()` 新增时间窗下界，`moments/recall.ts` 走同一个函数，
  超窗动态角色既看不到、也不会再被它触发回忆；默认「全部」= 行为不变。
- 附带：用户可长按删自己的评论（软删 `status='deleted'`，角色评论不允许删）；
  「世界 → 朋友圈」入口角标也受红点开关控制。

**偏好存储**：`src/lib/moments/preferences.ts` 用单一键 `virtugene-moments:<userId>`
（可见范围 / 红点 / 密度 / 封面 / 历史范围 / 发布提示），逐字段兜底 + 旧键一次性并入。
放在 localStorage 而不是 IndexedDB 是有意的：它只影响这台设备上的默认与展示，
不值得为它动 Dexie schema（迁移有「旧数据零丢失」的验收要求）。

## 四、实拍暴露并修掉的问题（脚本只报问题、不美化）

1. 「···」胶囊向下溢出、与浅底互动块**重叠 3px** → 上移到 `top:-6px`，复测无重叠。
2. 展开封面时头像压在裁切出的亮部、字形发糊 → 加 78px 压暗渐变。
3. 设置面板**比屏幕高 42px**、最后一行被切 → 两轮压缩到 `scrollHeight = clientHeight = 798`，一屏放满。
4. 密度文案「首屏能多放一条」与实测不符 → 改为「同屏能看到更多」。
5. 互动条左边缘（x16）与通栏动态行（x0）不齐 → 互动条改通栏行，两档都对齐 x0。
6. 分组标题贴住上一行 → 非首分组标题加细线 + 内边距。
7. 长按菜单**没有遮罩**、点空白不关（菜单还残留进了两帧截图）→ 补满视口透明遮罩，
   三套浮层行为一致；验收同步加断言。
8. 另收敛了 `globals.css` 下半段一版针对旧结构的网格覆盖规则（会把卡片改回 grid、
   给点赞块套第二层背景），旧类名现在引用为 0。

## 六、未完成 / 未验证（不写成"全部完成"）

1. **Android 真机验收仍未做**：键盘、返回键、安全区、长列表滚动、系统「减少动态」；
   朋友圈这一轮的触屏长按（450ms 计时）只在无头浏览器里验证过，真机手感需你确认。
2. **首段延迟没有实测数据**：沿用 5.1.4 的口径，不写推测值。
3. **紧凑档的取舍**：实测两档首屏都只放得下 1 条完整动态，紧凑档多给的是第二条的可见高度；
   文案已按实测改写，若你要"真能多放一条"，需要再压评论块或折叠长正文。
4. **C 档未做**：位置、@提醒谁看、视频——都要动媒体存储，未纳入本版。
5. **历史可见范围的存储位置**：它是本机偏好；导出备份到另一台设备时，那台设备用自己的设置。
