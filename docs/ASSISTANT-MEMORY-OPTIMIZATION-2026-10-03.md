# 助理记忆召回优化

## 本次修正

助理原来的候选排名会让无关事实占用上下文；最近提及的事实即使进入冷却，原话检索仍可能重新注入同一内容。“不要再记住……”虽然被解析为遗忘命令，却先被拒绝提炼分支截走，旧事实没有真正停用。办事记忆检查了回执版本，但没有核验回执所引用的实际待办、动态、日记或日期实例，因此生成期间的更新可能被忽略。

本次在 `src/lib/secretary/memory.ts` 修正这些路径：

- 先按当前话题过滤个人事实，再使用共同排名函数。明确的表达偏好仍可辅助相处方式；排除“喜欢、记忆、用户”等泛化匹配。短句提起同一主题时允许重新召回，换话题时不带入无关个人事实。
- 冷却或预算未选中的结构化事实，不通过其原消息重复进入历史资料。保存和原始聊天仍保留，不使用永久禁词或预设物件主题。
- 已解析的遗忘命令先进入真实遗忘处理。“不要再记住沈阳”会删除匹配记忆并抑制旧证据，不只是停止提炼当前句子。
- 相同待办及日期、动态、日记和草稿操作只提供一次进展；候选任务按相关程度及新旧顺序排列，减少多个回执占用上下文。
- 只为实际打包的资料记录来源版本。生成返回时核验任务原始请求及其修订、真实待办/动态/日记版本、日期实例版本。尚未生成的日期实例也保存“当时不存在”，生成期间新完成该实例会使旧答复失效。此读取不会补建实例。
- 使用日记或日记衍生草稿的召回标记需要解锁；生成期间重新锁定后不提交旧资料答复。
- 有效记忆读取批量取得去重后的原消息与账号墓碑，避免同一证据按每条事实重复访问数据库。用户、助理、私人会话和修订核验保持一致。

未改变助理的工具权限、日记授权、原始资料存储或聘用延续方式。有限历史检索和后台索引回填继续使用现有实现；未命中不能据此声称用户没有说过。

## 验证

记忆专项从60项增至76项，加4项窄屏布局检查。新增场景覆盖无关信息排除、短句重新提起旧话题、表达偏好冷却、不通过原话绕过冷却、否定式遗忘、重复任务回执、实际记录变化、原请求撤回、周期日期实例在生成期间首次完成、日记生成期间重锁。

使用真实Chrome、IndexedDB及React交互，模型HTTP响应采用替身；不读取实际用户数据，不证明真实模型在所有自由表达下的表现。

本轮 TypeScript 检查和生产构建通过。助理完整验收通过875项数据检查、139项界面检查；助理记忆76项与4项布局检查通过。统一记忆46项、注意力64项、记忆最终回归47项、连续性77项、角色记忆141项与角色创建19项均通过。生产构建仍有既有的分包与大体积文件提示。
