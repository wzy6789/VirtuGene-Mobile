# 助理工作记忆：问法、长历史和接续

本轮继续优化用户说过的信息能否在需要时找回。统一存储、来源修订、纠正、遗忘、账号隔离及聘用延续仍沿用现有记忆系统，没有另建一套事实库。

## 解决的问题

原来的事实匹配主要依赖字面重合。“我在苏州工作”可能无法匹配“我在哪上班”；短句接话不使用前一条用户话题。历史索引只保留最前面的96个词元，查询又只使用最前面的24个词元。常见关键词的候选还会先占满上限，长消息和较早资料容易被漏掉。即使检索命中了，消息仍固定截取开头，后半段的关键内容没有提供给模型。

另外，一条原话只提炼了部分事实后，整条历史消息都被跳过，其余工作信息消失。表达偏好进入话题冷却后不再影响回应。最近聊天没有加入来源版本检查，生成期间改写旧原话仍可能提交过期回答。

## 现在的行为

- `recall-query.ts` 统一事实匹配和索引词元。支持工作、住址、称呼、表达要求、饮食与饮品偏好的常见问法；仅作为召回线索，不推断地点、病症或偏好。单字匹配限短句，避免长问题碰到一个汉字就召回无关事实。支持用户自己提供的两字母简称及连字符英文名称。
- 明确的短句指代可取当前聊天上一条可见用户消息的最后一个主题片段。换话题和新会话没有前文时不会硬接旧主题；锁定日记的内容不能充当检索锚点。
- 索引覆盖完整消息，查询在全句分散选词并优先保留名称与类别。先读取稀有关键词，再按匹配程度及日期选取候选，避免“项目”“会议”等常见词占满名额。最多32个查询词元、512条索引候选，最终128条索引命中；包括有限近期回退后，消息不超过384条、任务不超过192条。
- 索引版本升为2。旧的已完成索引也会按每批128条消息重新回填，复用现有表和派生缓存，不阻塞首轮读取整个历史。索引未完成或候选被截断仍标明有限覆盖，不能声称已经查遍。
- 历史原话只去掉已提炼事实的证据片段，保留同一条消息中未提炼的其他内容。纠正、遗忘或拒绝记录的来源继续按墓碑抑制，不能借片段恢复。旧证据无法定位时保持保守排除。
- 长历史提供与当前问题相关的900字内片段，长近期聊天提供1200字内片段。原始消息保持完整，片段引用仍核验原消息版本。
- 话题冷却用于减少复述；称呼与文风等 `responsePreferences` 会持续指导回应。它们来自同一份已核验事实，不是第二份记忆；最多补充4条，并受相同预算、纠正、遗忘和版本检查约束。
- 明确询问以前办事的进度时，跨会话提供最近的真实回执及实际记录状态，不要求用户重报每件任务名称。草稿与发布分别描述，概览不复制草稿正文。角色代发只提供原始回执的状态和收件人标签，跳过镜像回执，不读取角色其他私聊，也不从“生成中”推断已有回复。
- 最近可见聊天也加入版本引用。历史片段、近期聊天、事实和任务来源在生成期间改写或删除，旧答复会被拦截。检索返回前再次核验账号；日记锁定仍按现有隐私范围过滤。

语义线索是一组有限的本地规则，不是向量检索，也不保证任意同义表达都能命中。未提炼的信息可以从原话检索，但只有用户稳定自述与明确记住的内容才进入长期事实。历史计划不能当作已完成事项，记忆不能替代当前授权。
