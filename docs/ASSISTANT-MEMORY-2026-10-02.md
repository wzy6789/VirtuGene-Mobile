# 助理连续记忆

## 问题与行为

助理原来只取当前会话最近16条消息和4条办事记录。角色记忆服务有意拒绝助理，以保持两套身份与权限隔离，但助理没有自己的长期取用入口。因此换会话后容易忘掉用户信息，旧任务和草稿也无法在对话中连续查找。

现在由 `src/lib/secretary/memory.ts` 统一取用私人助理工作区的用户信息、偏好、旧交流和实际任务进展。助理身份仍由账号绑定确定，改名、换会话和重新聘用保留账号资料；旧任期记录明确标为交接资料，不让新助理冒称自己亲历。记忆不改变办事权限，不自动接着执行旧任务。

## 保存与纠正

- 单独说“记住：……”直接保存原话，无需模型返回。查看及忘记长期记忆也使用本地确定性处理。组合任务继续进入原有规划路径。
- 普通聊天可在同一次规划响应中返回 `memories:[{kind,quote,replacesId?}]`。应用只接受当前用户消息中逐字存在的稳定自述，不接受模型编造、引述、星域剧情、临时情绪、问句和未来计划。无效的可选提炼不会影响其他独立操作。
- 明确纠正时，`replacesId` 必须是本轮实际提供的旧记忆ID。新事实写入、旧事实停用和任务进入ready在同一事务提交。任务重试不重复提炼。
- 沿用既有 `memories` 表及记忆台账、来源修订、证据片段、墓碑、备份与同步，不增加第二份用户事实存储。每条事实保留原用户消息和版本，来源删除或改写会失效；独立确认可保留尚有效的证据。

“助理更多操作 → 助理记忆”显示当前有效信息，支持纠正和忘记。编辑页校验来源归属及版本，过期页面不能覆盖新修改。忘记保留原聊天给用户查看，但原证据、旧列表回复和旧同步数据不再进入助理提示词。明确不让记的消息也从长期原话检索中排除。“忘记全部长期记忆”同时停止调用以前的非结构化个人陈述；后来新提供的信息仍可重新记住。

## 调用范围

当前会话仍提供最近交流。长期召回跨该账号助理的私人会话，按当前话题排名、去重和最近实际提及冷却；只打包选中的条目。旧交流最多4条、任务进展最多4组、结构化事实最多12条，长期资料总预算5000字符。已选事实的原消息不再作为另一条历史证据重复注入。

任务进展重新读取当前待办、单次步骤及日期实例，区分取消、完成和系列安排；步骤完成不会变成父待办完成。朋友圈草稿在用户问起时提供原文并明确尚未发布，已发布或撤回状态读取实际动态。日记仅在明确提及且解锁时提供记录标题/日期，正文仍通过本次授权查询读取。使用过日记的整理资料在锁定时不进入旧交流和草稿召回。

任务只保存真正注入的记忆、消息和记录ID及版本，回复保存实际提及的记忆ID。规划返回后再次检查账号、任期、当前请求和长期证据；中途忘记、纠正、撤回或切换账号会阻止迟到回复提交。

普通角色的记忆继承候选排除助理，显式指定ID也不能绕过；普通角色、群聊和星域继续使用角色共同入口。助理不会因此批量读取其他角色聊天、角色记忆或星域。每日整理继续只使用用户勾选的日期和来源，不附加长期资料。

## 验证

运行：

```powershell
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build
node scripts/verify/build-secretary.mjs --with-regressions --with-domain-regressions
node scripts/verify/run-secretary.cjs
node scripts/verify/run-secretary-regressions.cjs secretary-memory memory-unified memory-attention memory-final memory-continuity character-memory character-create
```

新增 `secretary-memory` 包含60条真实IndexedDB、请求和React交互检查，另外检查320、390、430px列表与320px编辑界面共4项。覆盖跨会话、明确/自动保存、重复确认、独立证据失效、更正、忘记及拒绝记录、旧同步防复活、普通角色隔离、任务/步骤真实进度、跨会话草稿未发布、日记衍生资料锁定与解锁、旧交流检索、解雇重新聘用、迟到回复、账号切换、实际管理菜单和数据库重开。

模型HTTP响应使用替身，不读取用户真实数据；真实模型的自然语言提炼与表达质量仍需实际体验。本次更新代码，未制作APK或发布。
