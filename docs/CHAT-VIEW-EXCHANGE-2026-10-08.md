# 看法交流与求助区分（2026-10-08）

## 本轮改动

在 `chat-expression-boundary.ts` 增加仅用于表达引导的 `isViewExchange`。明确的“你怎么看”“你同意吗”“告诉我你自己的看法”按交流观点处理；同一条消息中明确要求写回复、给方案、看报告或处理事情时，保留求助路径。引用、第三方转述、假设和否定不作为本轮邀请。它不是应用操作授权，也不是完整语义分类器；原消息仍送给模型。

私聊动作选择和会话意图使用同一判定。“告诉我你的看法”不再因“告诉我”自动变成办事请求。当前引导替换了原有更长的观点段落：强调人物自己的立场，以及用户原话与历史模型猜测的区别，没有新增质检调用或自动重写用户文本。具体补问仍允许。

## 验证

- chat-expression：544 项通过，包含看法交流与明确求助并存、否定、引用、转述等边界。
- chat-quality-complete：204 项逻辑与模型边界、7 项真实面板 UI 检查通过；该套件不调用付费模型。
- TypeScript：通过。
- Flash：两个实际预设人物（林霜、苏格拉底），各两轮新对话，使用隔离 IndexedDB 和真实私聊发送链路。四次真实提供方调用，输出上限每次 400 tokens，全部正常结束，没有重放旧回复，没有使用用户聊天数据。服务器摘要、记忆提取与结算被替代，上游非流式。
- 提供方报告输入 6,494、输出 1,031，共 7,525 tokens；没有未知用量。原始证据分别保存在 `CHAT-FLASH-VIEW-EXCHANGE-2026-10-08.json` 和 `CHAT-FLASH-VIEW-EXCHANGE-USAGE-2026-10-08.json`。连接关闭，密钥未存入报告。

## 结果与限制

林霜第一轮仍给出安排建议并追问“你是哪种”；第二轮能够就观点表达不同意见，但“提前说……不算失信”仍过于绝对，忽略具体约定和对方成本。苏格拉底能够区分独处意愿和既有约定，但仍较长、带训话感，把“给自己定罪”等未说明的心理带入讨论，并复述了部分引导措辞。两个人物关注点仍相近。

这批样本证明链路、调用预算和本轮引导确实接通，不能证明自然度整体提高。仅两个角色、一个情境、每人两轮，没有盲评和重复对照，不外推到长聊、其他角色或手机体验。观点交流默认变成说教的问题仍开放。下一步应先检查人物原始判断习惯和样本是否本身过度劝服，并用不同情境小样本校准；不继续堆叠泛化禁令，也不把规则级质检冒充性格验收。
