### 连续办理、取消与字段合并

- `conversation.ts` 定义理解、补充、选择、确认、执行、完成、暂停、取消和失败状态。每轮先处理独立控制意图，再接收当前问题的回答。取消只结束尚未执行的事项；已保存记录不会因“算了”被擅自删除。明确命名为“算了”的待办仍可创建。
- `pending-context.ts` 保存原任务、已知字段、待补字段、来源消息版本、任期、日期解释依据、候选版本与多项选择。重复日期可以合并；明确改口替换相应字段；两个冲突时间给出选择；无时段的“三点”补选凌晨或下午。跨午夜的相对日期仍使用原请求的日期依据。
- 待办、日记内容、朋友圈草稿/发布范围、历史查询、页面目标、重复间隔及多对象选择接入接续。已完成的单项待办通过工作区焦点支持跨聊天修改；后续外部修改、原消息删改、遗忘来源或换任期都重新核对。
- 多项待补充可以选择先处理哪项，成功后再接下一项；暂停保留，明确恢复才继续。补对象名称时核对真实自有记录，新的完整指令交回正常理解，不写成名称或正文。
- `operation-contract.ts` 保存当前指令位置、字段来源和前置操作序号。新规划契约按项校验，单项格式错误不丢弃其他有效项；前置未成功则依赖项失败，独立成功项保留，重试只处理未成功项。否定和引用语境不会因截取证据而被删掉。
- 额外收尾：只给时间但不要求提醒、重复安排缺开始日期，均保存具体补问并可本地接续；不擅自添加提醒。

### 检索与记忆

- 数据库增量版本为 v30：新增助理检索与游标表，消息、会话和任务增加对应复合索引。原消息、日记、待办和朋友圈数据保留。
- `retrieval.ts` 先查所有者/助理专属关键词候选，批量读取真实消息及任务；旧历史每批128条后台建立索引，不让首次办理等待全量处理。常规消息候选上限384条、任务候选上限192条；回退最近有限会话与消息，不扫完整聊天正文。
- 索引不存聊天正文，候选仍核对原表版本和归属。编辑、删除、来源遗忘同步使索引和相关焦点失效，后台回填不能恢复已遗忘来源。普通角色私人消息不进入助理工作索引。
- 检索明确标注有限候选与建索引状态，模型不能将未召回说成历史中不存在。稳定记忆、来源失效记录以及部分待办/收件箱读取仍有范围扫描，不声称所有历史读取都已消除扫描。

### 提醒与真实回执

- `todo-reminders.ts` 将数据库记录和原生调度分开：排队、待开权限、系统不支持、系统已安排、安排失败、旧通知待取消及结束状态独立保存。仅原生接口确认并能在系统待安排列表核对到通知 ID 后显示“系统已安排”；不推断用户已收到。
- 旧通知取消失败先保存待取消状态，不安装替代通知。改期、完成、恢复、取消和删除通过同一恢复流程处理；启动与返回前台重新核对权限和系统队列，丢失的调度可以恢复，同用户恢复串行执行，稳定 ID 防重复。
- 浏览器显示需手机应用支持；权限由用户点击开启，不因聊天请求自动弹授权。旧备份导入提醒置为待核验，不复用外部设备的成功状态，不自动执行旧建议。
- `readNotificationReceipt` 统一读取当前待办、日期实例和原生回执，聊天、卡片及收件箱复用；改期后旧版本“系统已安排”立即失效。单次完成、或重复系列中的某次完成，不再显示该日期排队中的提醒。
- 办事文字仍由应用生成；四种回应模式的自由文本统一经过声明保护。自由闲聊的保护仍含保守规则，尚不能证明任意真实模型措辞都已穷尽。

### 人物、手机界面与主动协助

- 五种性格的受控办事表达扩大短句变化，事实和执行权限统一。真实模型的长期性格稳定性、重复关心和复杂表达表现尚未据此认定达标。
- 成功卡片默认展示事项、时间、实际状态和查看操作；来源、详情及撤销展开后显示。聊天正文避免重复完整结果。零操作补问和多项选择提供对应控件，按钮通过真实聊天发送流程接续。
- 字号刻度由输入框 Aa 按需展开；沿用现有字号。每日整理将日期和补充事实折叠，读取范围直接可见；只记住待办与输出类型习惯，私密日记不沿用上次授权。
- `proactive.ts` 与首页建议卡由用户自选开启，基于真实记录提供优先事项、相同时刻安排检查、未补完整事项、未完成步骤和晚间整理入口。可以忽略、延后或关闭；指纹不变不反复出现；不静默改期、保存或发布。

## 无操作补问的连续对话与全分支声明检查

本轮修复评审复现的“明天开会，记得叫我 → 几点 → 下午三点”及“记成待办还是日记 → 待办”断链。新增 `pending-context.ts`，即使规划没有操作，也在原任务上保存已知标题/日期/时间、用途、缺字段、原任务引用及每条用户来源的会话和版本。聘用绑定只保存当前补问任务 ID，因此插入闲聊、数据库重开和新会话后仍可直接取到这个事项；明确补时间、选用途、补内容不调用模型。用途歧义由本地先问，丢弃模型猜的操作，不从猜测标题建记录。

每轮合并前及实际写入事务内复核来源消息内容、版本、撤回状态、会话归属和任期。原请求或中间补充被修改/删除后停止，清除当前指针并将上下文失效；换助理不能凭短答执行旧任期安排。暂停不撤销，普通时间短句不会继续暂停事项，明确说继续才能恢复。同一完成请求重复运行不增加待办。接续任务进入执行记录后仍使用原事务和幂等机制。任务上下文和绑定指针沿既有任务/聘用字段备份，无新增表；导入不重新激活短答执行，仅保留原消息供用户手动重新安排。

新增 `truthfulness.ts`：casual/advice/clarify/work 均检查无证据的应用操作或提醒声明，覆盖“闹钟已经设好，到点我叫你”、换行、问号及表情穿插；办事回执继续使用受控本地表达。只有当前用户请求中确实出现的引号原文可作为引述保留，不能让新增引述包装假执行声明。自由文本检查仍是保守规则，不能据此保证任意模型措辞都已穷尽，后续需真实模型对抗验收。

范围说明：本轮交付的是无操作补问的持久接续闭环，主要覆盖创建待办、提醒日期/时间与记录用途。完整对象焦点、多候选、多操作依赖、复杂改口、检索索引、提醒 outbox 仍未交付。普通历史读取仍有扫描；本地补问接续跳过最近任务历史读取，不能因此宣称历史检索已优化完成。未扩展提醒成功含义，保存待办仍不证明原生调度成功。
