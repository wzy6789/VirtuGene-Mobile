# 来消息通知界面

本轮调整应用内部普通聊天的新消息提醒，组件保留 NotificationCloud 名称及既有通知存储接口。

## 视觉

- 深色卡片使用 #1b2438 实体表面、#35415a 细边、#f0f2ff 姓名和 #b1bad0 预览文字，紫色/青色仅用于细线、新消息标签与头像信号点。移除旧的大面积渐变、模糊光晕和循环扫光。
- 20px 圆角、紧凑头像、清晰姓名及最多两行正文。消息预览经过已有正文归一化，超长姓名和正文不会撑出屏幕。
- 手机上位于状态安全区及标题下方，左右各留 12px；桌面最大宽度 440px。浅色使用相应的实体表面与较深文字。
- 正文区域整体可进入对应会话，关闭为独立 48px 按钮，不需要额外“查看”胶囊。

## 动作与生命周期

- 360ms 阻尼入场、190ms 轻上移淡出，剩余卡片 280ms 平滑补位。完成后取消变换层。
- 向上拖动可收起，短拖动可撤回，向下拖动有 9px 内的阻尼。方向先锁定，松手速度只在最近 100ms 内有效，避免按住后误判甩动。轻点、拖动、关闭互不误触。
- 动画期间按住即在当前位置接管，取消后回弹。每帧只更新 DOM，不触发通知列表 React 提交。
- 单条独立停留 5.5 秒。新通知不重置旧通知计时；悬停、键盘焦点、按住和页面隐藏暂停计时，离开后继续剩余时间。保持最多三条的既有上限。
- 点正文保留原有聊天入口与返回路径；关闭和 Escape 不导航。退场时立即 inert、aria-hidden，账号切换立即清空，不留下消息快照。
- 系统/应用减少动态效果跳过入场、退场及补位动画，并支持取消正在执行的动作。读屏礼貌提示发送者，正文由按钮的可访问名称提供。

- 类型检查、Vite 生产构建、定向 diff 检查通过。构建仍有已有的大包及混合导入提示。

- `node scripts/verify/run-touch-fluidity.cjs`：31 项原有触控与聊天滚动回归通过。

测试使用隔离浏览器来源，进入会话接口以测试替身记录，没有访问用户实际数据或发出系统通知。本轮没有修改 Android / Electron 的系统通知外观，也没有测量真机帧率。
