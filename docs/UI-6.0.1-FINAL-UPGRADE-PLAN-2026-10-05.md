# VirtuGene 6.0.1 最终 UI 升级方案

日期：2026-10-05。状态：调研及设计定稿，尚未执行本文新增产品改动。承接第一轮视觉升级，不重复重建已落地的令牌、图标、小球和物理动效。6.0.0 安装包冻结；数据、功能范围、导航结构及既有业务契约保持不变。

方向：**深空底色、清晰阅读、精细表面、有回应的小星**。科技感由紫青光线与连续运动表达，文字和操作保持安静。小星承担记录与状态反馈，角色头像继续承担身份识别；助理仍以用户命名和原有头像为主体。

## 1. 对来稿的取舍

| 来稿建议 | 决策 | 修改后的落点 |
| --- | --- | --- |
| 特效严格消费品牌令牌 | 采纳 | 氛围颜色和可操作强调色分离；危险红、提醒金继续保留 |
| 角色在场、里程碑编排 | 采纳 | 对真实输入/生成/完成事件作局部回应，使用已有关系事件 |
| 静态纹理 | 小范围试用 | 只用于英雄区域与空白氛围，不铺在正文、输入、设置项后方 |
| 每个效果有降级链 | 采纳 | 减少动效、隐藏、滚动、输入、弹层覆盖各有明确规则 |
| 全头像持续呼吸 | 改为事件驱动 | 非活跃头像静止，当前角色生成时才显示静态或短暂状态环 |
| 四级液态玻璃、照抄 blur/saturate 数值 | 不照抄 | 三类材料：阅读实底、重点柔光、浮层高光；原生默认不模糊 |
| 全局动态 shader 优先 | 不进入 6.0.1 正式实现 | 独立实验可评估，当前不加运行时依赖、不让首屏等待 WebGL |
| 问候/空态逐字模糊出现 | 改为整段显现 | 文字立即可读，只动画容器，避免中文拆字和模糊重绘 |
| 关系提升自动增加背景粒子 | 不采用 | 关系事件改变一次性纪念呈现，不持续增加阅读噪声 |

来稿的“零 GPU 开销”不能成立：CSS 渐变、滤镜、SVG 路径更新都有绘制或合成成本。当前小球使用共享 rAF 与 SVG attribute 更新，并非完全无循环；现有渐变与短时接力也不应被描述为静态上限。

Apple 官方介绍的是实时反射、折射和随上下文变化的材料，没有在本次来源中给出可直接照搬的 CSS 模糊/饱和度配方。`backdrop-filter` 可营造类似层次，不能等同其原生材料实现。[Apple 官方设计介绍](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/)

Paper 的 `speed` 是运动速度，不是帧率限制：源码在速度非零时继续请求 rAF。MeshGradient 文档还提供像素比和像素总量约束，说明需要单独控制渲染负载。“speed=0.1 即省电”“天然锁 30fps”均不能作为结论。[MeshGradient 文档](https://shaders.paper.design/mesh-gradient)，[实际调度源码](https://raw.githubusercontent.com/paper-design/shaders/main/packages/shaders/src/shader-mount.ts)

## 2. 调研对象与可迁移结论

本次读取官方仓库、组件源码和设计文档。以下“如何迁移”属于针对 VirtuGene 的设计判断；没有完成这些产品的真机横向性能测评，也不以 star 数作为视觉质量证明。

| 对标 | 已核对的依据 | 对 VirtuGene 的迁移 |
| --- | --- | --- |
| Lobe UI | 官方将 ChatHeader、ChatInputArea、ChatItem、Skeleton 与 Mobile SafeArea/TabBar 分成独立组件；ChatHeader 使用三段布局 | 聊天身份、主要操作和次级操作有明确区域；阅读与氛围分离，统一移动端边界 |
| Open WebUI | MessageInput 源码含生成时停止按钮、附件错误状态等实际操作状态 | 发送/停止占位稳定，错误可恢复，已有功能的入口可发现；不引入尚未存在的附件能力 |
| SillyTavern | 官方 UI 文档区分 Flat/Bubbles/Document 阅读方式，并提供 No Blur、No Text Shadows、Reduced Motion | 默认先保长文可读，装饰可退；不照搬大量参数和高密度面板 |
| Linear | 官方重设计文章强调减少视觉噪声、对齐、表面层次、统一深浅主题及对照原型 | 对同一类页面统一表面、标题和操作位置，先以真实内容比较再推广 |
| Material 3 Expressive | 官方物理系统区分 standard/expressive，处理手势打断与重定向 | 页面和任务采用克制阻尼，小球/成功回应使用局部表达，保留现有物理底座 |
| React Bits | 动效参考丰富，但检查的 BlurText/ShinyText 源码引入 motion/react | 只参考“一次显现、局部光泽”的视觉意图，用现有 CSS/WAAPI 独立实现 |
| Paper Shaders | Apache-2.0、canvas shader、固定版本建议 | 可作离线材质探索或独立实验参考，正式版暂不引入 |
| Vaul | 当前 README 明确标注 unmaintained | 不选作新增弹层底座，继续精修现有 Modal 和手势 |

来源：[Lobe UI 组件文档](https://ui.lobehub.com/sections/chat/layout)、[Lobe UI 仓库](https://github.com/lobehub/lobe-ui)、[Open WebUI 输入区源码](https://raw.githubusercontent.com/open-webui/open-webui/main/src/lib/components/chat/MessageInput.svelte)、[SillyTavern 官方 UI 文档](https://github.com/SillyTavern/SillyTavern-Docs/blob/main/Usage/User_Settings/uicustomization.md)、[Linear 官方重设计](https://linear.app/now/how-we-redesigned-the-linear-ui)、[Material 官方运动系统](https://m3.material.io/styles/motion)。

## 3. 视觉规范定稿

### 材质和颜色

- 保留 `theme-tokens.css` 的深空蓝黑底色与紫青品牌，不另建配色层。默认深色先设计，浅色独立纸感校准。
- 阅读实底：气泡、设置列表、表单、密集卡片不使用动态背景、噪点或玻璃模糊。
- 重点柔光：助理今日重点、角色首屏、世界入口允许顶部低亮度光泽，单一局部氛围层不穿过正文。
- 浮层高光：通知、弹窗、导航用边缘高光与不透明表面区分前后。Web 上小面积玻璃试验以 8–12px 静态 blur 为起点，同屏最多一个；原生默认保持当前无 blur 策略，真机证明可用后再调整。数值是设计试验起点，不是 Apple 配方。
- 静态纹理试验从 1%–2% 可见度开始，比较压缩体积和实际截图；不用每帧 feTurbulence。若明显降低文字或图片清晰度，直接去掉。

### 字体、图标和布局

- 正文目标 15–16px、行高 1.65–1.8，聊天继续尊重字号设置；说明 12–13px。主标题 20–24px，重点数字保持 32–34px。
- 中文不套用英文展示字的负字距，不对正文使用渐变、发光、阴影、逐字动画。拉丁品牌字保留现有签名工艺。
- 使用已建成的 Icon 24px / 1.5px 描边体系继续迁移遗留符号；角色头像、用户内容 emoji 保留其数据身份。
- 沿用间距/圆角令牌；列表内部分隔优先替代“卡片套卡片”。主操作可触区域至少 44px，紧凑 36px 视觉按钮扩展点击区域，确保相邻不重叠。
- 搜索框与聊天框采用首页已认可的圆角矩形和安静描边；焦点提示可见但不恢复粗紫框。

## 4. 各页面的最终效果

| 页面 | 视觉重点 | 具体行为 |
| --- | --- | --- |
| 消息首页 | 签名字、清晰会话列 | 保留文字、光丝、倒影和粒子，顶部 App 图标不恢复；列表头像静止；首页现有搜索框作为输入标准 |
| 普通聊天 | 角色身份与长文阅读 | 角色头像不被小球替代；小星记录入口先明确当前接入范围，再在现有入口内完善，不把未接入能力伪装成可用功能；生成状态只在当前回复附近回应 |
| 助理空间 | 名字、今日重点、小球回应 | 三页签不变；已有大数字和能量条继续保留；缩小重复卡片与重复标题，完成/等待/失败差异明确 |
| 设置 | 看得懂、找得到、知道是否保存 | 一组一表面，标题/说明/当前值三级层次；高级项沿现有折叠入口；错误紧贴字段，保存反馈不覆盖输入 |
| 通知与删除反馈 | 低干扰、可恢复 | 用现有 FeedbackHost 统一；成功简洁、失败可重试；仅对已有可撤销操作显示撤销；软键盘和底部安全区避让 |
| 朋友圈 | 内容和新互动 | 沿用已授权的互动入口与计数；新增互动强调头像与摘要，底部导航不加红点；不新建消息系统 |
| 世界与角色 | 场景氛围、身份与关系事实 | 入口可以有静态紫青氛围；重渲染关系星图和世界画布不重做；关系变化只在已有事件上呈现 |
| 启动 | 从暗到清晰的一次聚焦 | 现有标记与小星/光丝短暂汇合，立即过渡首页；不加人为等待、不阻塞资源加载 |

普通聊天小星是“记录与回看”的轻入口，助理小星是助理工作状态的反馈面孔；二者使用同一个组件体系但按场景表达。20px 流式装饰球不提供额外入口、不改变文本内容。避免在一个页面同时放多个抢注意力的球。

## 5. 动效编排定稿

| 触点 | 时长目标 | 动作与取消规则 |
| --- | --- | --- |
| 按下/滑出取消 | 80–120ms | 触点光泽、图标轻缩；退出点击范围或滑动后不提交，键盘同样可操作 |
| 页签切换 | 180–220ms | 指示器连续移动，文字局部状态过渡；快速连点接管当前位置，对话继续隐藏不卸载 |
| 页面/弹层 | 220–320ms | 延续统一阻尼，不动画大面积 blur、阴影或正文尺寸；拖拽和新点击可接管 |
| 完成事项 | 总长 ≤320ms | 真实成功后勾选、小球 success、已有触觉一起回应；保存失败不庆祝 |
| 关系里程碑 | 总长 ≤320ms | 原有事件触发，小范围光点收束到现有纪念卡/通知，文案始终可读；不弹强制全屏、不伪造关系进展 |
| 讨论事项 | 240–320ms | 从源卡到上下文横幅的有界连续运动，保持输入焦点与任务版本契约 |
| 错误 | 120–200ms | 静态错误色配一次轻脉冲，小球 error；输入和滚动不中断 |

每次动作只设一个视觉主角。小球在空闲页可保留轻微生命感；滚动、输入和覆盖态优先暂停无关氛围。不会对每个流式 token 分别触发动效或触觉。

系统与应用减少动效下，所有位移、缩放、粒子及光泽运动取消，以静态选中、勾选、状态文案提供同等信息。减少动效与“能否使用玻璃”分开判断：用户动效偏好不是硬件性能指标。

## 6. 性能与验收

- 默认路线不新增运行时依赖，不新增 WebGL 场景。正文只做现有流式更新，装饰不参与消息保存、textContent 或几何计算。
- 每屏最多一个主氛围区域；列表不为每个头像/卡片建持续循环。动画帧内不新增 React state 提交，DOM 测量合帧并与写入分离。
- 背景/窗口失焦/不可见/覆盖层状态延续现有停帧。共享元素找不到目标时立即采用静态落点，不等待。
- CSS 总 gzip 相对冻结升级前基线仍不超过 +15%；上一轮记录为 +2.66%，这是历史验收值，不代替下一次构建。JS 默认不得因参考库而增加依赖，静态纹理资源另行记账。
- 同一台 60Hz 真机、同一份数据记录长列表滚动、流式长文、软键盘、两球同屏及快速切页。先测现状再测新版本；交互中持续低于约 55fps 或 p95 帧间隔相对基线恶化超过 10% 时回退新增效果并定位原因。此项为拟定发布门槛，不是已实测结果；rAF 间隔不代表 GPU 完成时间。
- 320/390/430px × 深浅色截图，含超长名字、最大字号、加载、失败、空态、软键盘与 reduced-motion。正文对比度 ≥4.5:1，大字 ≥3:1；触控与焦点可达。
- 回归继续使用 TypeScript、renderer 构建、助理/行动舱/流式/小球/分包既有脚本；视觉断言可新增，原业务断言不放宽。每批存新旧截图和体积报告。

## 7. 实施顺序与交付

| 顺序 | 交付 | 工作估计 | 出口 |
| --- | --- | --- | --- |
| A | 消息首页、普通聊天、助理、设置四个真实内容对照屏，确定材料/字号/动作密度 | 1–2 个工作日 | 深浅色、窄屏、长文方案确认并记录 |
| B | 公共表面、输入、按钮点击区、图标和设置行的迁移 | 2–3 个工作日 | 无旧新混搭、关键页可读性通过 |
| C | 聊天阅读、通知与助理签名动作收口 | 2–3 个工作日 | 生成/取消/撤销/切页无回归 |
| D | 世界/角色/朋友圈入口表面与已有里程碑呈现 | 1–2 个工作日 | 原功能可发现，不增加数据契约 |
| E | 真机检查、全套回归、体积与截图归档 | 1–2 个工作日 | 达到发布门槛 |

增量预计 7–12 个工作日，包含调校；不是无真机数据时的固定交付承诺。最大杠杆是 A+B+C，应先完成并实测，再扩展 D。

Shader 单列为后续实验：如另行开放依赖范围，先在非启动、非聊天的独立角色展示样本比较静态和动态。最多一个 canvas，明确像素总量、真实节流、context-lost 恢复与卸载，后台完全停帧；需要实测耗电与滚动收益后才考虑正式接入。试验失败不影响 6.0.1 的主体交付。
