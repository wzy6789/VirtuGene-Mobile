# 原话复述与具体事实问答整改

## 真实完整流程

苏格拉底六轮：秒回观点 → 不同意见 → 用户改口 → 问起床时间 → 提供十点的新事实 → 要求复述。实际私聊发送、上下文和 IndexedDB，deepseek-flash 默认低强度思考，主动性 0.5，每次输出最多 500 tokens，摘要/结算/提取边界替身，上游非流式。

基线保持自己的不同意见和口癖，能说不知道、能复述正确原句，但未知事实后以聊天时钟评价作息，复述后继续追问“要我念第二遍吗”。这些回复不是本地检查能证明人味达标的样本。

## 改动

- 将复述识别集中到 chat-turn-cues.ts，发送意图、当前回复节奏、直接引导及重复质检共用。reply-quality.ts 保留原导出接口，不要求外部改调用。
- 支持明确再说/再念、原样读回；排除引用、转述、假设、否定和词语解释。冒号后的待读文字不当成新的指令，例如“请原样说：不要再说一遍”仍是有效读回要求。
- 用户明确请求复述时，既豁免重复自己，也豁免高相似度的用户原文；未经请求的复述照常质检。追加一个足够长的真实中文段落作为对照：不带读回许可时确实命中 repeat-user，带许可时通过，避免写一个本来就低于相似度阈值的伪验收样本。
- 明确复述得到独立的短引导：按指定对象保留原措辞，不将用户原话冒充角色自身事实，不加点评或追问；缺少对象或找不到原文才具体补问。
- 用户直接问自身时间/地点类事实时，已知直接答、未知坦白，不从当前时钟或聊天时间推作息及原因。此规则是有限本地线索，不是事实问答全语义覆盖，不授权助理或角色写入记录。
- 固定前缀工具支持 replay-first-three，维持同源人物/场景/模式/输入/正常真实原始回复核对；不用重跑整段来测试第四轮。
