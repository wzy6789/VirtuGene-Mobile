### 一条新的产品规则（本阶段引入）

> **未结束的未完成事项不再出现在「最近发生」里**——它已经由大卡与「未完成的故事」区块承担，
> 否则同一件事会在同一屏出现两次。已完成的（`resolved=true`）照常作为时间线出现。

对应实现：`recentHappenings = recent.filter(e => !(e.type === 'continuity' && !e.resolved)).slice(0, 3)`。

### 挑选逻辑（纯函数，可验收）

`src/lib/world/world-picks.ts`：

```
pickWaitingStory(threads, now)：
  1. 已过约定时间的 → 逾期最久的优先
  2. 有约定时间但未到的 → 最近到期的优先
  3. 都没有时间的 → 最近提起/修改的优先
  都没有 → null（页面据此隐藏大卡）
relativeDay(ts, now) → 今天 / 昨天 / N 天前 / M 月 D 日
THREAD_TEASER[kind] → 类别化的"人话"一句（不暴露任何字段）
```

判断规则固定、可解释、**不发请求**；没有把判断塞进组件里，因此能被单测式验收直接覆盖。

## 5. 过程中发现并修掉的 bug（都是测试/审核逼出来的）

1. **「最近发生」被未完成事项占满后过滤成空**（自测发现）
   我最初写成"先取 top-3 再过滤掉未结束的未完成事项"，结果 3 条未完成事项把真正想展示的关系事件挤出了窗口，过滤后整块为空。
   修复：**多取（10 条）→ 过滤 → 再截断 3 条**。这是典型的 limit-then-filter 顺序错误。
2. **弹窗断言读到空**（测试侧）：`ContinuityThreadsModal` 通过 portal 挂到 `document.body`，
   而验收脚本读的是 `host.innerText`。改为读 `document.body.innerText` 后通过——
   也顺带证明了"点线索确实打开了既有面板"。
3. **恰好只有一条未完成事项时，页面显示「未完成的故事 · 1 件」却是空列表**（**审核发现**，本次修复）
   原因：区块的显示条件用的是"全部未完成线索"的数量，而列表渲染的是"其余线索"（大卡已占掉一条），
   于是 `1 - 1 = 0` 条时区块仍被渲染，计数与列表自相矛盾。
   修复（`MobileWorldPage.tsx:135`、`289`、`293`、`318`）：
   - 新增 `restThreads`：`waiting ? openThreads.filter(t => t.id !== waiting.id) : openThreads` 后 `.slice(0, 4)`；
   - 区块与"还有 N 件…"提示**都**改为以 `restThreads.length > 0` 为条件；
   - 区块计数改为 `restThreads.length`（= 真实渲染出来的条数，不再可能出现"1 件 + 空列表"）。
   回归断言：2b-1 新增 **G 组**（删到只剩一条线索 → 大卡仍在、区块消失、页面上不出现 `1 件`）。

### 验收脚本自身的一处口径修正（已披露）

修完上一条后，**Phase 2a 的 D 组出现一次 FAIL**：原断言写成整页正则
`!/最近发生[\s\S]{0,120}周末一起去看电影/`，而 2b-1 的 `restThreads` 修正后，
「未完成的故事」区块会**紧跟**在「最近发生」之后渲染，这条线索落进了正则的 120 字窗口内，
于是**断言误报**（页面本身是正确的：该线索在大卡 + 未完成的故事区块里，不在「最近发生」列表里）。
修复：新增 `blockText(label)` 辅助函数——**先按区块标题定位，再取同 `section` 内其后的第一个 `<ul>`**，
把断言限定在该区块自己的列表里，并把 `undefined` 明细改为输出真实区块文本；
同时补一条**正面控制**断言「未结束的线索确实由『未完成的故事』区块承担」。
这是让测试更精确（不再跨区块误判），**不是放宽标准**。

### Phase 2a 夹具的必要更新（已披露）

2a 的 D 组原本**手工造了一条未结束的 `continuity` 世界事件**来断言"最近发生"。
2b-1 引入新规则后，这类事件不再出现在「最近发生」，因此我把夹具改成**更真实的形态**：
用 `continuityRepo.create()` 造**两条**真实线索（会同时派生世界事件；两条是必需的，因为只有一条时区块会按设计隐藏）
+ 一条已解决的 `relationship` 事件，并新增断言「未结束的未完成事项不作为"最近发生"重复出现」。
**改的是夹具与断言口径，不是放宽标准**：D 组现在覆盖的区块比原来更多。
