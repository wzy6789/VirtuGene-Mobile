# 助理评审整改记录 · 2026-10-03

## 已完成的代码整改

本轮依据用户提供的评审实施，保留用户的会话、记忆和生活记录；未修改版本号、打包、提交或发布。

### 1. 授权与原话依据

- `src/lib/secretary/intent.ts` 集中操作授权和用途不明的“记一笔”判断。规划入口、待补充上下文和执行前使用相同判断，保留既有控制与连续修改路径。
- 新模型规划统一按 V2 校验：每项操作必须携带 `evidence:{start,end}`。模型省略版本、降级版本或省略依据，均不能借此绕过新契约。单项不合格不会使其他独立、合格的操作失效；依赖仍按实际前项结果判断。
- 索引采用 JavaScript UTF-16 单元，不是字节；拒绝越界、空范围和拆开 emoji 的范围。引号内裁剪出的“指令”不能授权；执行前仍扩大至所在完整分句，保留否定语义。
- 修正了黄金语料实际揭示的否定日记追加、否定动态起草漏判，以及“发朋友圈”的自然说法漏识别。
- 旧任务、旧归档和本地连续补充维持兼容；恢复不会自动执行。所有者、任期、源消息、目标版本、明确发布授权和撤销保护继续保留。

这仍是本地规则系统，不声称支持所有中文句式。引述、嵌套引号、改口与长尾指令需要持续扩展反例，不能仅靠多加正则声称语义完备。

### 2. 轻量闲聊

- 精确匹配少量问候和情绪短句，例如“你好”“今天好累”；未知句式、复合操作、带指代或时间的输入继续完整规划。
- 不增加分类模型调用。轻量路径省去完整工具说明、待办候选和历史索引检索，但保留人物性格、表达偏好、经证据验证的稳定记忆和最近对话。
- 轻量模型即使返回操作也会被清空，不能写生活记录。仍校验回复真实性及可采纳记忆。
- 这是减少明确闲聊的提示词与检索工作，并非固定响应时间保证，也不是所有记忆读取都变为常数成本。

### 3. 数据访问与提醒

- 待办候选的 occurrence 用一次 `bulkGet` 读取，替代逐项读取。
- 一轮多项待办提交后，只执行一次账号级提醒重建，再逐项读取真实通知回执。恢复路径仍可重建未完成的通知调度。
- 收窄选择会话、保存草稿和放弃单项的事务表范围；依赖多个仓库、撤销与证据链的复杂写入继续使用原完整事务，保留原子性。没有机械地删除所有全表事务。

### 4. 日记锁与来源分类

- 本地产生 `privacyScope:plain/diary/unknown`。判断直接日记操作、日记召回及来源任务；缺失、跨所有者、跨助理或未知来源不能判为普通请求。
- 锁定时普通请求的收件箱原文仍能查看；日记及其衍生待办/草稿隐藏，执行需先解锁。
- 近期聊天的隐私判定独立于历史检索相关性，避免“没检索到任务，却把近期日记原文送进模型”。完整与轻量上下文都执行相同来源检查。
- 回应、结果卡片、重新填写和继续办理同步遵守分类；旧任务没有可信分类时采取保守隐藏。备份恢复把分类重置为 `unknown`，不相信导入文件自报普通来源。
- 如果某次模型规划确实读到了近期私密内容，即使最后操作是待办或草稿，也会继承保护。这是来源保护，不能只按最终工具名称判为普通。
- 每日整理原有的来源验证和失败状态保留，不用新的通用拦截覆盖它。

日记锁控制当前召回和展示，无法让已经发送给模型的内容“撤回”；用户自行发布的内容和生活记录也不能被说成从未公开。

### 5. 名称

新界面、错误提示、输入标签和新问候统一使用“助理”。`secretary` 代码标识、历史提示标记及旧生成问候匹配保留，避免破坏兼容；用户原有聊天不重写。

测试夹具同步提供新契约要求的原话依据；明确的错误依据不修复，并保留省略依据的专项反例。收件箱夹具使用独立账号，普通任务在日记锁定、私密上下文不可用时创建，避免把实际读过私密来源的任务错误地当成普通任务。额外验证了真实执行器阻止日记派生待办，以及轻量/完整提示词均不含锁定原文。构建还发现消息语音按钮调用不存在的函数，修正为该组件现有的 `toggleVoice`，恢复编译并保持原有播放逻辑。

`scripts/eval/assistant-golden.json` 为固定 150 项授权语料：75 肯定、45 否定、30 引述，覆盖 15 种基础表达的变体。它是本地闸门语料，不是 150 个完整连续任务，也不能代替复杂改口与实际任务验证。

`scripts/eval/run-assistant-live.cjs` 对其中 60 项分层样本，运行真实应用请求、规划、执行及本地数据库路径：每类 20 项。使用独立浏览器与合成账号，不读取用户已有数据库。密钥只通过本机进程环境进入 HTTP 中继，不写入浏览器或报告。

评测区分模型意图是否正确、实际执行结果、未授权写入和耗时。负例即使模型提出操作，也必须没有生活记录变更；正例不能靠全部拦截得到安全高分。门槛为未授权写入 0、正例成功率至少 95%。正式发布前应对 2—3 个实际支持的模型分别运行，并人工核对字段、五种性格、连续任务和补问体验；当前评测的动作类别一致不能证明所有字段都正确。

node scripts/eval/run-assistant-live.cjs  # 只检查语料规模，零联网

不要把密钥发到对话或写进报告。真实模型评测工具已实现，真实服务评测尚未执行；本轮自动检查使用 HTTP 替身，不声称通过真实模型或 Android 真机验收。

## 多设备：独立发布门槛，尚未闭合

现有本机 IndexedDB 锁和操作去重无法阻止两个设备在同步前同时执行同一任务。本轮没有把本地锁包装为服务端幂等，也没有部署新服务。

服务端改造应一次覆盖以下契约后，才能宣称多设备任务安全：

1. 账号认证产生所有者，服务端维护递增聘用版本；请求携带预期版本，离职/重新聘用后的旧请求拒绝。
2. 请求在规划前生成稳定 requestId，每项操作有稳定 operationId；同一操作跨设备、重试和重连不得重新生成。服务端唯一键 `(userId, operationId)`。
3. 领取执行租约使用服务端原子 compare-and-set 与 fencing token。租约超时本身不能证明旧执行者没写入；晚到写入必须校验 fencing token。
4. 记录写入、目标版本比较、幂等回执在同一服务端事务提交；客户端“先本地写，再登记服务器”仍会双写。重试返回同一回执，不能再次执行。
5. 离线只保留草稿/待执行状态；恢复联网后取得权威结果再投影到本地。不能同时允许两个设备各自执行写入并声称全局恰好一次。
6. 撤销、发布和原请求撤回使用同一幂等体系，不能只保护创建待办。通知由明确指定的设备或服务端负责，不让每台设备各安排一次。
7. 双设备同时创建、离线再上线、任期变化、目标版本冲突、租约过期迟到、提交成功但回执丢失、重试及撤销必须有集成验证。

在这项完成前，正式说明仍应写“本机防重复”，不能承诺跨设备统一执行。

## 其余边界

- 定时每日整理提醒是新增产品能力，本轮没有擅自增加后台调度；现有每日整理仍需用户明确采用。
- 本地分类器是后续方向，不用未经评估的分类器替代授权硬规则。
- Android 实际通知、键盘、权限、真实模型表达质量和低端设备大数据耗时仍需要实际设备/服务验证。
- 构建保留原有大 chunk 和混合导入警告；不以构建成功宣称已经解决包体或性能瓶颈。
