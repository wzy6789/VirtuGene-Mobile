# 角色表达示范与开场白优化

本轮落实 GitHub 调研后的前三项：开场白审查与预览、声音卡精简、可撤销的表达样本。没有增加每轮语义裁判或情绪模型。

## 使用入口

- 编辑普通角色：可预览普通聊天开场白建议，采用后仍是编辑草稿，保存角色才生效；已有聊天不被改写。原文含动作、现场安排或较长叙述时显示参考提示，审查是建议，不自动覆盖用户创作。
- 长按自己的未公开普通角色的完整私聊回复，选择“表达样本”：先预览并编辑用户消息与角色回复，删去私密细节，再明确采用。
- 编辑角色的“管理采用的表达样本”入口可查看、移除。每个角色最多八组。失效样本保留可管理状态，不继续用于提示词。
- 沿用全屏页面式 Modal，不增加底部抽屉或每条气泡的评分按钮。

## 真实接线

`readVoiceSampleCharacter` 在实际私聊、主动消息与群聊角色声音卡的读取入口核对样本来源，只有有效样本才进入临时 `reviewedVoiceLines`。编译时与原人设样本共同按情境选择，仍受既有样本数量上限控制；例句明确只作表达参考，不代表历史事实。

声音卡有具体判断习惯时不再重复标签的通用判断指导；缺少具体设定时最多使用两类标签补充。情境和执行真实性保护保留。

## 保存与失效

- `Character.reviewedSpeechSamples` 是非索引可选字段，不需要新增 Dexie schema 版本；旧角色、原人设与生活数据继续保留。
- 来源保存消息 ID、版本和 SHA-256 内容摘要，不额外保存未编辑的来源全文；保存的示范文字是用户预览后采用的版本。
- 校验账号、角色、私聊会话、人物版本、来源版本、实际内容、删除及撤回标记。连发回复中的任一来源发生变化，整组停用。
- 采用前再次在数据库事务中核对来源与账号，防止预览期间编辑或切换账号造成错误写入。读取按来源 ID 批量查消息，采用预览使用有上限的时间索引窗口，不为样本扫描整个聊天历史。
- 公开角色不提供私人样本入口；发布角色时排除私人样本及其来源引用。现有账号备份、同步会随角色保存这些私人字段，其他设备没有对应来源时样本自动停用。它们不是跨账号公共角色资料。
- 样本移除即时生效于后续请求，已生成的历史回复不被重写。人物设定的版本摘要与原有声音缓存保持一致。

## 调用量与验证边界

普通回复没有新增模型调用。用户点击开场白建议时进行一次显式辅助生成，失败不替换原开场；样本采用与移除完全在本地完成。

验证使用隔离数据库和模型替身，不触碰实际用户数据、没有付费模型调用。已覆盖真实发送链路注入与来源删除后的排除、编辑与版本变化、撤回、多气泡校验、账号变化、发布隔离、开场白预览与保存、手机上的样本编辑与移除。

本地结果：chat-expression 288 项；chat-policy 62 项数据检查及 18 项界面检查；chat-quality-complete 182 项逻辑与 7 项界面检查；chat-stream 50 项；类型检查与生产构建通过。

真实模型的自然度与人物辨识度仍需实际聊天观察。连续轨迹 A/B 工具、负面表达反馈分类与模型对比是后续阶段，本轮没有宣称已完成这些工作。
