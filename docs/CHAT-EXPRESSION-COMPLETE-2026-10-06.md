# 聊天表达整改：代码交付与验证入口

日期：2026-10-06。完成文本清理、多入口质检、情境辅助信号、声音样本复用、按入口统计和可主动运行的表达验收工具。沿用既有四气泡协议、纯反应条、问号强度、口癖、emoji、声音卡尾部位置，不另存 rawContent，不改写用户人设。

这里的“完成”指开发与本地验证完成。真实模型的人物辨识度、情境恰当性和长聊漂移仍需实际调用并人工评分，不根据替身测试宣布人味达标。

## 1. 文本和流式呈现

- `src/lib/ai/text.ts` 按明确动作结构清理长括号，逗号和字数不再导致动作漏过。说明、数字、英文、公式、引用和不确定内容保留。规则是保守识别，不承诺任意括号语义都能判定。
- `collapseChatNewlines` 共用于气泡与回复润色。中文换行直接连接；两侧是英文或数字时保留分隔空格；原有明确空格不被全局删除。
- `chat-stream.ts` 缓冲未闭合括号及尾部换行，避免先闪现动作再删除。已显示的气泡身份和内容不被静默重试替换。
- 落库仍使用上屏文本。清理差异指标忽略空白和分条标记，另计动作删除字符数、换行数、额外引入的中文空格。实际捕获原文的文字差异超过 15% 时记录告警；无法捕获原文时不冒称精确测量。

## 2. 同一质量入口覆盖三条链路

`src/lib/chat-output-quality.ts` 统一处理文本清理、口语检查和明确的人设禁用项。

| 入口 | 行为 |
| --- | --- |
| 私聊 | 未上屏时最多一次质量重试，保留检查较好的候选；已上屏后只记录问题，不重新生成 |
| 主动消息 | 检查失败最多再生成一次；两次失败不发送。发送前核对账号、角色设定和最近消息，丢弃过时稿 |
| 群聊 | 各角色独立检查；每个选中发言最多一次额外质量重试，隐私降级共享预算；导演兜底也检查 |

自然问候、纯反应、标点强度及口癖不被当成客服腔。重复比较仅使用相应角色的历史。人设明确写出的“表情：不用 emoji”和“禁用称呼”可以本地检查，当前用户明确要求表情时允许覆盖偏好。不因没说口头禅、没加情绪或只回一个字判错。

这些规则检查的是有限、可观察的冲突，不能判断任意回复是否“像 TA”，也不是助理执行真实性契约的替代品。

## 3. 情境信号与角色声音

- `chat-expression-guidance.ts` 返回请求与情绪两种独立信号及置信度。后置的“报告你帮我看看”能与疲惫同时存在，明确请求不会被安慰取代。
- 引用、假设、第三方情绪和否定表达不直接成为用户情绪。低置信度时使用中性指导，原话始终优先。情境识别仍是本地启发式，只影响表达，不授权写入或操作。
- 固定语料推动修复了“开心不起来”被当作喜悦、转折后的第三方情绪以及“不要替我……”的否定漏项。
- `buildCharacterVoiceCard` 成为三入口共用的声音卡构建函数。主动聊天与群聊读取当前有效缓存；群聊声音卡仅进入对应角色自己的请求，不给导演共享。
- 手写样本优先；缓存按角色来源版本校验，修改人设后旧缓存失效。保留既有成功私聊后的去重懒生成，以及编辑页预览采用后显式保存。质量页另提供按角色手动补全，显示有效、待补全、处理中和失败状态，不批量自动调用模型。
- 温度和本轮节奏只能作为辅助指导。没有新增长期保证某供应商参数一定生效的声明；真实效果由实际模型样本校准。

## 4. 本机质量面板

入口：**设置 → 数据与设备 → 聊天质量**。使用现有全页导航，按需加载，不新增底部抽屉。

面板提供：

1. 私聊／主动／群聊分别统计检查、重试、重试后通过、仍有问题、拦截、已上屏问题和处理耗时。私聊实际发布首段时记录首次显示耗时。
2. 私聊文字差异和超过 15% 的记录计数。
3. 当前用户角色声音样本覆盖状态与手动补全入口。
4. 数值统计导出和清空；默认折叠的真实模型验收区域。

本地按账号保存最近最多 200 条数字和枚举事件，不保存聊天原文、提示词或密钥。旧账号的迟到事件不会写入新账号。时延是处理／发布计时，不是网络单独耗时，也不代表服务器响应速度。

## 5. 可运行的模型对照与人工评分

`src/lib/chat-expression-evaluation.ts` 提供显式启动的隔离测试：

- 当前角色 15 个固定场景；
- 专业、搭档、温柔、元气、俏皮五种测试声音 × 15 场景，共 75 次；
- 当前角色连续 30 轮，保留最近 18 条历史，观察有限上下文下的表达变化。

使用当前默认对话模型。点击前说明额度消耗；可以停止，离开页面或切换账号会取消，迟到结果不再展示。配置或额度失败时停止，避免重复失败调用。

不读取私人记忆，不创建聊天会话、消息或生活记录，不修改角色。原文结果仅在页面内存中存在，用户点击“导出测试原文与评分”才产生文件；该文件与无原文的统计导出明确分开。

每条可对自然度、人物辨识度、情境贴合、事实可靠四项评分。全部维度未评分时不得计为已评分；本地检查全绿不自动获得语义通过。报告包含模型标识、角色来源版本、主动性设置、耗时、失败、检查问题及人工评分。

这是表达对照工具，不是生产全链路复刻：没有真实应用中的私人记忆、滚动摘要、通知或流式 UI。完整长聊还需要在真实聊天里观察；测试风格是临时样本，不会替换用户助理。
