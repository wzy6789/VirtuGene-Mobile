# 助理记待办失败整改

日期：2026-10-03。用户报告“让助理记待办但显示失败”。尚未收到具体原请求与失败提示，不能认定手机上的那次失败一定属于下面路径。本轮先复现并修复应用内可确定的解析、重试和错误反馈缺陷。

## 原因与修复

1. 新模型计划强制要求原话依据。模型返回正确的待办，但省略依据或计算错UTF-16位置时，会显示失败。既有大部分测试替身自动补齐依据，不能证明真实模型都能遵守。新增 `plan-source.ts`：允许模型逐字引用原话，由应用定位唯一出处；兼容旧数字位置。明确的单项新待办，名称确实在原请求中或尚未给出名称，并且没有多项、依赖或复杂字段来源时，可以从实际请求补齐遗漏或越界位置。缺名称仍补问，不编造名称；缺提醒时间仍补问，不冒称提醒成功。
2. 原先解析失败后丢失待办名称，卡片“重试”仍带着同一个解析错误，只会再次失败。现在保留可校验的操作字段。点击重试重新调用规划，只替换失败项；核对数量、事项身份及其他操作，保留已成功项。保存过的默认优先级与提醒提前量按原工作习惯比较，避免将应用补齐的默认值误判成模型改了操作。
3. 重试成功后，应用更新同一结果记录和数据库回执，当前聊天同步更新，避免卡片已成功而气泡仍说失败。
4. 发送异常不再统一显示“没收到回复”：分别反馈模型密钥失效、余额不足、服务关闭、限流、超时、连接失败、理解不完整或来源变化。失败原因保存为本地固定文案，不展示模型服务原始错误、响应正文或密钥。

## 执行保护

- 引述、否定、虚构名称、用途不明、一般询问、多项缺依据、同一句原话出现多个位置，不借兼容处理猜测执行。
- 原话文本和字段来源仍经过原有指令范围校验；引用内部的命令不能成为授权。
- 重试只针对解析失败的未执行项。每日整理、待补上下文或接续来源含解析错误时保留原流程，提示用户重新发送，不绕过原有来源与采用机制。
- 重试前后核对账号、任期、任务版本、消息内容与修订、来源遗忘状态及模型读取的记忆引用。原消息在规划期间编辑或撤回，停止写入。
- 已成功项不重复执行；重新理解后事项数量、名称、类型或其他事项变化，则拒绝替换。没有自动重发请求，没有静默执行旧建议。
