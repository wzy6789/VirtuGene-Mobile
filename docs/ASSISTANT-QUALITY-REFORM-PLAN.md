# VirtuGene 生活助理：完整质量整改方案

日期：2026-10-02。范围：手机端生活助理。本文是设计与开发规格，不代表已完成实现或获得满分。

## 0. 当前评价与边界

当前已有真实日记、待办、应用内朋友圈操作，事务、请求幂等、撤销、补问、交接和助理记忆。方向正确，约 8/10；剩余短板集中在复杂自然表达、跨会话任务焦点、长期读取成本、提醒可观测性、人物表现和手机操作负担。

最新本轮复跑：479 项助理逻辑检查通过，TypeScript 无错误。模型边界是替身，不能据此证明真实模型表达、解析成功率和 Android 通知到达质量。本轮新增检查也确认：以前发现的问号尾句和“已经记好了 / 已经发好了”假声明在当前办事回复中已被拦住；情绪句“你已经很累了，先歇一会儿”保留。普通“给我记一笔”用途歧义仍需更好的接续处理。历史读取与任务焦点整改尚未完成。

开发保留：现有用户聊天、日记、待办、朋友圈、记忆及来源；现有五种性格、十款头像；账号归属、日记锁、明确发布、旧任期迟到拦截、事务和撤销保护。聊天保持非流式。无需新增外部托管、向量服务或多轮固定模型调用。不得把其他普通角色的私人记忆自动导入助理。

“10分”在这里定义为下列全部门槛通过的交付目标，而非凭设计保证体验满分。

## 1. 收据真实性：结果只能由执行记录产生

涉及保存、发布、修改、完成、提醒、删除、记忆写入和页面跳转的事实，只允许从执行器和当前原记录产生。结构化草稿不等于发布；数据库有待办不等于系统通知已安排；系列状态不等于某一天的状态；按钮已就绪不等于已跳转。

保持现有情绪句白名单作为迁移保护，禁止再次让 raw reply 直接拼进办理回执。长期改为独立字段：responseMode(casual/advice/clarify/work)、acknowledgementCode、actions、clarification。acknowledgementCode 是可验证的情境枚举，如 tired、anxious、frustrated、neutral，不能含执行状态。性格表达在本地受控词库中生成。未知码不影响有效工具操作。

办事模式输出：一句符合性格的情境回应 + 真实卡片 + 必要补问。闲聊和建议可使用自然语言，但不能自称执行没有对应记录的应用操作；不能把“没有工具操作”误判为所有自由文本都可信。用户引述中的“已经发了”等文字与助理自身的执行声明必须区分，不能用粗糙全文替换损坏引述。

新增 ReceiptViewModel：operationState、entityState、missingFields、notificationState、entityRef、entityVersion、undoAvailable。它是读模型，不复制日记正文，也不是第二套事项数据库。结果生成与卡片复用同一个读模型。

验收：所有现有 14 类操作分别覆盖完成、待补充、失败、撤销；注入“记好了 / 发好了 / 搞妥了 / 已经设好闹钟 / 到点我叫你”和问号、表情、换行变体。零工具、失败、草稿、部分成功时不得冒称全成功。

## 2. 自然表达与授权：理解整句话，而不是扩大关键词列表

扩展现有一次结构化规划请求，返回稳定的 actionId、当前请求中的依据片段、字段来源、缺失字段和依赖关系。每项操作独立校验，所有 ID、日期、对象版本、受众仍由应用检查。依据必须对应当前用户消息，模型置信度本身不能授权执行；引述和旧记忆不能作为新操作依据。

建立常用表达语料：记上、记一筆/记一笔、别让我忘了、记得叫我、那个挪一下、把第二个划掉、不要提醒只记录、先写别发、不是明天是后天、改成每周但这周除外、查一查但不要改。对用途不明的“记一笔”具体询问“记成待办还是日记？”；选择后保留原内容接续，不能要求重新输入。

歧义用真实候选和最少补问处理。模糊“三点”不默认凌晨或下午；“下周五之前”是截止时间语义，不擅自改成周五某个钟点；重复例外能力未支持时说明并提供单次处理，不假装支持。对改口先形成最后有效字段再执行，不能先创建一项然后因“不是”又创建第二项。

多操作有显式依赖：可独立的事项正常完成；依赖先前写入的操作只在前置成功后执行。“先写草稿给我看再发”停在草稿；失败时只重试失败项。每项有幂等键和源消息版本，编辑源指令使未执行计划失效。

不把自信不足都交给用户确认：低风险、明确指令直接执行；用途/对象/时间有歧义或受众未定时才补问。保持“写朋友圈”默认草稿与明确发布边界。

## 3. 任务焦点：跨会话继续同一件事情

新增持久化 SecretaryFocus，归属于账号的助理工作区，并保留会话分支：userId、workspaceId、focusId、threadId、originTaskId、sourceMessageId/revision、candidateRefs、selectedRef、selectedVersion、awaitingFields、lastConfirmedAt、employmentId。存来源和引用，不存另一份生活记录。

至少区分等待选择、等待字段、可以继续、暂停、已结束、失效六种状态。最近对话不足以代替任务焦点。短句接续次序：当前明确引用 > 当前未完成焦点 > 同会话最近明确对象 > 工作区保留事项；多个同等候选显示选择。新会话可接续明确焦点，但不能任意修改旧事项。

用户说“先不弄这个”“换个话题”暂停焦点，不反复追问；用户重新提及时恢复。话题改变不是撤销，也不完成任务。源消息被编辑/删除、事项被取消、对象版本变化时重新读取并具体说明差异；不能覆盖用户后续编辑。

换助理保留工作区事项，旧助理异步计划仍失效；新助理可看到真实待办和用户允许保留的习惯，但旧草稿发布及旧未授权操作必须手动接续。

验收：新会话、重开应用、普通闲聊插入、改口、多个待办、删除原请求、改期后再撤销、解雇和重新聘用；每种均检查实际数据和发送给模型的资料。

## 4. 记忆分层与动态状态

四层：用户明确的稳定事实与偏好；当前任务焦点；真实生活记录引用；最近对话。工作区习惯跨聘用，助理本人性格和表达身份按当前任期读取。未来计划不自动固化成永久事实，虚构星域经历不自动冒充用户现实经历。

调用前重新确认记忆有效性和源消息版本。用户纠正时，相关旧记忆、检索索引、受影响上下文摘要和焦点说明一并失效；用户忘记后，备份导入不能复活撤回来源。正在进行的请求也应在执行/显示前检查是否已撤回。

事项内容必须读取当前原表：实际改期、完成、取消、改名、撤回朋友圈后，不能让旧收据变成现状。可以回答历史发生过的操作，但明确“当时”，不能说它现在仍有效。

日记锁、归属和读取范围延续现有边界。普通角色知道的事与助理工作资料不能自动共享；助理对用户开放的任务记录也不能使所有普通角色自动知情。

## 5. 检索性能：限制读取量，而不只是限制提示长度

当前 memory.ts 会扫描多个会话的历史消息和任务。改为按工作区、来源类型、时间、状态建立本地检索索引，保存规范化关键词、别名、引用和版本，不重复存敏感正文。写入、修改、撤回同步维护，旧用户后台分批建立；索引未完成时有界读取兜底，不阻塞首次发送。

检索顺序：选中对象与未完成焦点 > 明确日期/名称/ID > 稳定偏好 > 有限近期记录 > 历史关键词候选。先取候选 ID，再批量读取和验权；不得每次把所有会话全文拉入内存。取消旧请求时同时取消可取消的读取；不能把一个账号的检索缓存给另一个账号复用。

设置可调整的候选与时间预算，超预算先返回确定的结果，明确是否还有更多记录，不说“没有”来掩饰尚未读完。压缩保留明确要记住的事实、来源、当前任务和最新对话；不得修改用户原聊天。

压测：1千/1万/5万条消息、100/1000/5000项任务，冷/热启动分别测，报告测试设备、P50/P95、读取量、峰值内存和首屏耗时。目标参考：中端测试机热检索 P95 <=150ms，1万条消息冷检索 <=500ms；这是验收目标，达不到须优化或披露，不能当已实现成绩。一次普通办事默认一次模型规划；补字段、选候选和查看状态能本地完成则不再调用模型。

## 6. 人物性格与人味

继续保留五种性格，不变成五种同义的“收到”。专业型清晰、克制；搭档型轻松、一起解决；温柔型具体体谅；元气型积极但不强迫；俏皮型有分寸、失败不嘲讽。事实和权限一致，表达不同。

建立情境 x 性格的受控短回应库，并保留用户称呼/表情/长度习惯。不照搬长台词，不一味说“辛苦了”，不每条都夸，不把每次办事变成心理咨询。同情境短句轮换，最近使用过的句子降低优先级；用户转话题及时跟随，不追着疲惫或焦虑反复说。

用户只是倾诉时不强行创建待办；用户让办事时不先聊一大段。主动作出建议至多一个具体下一步，可以拒绝。每条气泡去除首尾空白、连续多余空行；多条回复保留头像并有短节奏，但办理回执避免无意义拆成多条，保持非流式。

真实模型盲测五种性格，每种相同的办事、疲惫、失败、拒绝、纠错、换话题样例。评审关注差异、克制、是否听懂，不以有更多表情或形容词当高分。

## 7. 手机界面：信息各有归属

首页保留紧凑助理卡，展开才显示待处理概览。进入聊天后仅保留一行办事入口，默认最多三项常用操作和一个更多；聘用管理归入更多。不要在对话页重复工作台说明。

普通回复一句情境回应。标准结果卡默认：事项标题、日期时间、动作状态/实际状态、一个主按钮。单项无复杂信息时高度参考 96–132px；换行和大字号允许自然变高，禁止裁切汉字。详情、撤销、来源记录放按需展开区；缺字段时优先展开那个字段。多个独立事项合成摘要，逐项状态可展开；部分失败不能只显示一个总成功标记。

沿用现有聊天字号；主体 14–16px 随用户字号设置，辅助文字不低于12px，按钮常用14px，点击目标至少44px。状态颜色不是唯一提示。320/360/390/430px、大字号、明暗主题及键盘同时覆盖。虚拟滑杆不回归，聊天不出现底部四导航浮起。

光感限于低频背景和焦点边缘；点击反馈使用 transform/opacity，避免每条消息重建大面积滤镜。保留主题特效，减少动画同时运行数量。遵守减少动态偏好。用户点击输入框、自己发送、收到新回复时，最新消息在输入框上方可见；重新挂载和键盘变化不重复强制跳动。

## 8. 提醒独立状态与可靠恢复

把提醒状态从“操作已完成”里独立出来：未要求、待补时间、待开权限、排队中、系统已安排、安排失败、不支持。只有原生调度成功且存在记录，才能展示系统已安排；只能证明系统接受，不保证用户已看到通知。未来时间、时区、重复实例与提前量由确定性规则计算，避免出现已经过去的提醒。

数据库操作和原生通知不能假装一个事务：事务中保存带版本的提醒 outbox，提交后幂等调度；成功后确认状态，失败有单项重试。改期、关闭、取消、完成、撤销均使旧通知失效，并有可恢复的取消/替换记录。调度过程中账号切换或版本变化时，迟到结果不得覆盖新设置。

启动、回前台、权限变化时核对自己负责的提醒；未启用权限不反复弹窗，用户点击启用时再请求。重启后能修复未确认的调度工作。Android 强制停止及厂商限制不能宣称必达，测试结果如实记录，提供检查入口，不用虚假承诺掩盖。

真机覆盖：权限拒绝/允许、屏幕锁定、后台、应用重开、设备重启、改期、重复、取消和撤销、网络断开、时区变化。验证旧提醒不多发，失败不说已安排。

## 9. 每日整理与主动协助

每日整理默认今天，记住非敏感显示和输出习惯，私密日记使用仍保留明确选择与锁校验。先展示可折叠的真实材料概览，再生成建议；资料不足具体提示还缺什么。草稿/建议逐项采用，不能静默保存和发布；素材变化后旧建议显示需要重核，不能覆盖新数据。

主动协助由用户启用。打开软件时根据真实事项提供一次可忽略的短提示，初始一天最多一次，同一事项同一状态不反复提醒；可选择仅当天或当天加逾期。时间冲突、未补完整的安排、用户允许的晚上整理是候选，不把日记内容带到首页提示。

前台建议不需要先打一轮模型；本地规则生成明确事实，点击“帮我理一下”才规划。关闭、忽略、延后均持久保存。用户忽略不是完成。后台执行必须有真实调度，不以 prompt 冒充定时服务。主动帮助不自动发布动态、不擅自改期、不新建用户没同意的任务。

## 10. 兼容性、迁移与实现位置

在现有 secretary 模块扩展，不重写整个聊天或角色体系。建议增加 planning-contract.ts（规划与字段依据）、receipt.ts（事实读模型）、focus.ts（任务焦点）、retrieval.ts（有界检索）、suggestions.ts（主动协助）；扩展 types.ts、agent.ts、feedback.ts 和现有通知模块。

涉及新增焦点、索引、outbox 表时使用当前最新 schema 的下一个版本，不在本文写死版本号。旧任务没有新字段时通过兼容读模型渲染；旧原始 reply 不重新编造成新历史消息。原聊天和生活表不清空，不改变用户手写内容，记忆纠正保留可追溯来源。

备份/同步纳入新增字段；导入后不自动继续操作、发布或安排旧通知；校验账号归属、来源版本和任期。单机幂等保护继续保留；若尚无服务端多设备锁，不声称已保证跨设备 exactly-once。多设备能力列为独立发布门槛，不能凭本地锁得出结论。

## 11. 一次性交付顺序

P0 收据契约与状态读模型 -> P1 意图/字段/多操作接续 -> P2 持久焦点和记忆有效性 -> P3 检索索引与压测 -> P4 提醒 outbox 与真机核验 -> P5 人物表达、紧凑卡片、每日整理 -> P6 自选主动协助 -> P7 全回归、真实模型试用、迁移与发布报告。

每个阶段先实现后跑针对性的真实数据/组件验收，不仅测 helper 返回值。不停在“文案改完”或“类型检查绿了”。异常可以记录和恢复，无效项目不影响独立有效操作。最后汇总所有阶段，不自动出包/发布，除非用户随后授权。

## 12. 满分交付门槛

1. 真实性：已有及新增对抗样例零假保存、假发布、假完成、假提醒；实际卡片与源记录一致。
2. 可执行性：至少150条固定中文任务语料及真实组件流程，覆盖否定/改口/多项/依赖/歧义；确定性边界全通过。真实模型至少60个任务，分布在实际可用的2–3种模型配置；明确意图正确办理 >=95%，剩余样例必须安全补问/失败而非错误执行，公布每配置成绩。
3. 连续性：跨会话/重开应用/改口/换话题/换助理/事项编辑撤销完整通过；源删改后的索引、摘要和焦点无幽灵信息。
4. 归属：跨账号、日记锁、角色私有记忆、撤回、迟到异步、导入和备份不扩大读取或写入范围。
5. 人味：五种性格真实对话评审，事实正确、性格可区分、尊重换话题；评审记录不以一个主观总分代替样例证据。
6. 界面：真实320–430px组件、明暗、大字号、键盘、长内容，无遮挡/横向溢出/状态混淆；屏录验证特效与滚动稳定。
7. 提醒：真机实验验证安排、失败、恢复、取消与替换；无法验证的状态不能标成功，平台约束如实列出。
8. 性能：完成上述数据量压测并报告指标，检索不再无界扫描；普通办事不增加固定模型往返。
9. 回归：既有助理、记忆、待办、日记、朋友圈、备份、聘用套件，以及类型检查/生产构建全通过。测试不得把“语句被吞掉”当完整正确处理，也不能用错误夹具降低失败数量。
10. 发布：至少一组旧真实备份升级前后数量与内容核对，未执行建议不被升级执行；交付真实模型报告、Android体检记录、已知限制、回退方案和实际改动清单。

满足这些门槛才称为完整交付。测试数量增长只说明覆盖增加，不能替代真实用户成功率、提醒实验和长期性能。
