# VirtuGene 5.0.0 真机体检清单

> **为什么需要你来做这一步**：5.0 到现在（Phase 1 → Phase 3c）所有结论都来自真实浏览器 + 真实 IndexedDB 的自动化验收。
> 但有四件事**只有真机能判定**：**节奏**（幕次早/晚）、**岔路密度**、**角色会不会反复提同一件事**、**稳定性**。
> 这份清单把它们变成可执行的动作 + 可回报的格式。
>
> **前提**：装的是 5.0.0 调试包；数据都在手机上；世界页与剧场列表**不需要联网**也能看。
> **回报格式**：`场景 → 现象 → 我的期望 → 截图/录屏`。不要贴 API Key，不要贴隐私日记正文（说现象就够）。

---

## 0. 开始前（5 分钟）

- [ ] 先做一次备份（我的 → 备份/同步），确认能导出成功（**出现任何异常就先停下来告诉我**）
- [ ] 记下世界页顶部那行弱化统计：`N 个角色 · 第 N 天 · N 段共同记忆`
- [ ] 准备两个角色：一个你常用（叫它 A），一个**几乎不用**（叫它 B）——B 是"旁观者"对照组

---

## 1. 世界页首屏（性能 + 诚实性）

- [ ] 点「世界」：内容是否**一秒内**出现？有没有白屏/闪烁/跳动？
- [ ] 数据为空时的文案：应是「你的世界还没有开始」，并且**不承诺**还没做的自动记录
- [ ] 退出再进、杀掉进程再进：数据稳定（不重复、不丢、统计数字对得上）

> 期望：首屏秒开；空世界如实说空；统计与列表一致。

---

## 2. 舞台节奏（对应已知限制 L1 / L4，**这次体检的重点**）

做**两次对照**：

- **顺推**：约 8~12 个动作，尽量顺着剧情推进（该走就走、该问就问）
- **拖戏**：同样 8~12 个动作，故意不推进（原地闲聊、回避冲突）

每次记录：

- [ ] **第几幕在第几个动作之后出现？**（舞台顶部有「第 N 幕」徽标，正文中间有「—— 第 N 幕 ——」标记）
- [ ] 出现得**太早**（还没进入状态就翻幕）还是**太晚**（聊半天还在第一幕）？
- [ ] **岔路口（选项）出现频率**：太少 / 合适 / 太多？两次各出现几次？
- [ ] 选项是不是"真选择"：选完**按钮消失**、不能再点；选项内容合理；**没有替你写动作**
- [ ] 你选了 A 之后，后面的剧情**有没有顺着 A 继续**？如果不顺，记下那一场与具体轮次

> 期望（供参考，不是硬标准）：第一次翻幕落在第 6~10 个动作之间；岔路**每一幕大约 1 次**。

---

## 3. 结算是否正确（错了比"不好玩"严重得多）

**完整演完 3 场戏**，每场结束后逐条对照：

- [ ] 世界页「最近发生」是否多了一条，类别显示**「世界剧场」**，标题就是那场戏的名字
- [ ] 若那场戏确实发生了值得记住的事 → 「共同记忆」里是否有它（不该凭空多出）
- [ ] **关系网络**页 → 那个角色的「为什么会变成这样」里，原因读起来**像不像那场戏**（而不是通用套话）
- [ ] 「未完成的故事」里是否出现**剧情里根本没提过**的事（出现 ⇒ 记下来，这是模型越界）
- [ ] 有没有把**系统提示/第几幕/选项按钮文字**当成剧情写进结算（不应出现）

> 期望：结算内容都能在正文里找到依据；找不到依据的即为缺陷。

---

## 4. 角色会不会反复提同一件事（对应已知限制 L4，**决定要不要加冷却**）

对角色 A **连续聊 10~15 轮**（中间穿插不同话题）：

- [ ] 它主动提起「共同记忆 / 演过的戏」几次？分别在第几轮？
- [ ] 是不是**几乎每轮都提**？（期望：偶尔，且与当前话题相关）
- [ ] 有没有把"你和它一起演的戏"说成"它和**别的角色**"的经历（不应出现）
- [ ] 有没有编造戏里没发生的细节（不应出现）

> 若"每 2~3 轮就提一次"或"完全贴着上一场戏不放"，请把当时的对话截图发我 —— 我会加冷却/衰减。

---

## 5. 隐私边界（对应 Phase 2b-4 / R6 收口，**可信度关键**）

- [ ] 写一篇**私密**日记（默认「仅自己可见」）→ 与角色 A 聊 5 轮：它有没有提到那篇日记的**内容或情绪**？（**不应出现**）
- [ ] 把同一篇改成**「告诉 A」**→ 再聊：A 提不提？（可以提）角色 B 提不提？（**不应提**）
- [ ] **撤回**授权（改回「仅自己」）→ 再聊：A 是否**立刻**不再提？
- [ ] 打开「谁能看到我的日记」总览：里面的状态与你的实际感受一致吗？「收回」是否好用？

---

## 6. 稳定性与失败表现（宁可不做，不可假做）

- [ ] **断网**发消息：应明确提示失败（不能假装成功）；历史消息仍可看
- [ ] **断网**时看世界页 / 剧场列表：应能正常打开
- [ ] **舞台中断网**点「继续」：应给出清楚的错误提示，并且**只保留你真做过的事**（不该出现空白、也不该出现假剧情）
- [ ] **长场景**（>100 条）：打开是否慢、滚动是否卡？
- [ ] **切后台再回来**（或接个电话）：舞台/聊天状态是否还在
- [ ] 连续使用 20~30 分钟：有没有发烫/掉电异常/崩溃（有就记下机型 + 时间）

---

## 7. 成本体感（5.0 第一次"会花钱"的功能）

- [ ] 私聊：大约每 5 条用户消息结算一次（这是 4.x 就有的机制）
- [ ] 舞台：**每个动作 1 次调用**；**每场戏结束再 1 次结算**；打开/离开/暂停**都不花钱**
- [ ] 记一下当天大概聊了多少轮、演了几场戏

> 若费用异常偏高，把当天使用情况告诉我，我按调用点逐条核对。

---

## 8. Android 细节

- [ ] 状态栏不透白（顶部深色条）；底部导航不被键盘顶起
- [ ] 返回键：世界 → 剧场/关系/我的生活 覆盖页都能正常退出
- [ ] 深色/浅色切换后，世界页与剧场页文字仍可读
- [ ] 舞台里长按选中文字、滚动是否正常

---

## 9. 回报优先级（按这个顺序）：

1. **结算错误 / 编造**（第 3 节）
2. **隐私泄露**（第 5 节）
3. **节奏不合适**（第 2 节）
4. **性能 / 崩溃**（第 1、6 节）

其余（视觉不精致、文案不顺口）可以直接说，我会排到视觉阶段（2c）一起处理。

---

## 10. 已知限制（**不必当 bug 报**，本次体检就是来给它们定值的）

| # | 限制 | 说明 |
|---|---|---|
| L1 | 幕次阈值是初始值（本幕 6 条 / 张力 0.65 / 兜底 12 条 / 最多 4 幕） | 等第 2 节的体感反馈再调 |
| L2 | 选择只进线性年表，不产生永久分叉 | "选过什么"会被记住并进入结算，但世界不会分叉成两条时间线 |
| L3 | 长场景一次最多显示 400 条 | 数据不丢，可继续写；分页懒加载未做 |
| L4 | 共同记忆/舞台**没有冷却机制** | 提示词里已写"不要每次都提"，但那是软约束；第 4 节就是来判定要不要加硬闸门 |
| L5 | 场景无模板/推荐，"第几幕"这类元信息不参与结算 | 有意为之，避免元信息被当成剧情 |
| L6 | 5.0 尚未发布：没有 APK 产物、没有 Release、没有推送远端 | 体检通过后再谈打包与发布 |
