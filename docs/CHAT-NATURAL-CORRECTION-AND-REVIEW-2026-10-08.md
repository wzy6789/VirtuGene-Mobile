# 自然纠正与语义评审：真实失败记录

总体目标尚未完成。这里记录的是一个失败方向及本地验证体系的实质改进，不是聊天达标报告。

## 自然纠正仍不稳定

生产提示已区分“没有记载”和“从未发生”，要求纠正保留角色口语，不公开依据、核验等内部过程；已有背景不扩大成第三方反应、身体体验或新的近况。相关区块只在角色经历追问时加入，不增加生产模型调用。

三次 DeepSeek V4.1 Flash 真实探针使用当前提示构建函数和共享契约，每次输出上限 320 token，思考 low。它们不是完整数据库/UI 验收。

- 无来源童年：撤回了旧话，但仍说“我这儿没这段记录”，有内部审查味。
- 有来源童年：保留了和哥哥看过的背景，却新增“偶尔重看”的现时习惯。
- 无来源咖啡：撤回原话后又编了“我认识一个下午四点灌浓缩晚上照样躺平”的人，并说“没这回事”，未知与事实否定仍未稳定分开。

三次服务商报告 4,368 token，正常结束，无自动重试。原始提示、合成历史、回复与 usage 在 `CHAT-FLASH-NATURAL-CORRECTION-2026-10-08.json`。

## 评审模型也需要验收

新增 `chat-candidate-review.ts`：构建有独立来源、历史和候选分区的评审请求；严格验证类别、结论、逐字问题引用及 JSON。普通口癖、短反应、无 emoji、无追问不被当作缺陷。该模块不发请求、不写数据，目前没有接入生产回复链路。

五次非思考 Flash 评审用量 2,923 token：一个评审引用了历史错误句而非候选原文，解析为未知；一个漏掉“偶尔重看”的编造，错误放行；编造咖啡熟人的例子被指出；两个正常口语对照被放行。

修改提示后只做了一次思考 low 校准，输出上限 512 token 全被思考耗尽，没有候选评审正文。记录为截断/未知并立即停止后续调用，没有不断抬高 token 上限。此次服务商报告 1,145 token。

以上九次请求总计服务商报告 8,436 token。凭证没有写入报告或代码，执行内核已重置。后续本地复核没有模型调用。

`chat-review-calibration.mjs` 可直接读取保存的两个评审报告，重跑本地解析并产生汇总：六次中正确 3、无法判断 2、错误放行 1、错误拒绝 0。这里的期望是开发者声明的样本判断，不是独立人工盲评。`productionReady:false`；未知和错误引用不会被算成通过。

## 小测的停止条件

`chat-expression-evaluation.ts` 现在明确标记截断，保留实际回复和用量，停止后续调用。没有可显示回复也停止。即使人为把生成标记改为完成、并给截断回复满分，汇总仍不能显示语义评分完成。UI 用既有错误状态展示停止原因。

最新本地证据：聊天表达 384 项、候选评审协议 20 项、质量完整链路 193 项和真实面板 UI 7 项通过；类型检查通过。测试只证明本地规则和接线，不证明真实人味、全部角色、长聊或语义评审达标。

下一步必须从会编新经历的真实反例继续改进，并扩展人物差异与长聊对照。未经校准的语义评审暂不作为生产放行条件。
