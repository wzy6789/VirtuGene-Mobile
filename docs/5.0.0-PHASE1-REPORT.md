> 因此世界层使用 **v17**。版本号永不重用。

| 表 | 用途 | 为什么需要（规则 3） |
|---|---|---|
| `worlds` | 世界容器，每用户一个默认世界 | 按 §二 确立为**正式实体**：现在建，将来加多世界/平行世界线/世界模板/世界导入复制时不必整层重迁移 |
| `worldEvents` | "世界真正发生过什么"的统一记录 | 年表 / 最近发生 / Life Trace 的唯一骨架；`LifeTrace` 合并为其中一种 `type`，避免两套时间源 |
| `worldScenes` | 一场 World Stage + **结构化** `SceneState` | §36 要求状态结构化，不能只写进 Prompt |
| `worldSceneEntries` | 场景正文（narration/dialogue/choice/user_input/system + act + index） | §六：必须独立表，支撑长场景、分页、断点恢复、暂停继续、单条重生成；正文塞进 `worldScenes.state` 会撑爆单行 |
| `characterKnowledge` | 谁知道什么 / 能不能说 / 谁的秘密 | §15 地基：**"发生过" ≠ "某个角色知道"**；秘密按 §五 合并进本表（`isSecret` + `secretOwnerId`），暂不独立建表 |
| `sharedMemories` | 用户与角色真正共同经历的重要片段 | §26 全字段；与 `memories`（用户事实）严格分工，互不迁移 |
| `relationshipStates` | A ↔ B **当前**关系状态（含分面） | §三：仅靠事件不足以回答"现在是什么关系"；关系页禁止现场累加历史 |
| `relationshipEvents` | 关系**为什么**变成现在这样 | §四：可解释关系 + 变化原因 + 来源事件回溯 |

**新旧分工（未替代、未迁移）**：`memories`（用户事实）、`sharedStoryEvents`（人物共同事件原始录入）、
`continuityThreads`（未完成事件）、`CharacterState.lifeEvents`（生命轨迹）**全部保留原样**，
世界层只是**派生**关系。

## 3. 实际新增索引

```
worlds              : id, userId, isDefault
worldEvents         : id, userId, worldId, type, [worldId+timestamp], [worldId+type],
                      [worldId+sourceType+sourceId], sourceType, sourceId, timestamp
worldScenes         : id, userId, worldId, status, [worldId+status], updatedAt
worldSceneEntries   : id, sceneId, [sceneId+index], index
characterKnowledge  : id, userId, worldId, characterId, eventId,
                      [characterId+eventId], [worldId+characterId]
sharedMemories      : id, userId, worldId, [worldId+createdAt], sourceType, sourceId,
                      [worldId+sourceType+sourceId], *characterIds
relationshipStates  : id, userId, worldId, pairKey, [worldId+pairKey], *subjects
relationshipEvents  : id, userId, worldId, pairKey, [worldId+pairKey], *subjects, sourceEventId, createdAt
```

- 每个主表都带 `worldId`（§二），因此验收 #8 的 World 隔离是**索引级**保证，不只靠代码过滤
- 复合索引 `[worldId+timestamp]` / `[worldId+pairKey]` / `[characterId+eventId]` 支撑世界首页、关系页、认知查询
- `*subjects` / `*characterIds` 为 multiEntry：一次查出"与某主体相关的全部关系 / 与某角色相关的全部记忆"

## 4. 数据模型最终定义

完整定稿见 **`docs/5.0.0-DATA-MODEL.md`**（术语表、字段语义、幂等键、迁移语义、删除规则、API 摘要）。要点：

### 4.1 主体标识（§十一）
```
用户 u:<userId>      角色 c:<characterId>
pairKey = 排序后用 | 连接：  c:gu-yue-na|u:abc123   /   c:lin-jian|c:xing-yao
```
不再使用裸字符串 `user`，避免与真实 characterId 撞名。

### 4.2 幂等键（§十）
```
幂等键 = userId + worldId + sourceType + sourceId
id     = stableId(prefix, ...parts)  →  "<prefix>_<16 位十六进制>"
```
确定性 id ⇒ 重复迁移/重放只覆盖同一行；迁移对已存在的行采用"**存在即跳过**"，不覆盖运行期新数据。

### 4.3 WorldEventType（§八，语义严格区分）
`reality` · `interaction` · `shared_memory` · `stage` · `relationship` · `continuity` · `knowledge` · `life_trace`
**明确禁止**：普通互动 → `stage`、未完成事件 → `stage`。

### 4.4 可见性（§九）
`private`（只有用户）/ `selected`（只有 `visibleTo` 里的角色）/ `world`（世界内可见）。
`sharedMemories` 与 `worldEvents` 均支持 `visibility + visibleTo`。
**`participants`（谁经历了）与 `visibleTo`（谁被允许知道）是两个维度**，不混用。

### 4.5 关系分面（§三/§四/§28）
`trust / affinity / dependency / conflict / familiarity`
- `affinity` **与 4.x 好感度同源，保留无上限语义**（可 >100）
- 其余分面 0~100 夹取；`0` = 尚无记录/中性起点，不是"关系为零"
- UI 只显示语义等级，数字仅供 Prompt 与剧情条件

### 4.6 隐私分级（§十三）
`Diary` 新增 `visibility` / `visibleTo` / `worldEventId`；
**旧日记升级后一律 `private`**，旧全局开关只影响将来新建日记的默认选项。

## 5. Migration 实现

实现文件：`src/lib/world/migrate-4x.ts`（`runWorldMigration(tx)`），由 `db/index.ts` 的 `version(17).upgrade()` 调用；
另有 `worldRepo.rerunMigration()` 供升级中断后补偿重建。

| 来源 | 产出 | 幂等键 |
|---|---|---|
| `CharacterState.lifeEvents.interaction` | `worldEvent(type=interaction)` + 认知 | `migration:lifeEvent:<id>` |
| `.memory` | `worldEvent(type=shared_memory)` + 认知 | 同上 |
| `.relationship` | `worldEvent(type=relationship)` + 认知 + `relationshipEvent` | 同上 |
| `.goal` | `worldEvent(type=continuity)` + 认知 | 同上 |
| `continuityThreads` | `worldEvent(type=continuity, resolved = status==='done')` + 认知 | `migration:thread:<id>` |
| `sharedStoryEvents` | `worldEvent(type=relationship)` + 双方认知 + `relationshipEvent` | `migration:sharedEvent:<id>` |
| `diaries` | **不派生**，仅补 `visibility='private'`、`visibleTo=[]` | — |
| `memories` | **不迁移**（保持"用户事实"） | — |
| `sharedMemories` / `worldScenes` | **不回填**（由运行期产生） | — |

**附加产出**：`relationshipStates` 初始化 —— 用户↔角色继承 4.x `affinity`（如 85），
角色↔角色按用户设定的 `storyRelations` 建行（数值留 0 = 尚无记录）；不编造 trust/conflict 等无来源的数值。

**约束遵守**：
- 升级回调内**零网络、零长任务**，纯本地变换，分批写入
- 既有 11 张表：**零改写、零删除**（`diaries` 仅补两个默认字段）
- 派生事件 `visibility` 保守取 `selected` + `visibleTo=[相关角色]`，不擅自让全世界角色都知道
- 每行保留 `sourceType` / `sourceId` / `meta`，可回溯到 4.x 原始记录（§60）

## 13. 下一阶段建议（Phase 2：世界入口）

不建议在 Phase 2 一次做完整个世界首页。建议拆成三小步，每步都能单独验收：

1. **2a 导航与空世界**：`MobileTab` 增加 `world`；底部四栏改为「消息｜世界｜角色｜我的」；
   手账从一级 tab 下沉为「世界 → 我的生活」入口；世界页先用真实数据渲染**空状态**（"你的世界正等待第一件事发生"）。
   验收：旧路径（聊天 / 群聊 / 角色 / 手账 / 设置）全部不回归；`tauri`/Capacitor 打包正常。
2. **2b 世界首页数据层接线**：`worldRepo.stats()` + `worldEventRepo.listTimeline/listUnresolved` + `sharedMemoryRepo` +
   `continuityThreads`（复用 4.x 的未完成事件 UI 组件）→ 真实渲染「最近发生 / 未完成的故事」四模块。
