## 1. 这一阶段让角色真的"说得出来"

2b-2 把用户收藏的瞬间写进了世界层，但角色说话时还看不到它（L1）。本阶段把它接上：

```
用户长按收藏 → sharedMemories + shared_memory 事件 + 认知（2b-2 已完成）
                        ↓（2b-3：每次发送前的纯本地召回，零网络）
              selectRecallableSharedMemories（三道闸门）
                        ↓
        systemPrompt 新增区块「[你和用户一起经历过的事]」
                        ↓
        角色的回复可以自然地提起这件事（不是被塞进嘴里的复述）
                        ↓
   Message.contextTrace.sharedMemoryIds 如实记录 →「记忆依据」面板可查
```

**用户现在能看到什么**：聊天里长按一条消息收藏后，继续和 TA 说话时，TA 会**自然地带出**那件事
（"那晚的风我到现在都还记得"）；长按那条回复 →「🔍 查看记忆依据」→ 面板里出现
**「你们一起经历过的事」**区块，写着那条共同记忆的原文。

## 4. 注入长什么样（可逐字核对）

```
[你和用户一起经历过的事]
- 那天凌晨三点，你说就算没人用也要把它写完，后来我们关灯看天亮。
这些是你们**共同经历过**、你也确实记得的事。如果这一轮话题自然相关，可以像真人一样提起它
（提一句、接着聊、或者只是语气里带着这份熟悉感）。要求：不要每次都提；不要像念清单一样逐条复述；
不要编造细节、不要把这些事说成是别的角色和你经历的；如果用户不接这个话题，就顺着用户。
```

区块 priority = **93**（relationship 100 / taught-memory 100 / story-relationships 97 / current-time 95 /
continuity 94 / **shared-memory 93** / life 92 / user-emotion 90 / shared-events 88 / memory 85 …）。
预算不足时它会被截断或丢弃——**此时溯源不记录**（见 §5），绝不谎报"已参考"。

## 5. 溯源契约（4.x 规则不变，且现在可被验收覆盖）

原来的规则写在 `ChatWindow` 里：只记录**完整注入**的区块。本阶段把它抽成纯函数
`buildContextTrace`（`src/lib/chat-trace.ts`），并用**真实的编译器**构造出"被截断 / 被丢弃"的场景来验证：

| 断言 | 结果 |
|---|---|
| 区块完整注入 ⇒ 记录 `sharedMemoryIds` | ✅ |
| 区块被预算**截断**（`partial`）⇒ **不记录** | ✅ |
| 区块被**丢弃**（`omitted`）⇒ 不记录 | ✅ |
| 4.x 三个来源的规则照旧（记忆与"主动回忆"合并去重 / 未完成事项 / 人物故事） | ✅ |
| 全空 ⇒ `hasTraceContent=false`（不往消息上挂空对象） | ✅ |

## 8. 过程中的三个发现（如实说明，其中两个是测试自己抓出来的）

1. **我一开始把"多出来的一次 LLM 调用"误判成召回的成本**。
   验收 D 组要求"两次发送 = 2 次调用"，实测 3 次。打桩的回复两次**一模一样**，
   于是触发了 4.x 既有的「重复自己」自检 → 静默重试一次（这正是 4.x 在正常工作）。
   改成每次返回**明显不同**的回复后，逐次计数 = 1。现在 D 组是按"每次发送的增量"断言的，更精确。
2. **发现一个与本阶段无关、但值得你知道的既有行为**：
   进入聊天时如果角色**还没有声线**，4.x 会调一次 AI 判定声线（1 次真实网络请求 + 该角色的声线）。
   验收里我最初没给夹具角色预置声线，于是这 1 次网络请求污染了"零联网"的测量。
   产品上这不是 bug（`createCharacter` 创建时会分配声线；受影响的是"导入/老数据/声线缺失"的角色首次进入），
   但**它确实是一次用户可能没预期的联网**。验收现在给夹具预置声线以隔离噪声，并把 fetch 调用栈打印出来备查。
3. **我自己写错了一处测试夹具**：忘了 `compileChatContext` 的预算是 `max(6000, budget)`，
   于是"被截断/被丢弃"两个场景其实根本没发生（3000/5000 字都塞得进去）。
   现在显式传小预算，并且**先断言"夹具真的落在 partial/omitted 里"**，再断言溯源规则——
   否则测试会在什么都没验证的情况下"通过"。

| L4 | 每轮都会注入（最多 3 条），**没有冷却** | 提示词里要求"不要每次都提"，但这是软约束；如果实测出现"连续几轮反复提同一件事"，需要加冷却/衰减（属体验调优） |
| L5 | 没有"这条我不想让它提"的开关 | 记忆管理入口（删除/隐藏）留到后续阶段；目前可用的手段是删除那条世界记录 |
| L6 | 群聊未接入 | `GroupChatPage` 仍是 4.x 的上下文；群聊涉及"多人在场"的可见性口径（`isVisibleToEveryCharacter` 已备好），留到世界舞台阶段 |
