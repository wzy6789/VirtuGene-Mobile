## 0. 一句话结论

**5.0 的世界不再是一套"剧情功能"，而是一个可以直接用自然语言共同生活、行动、创造、修改和延续的世界。**
用户不需要判断"我要聊天 / 开剧情 / 改设定 / 推进关系"——只说想说的话、做想做的事，系统内部把这句话翻译成

## 1. 最终架构

### 1.1 整体形状

```
用户说一句话（自然语言，唯一入口）
      │  写入 worldSceneEntries（用户行动立刻可见）
      ▼
┌─────────────────────────────────────────────────────────────┐
│ WorldAIClient（世界层唯一 AI 出口，§54）                      │
│  BYOK（用户自己的 Key）→ llmChat                             │
│  网关（4.x 既有 server/）→ gatewayChat                        │
│  都没有 → UNAVAILABLE，明确告诉用户（§55）                    │
└─────────────────────────────────────────────────────────────┘
      │
      ├─ Stage A  Intent Interpreter（1 次；"撤销"走本地规则 0 次）
      │            └→ WorldAction（永不展示给用户）
      ├─ 本地确定性动作（0 次）：改地点 / 改规则 / 改角色事实 /
      │            时间跳跃 / 召集与离开 / 结束话题 / 撤销 / 修改世界事实
      ├─ Stage B  Context Builder（0 次，L0–L10 分层 + 角色私有上下文）
      ├─ Stage C  World Director（1 次）→ TurnPlan（谁回应、要不要旁白、值不值得结算）
      ├─ Stage D  Narrator（条件性 0/1 次）+ 每角色独立 Actor（每人 1 次，可串行/并行）
      ├─ Stage E  Consistency Guard（重要轮次 0/1 次，可改写/丢弃）
      ├─ 可见内容落库并即时推送（§57 渐进式回应）→ 用户可以立刻继续输入
      └─ Stage F  Settlement（值得留下时 1 次）
                  LLM 建议 → Schema 校验 → 业务规则校验 → 事务 → 持久化
                  → WorldEvent / SharedMemory / Relationship / Knowledge /
                    Continuity / WorldFact / CharacterState
```

## 6. WorldAI Pipeline

统一出口 `WorldAIClient`（§54），内部按顺序尝试 **BYOK → 网关 → 明确失败**。
调用形态：`worldChat({ messages, temperature, jsonMode, disableThinking, maxTokens })`。
所有结构化输出都走 `safeParseAIResponse`。

实测调用次数（脚本可核对，逐轮记在 `worldTurns.llmCalls`）：

| 场景 | 调用次数 |
|---|---|
| 普通一句"你好" | 3（理解 + 导演 + 1 角色） |
| "大家别说话" | **1**（导演走短路规则，0 次模型调用） |
| 换地点 / 立规则 / 召集与离开 | 3–4（+1 次结算） |
| "直接到第二天早上" | 4（理解 + 导演 + 角色 + 守护；**不**结算） |
| "你们两个自己聊聊"（2 人 + 自动续 2 拍） | 7 |
| 撤销上一轮 | **0** |
| 打开 / 离开世界空间、翻看关系/记忆/时间线/设定页 | **0** |

## 7. WorldAction 实现

`WorldIntent` 共 20 种：`talk / act / summon / dismiss / character_interaction / change_location /
change_time / change_atmosphere / world_rule / character_fact / start_event / continue_event /
pause_event / end_topic / time_skip / recall / retcon / undo / direct_character / freeform`。

三层判定（顺序固定、可核对）：
1. `ruleInterpret`（0 次调用）：**只**认语义完全无歧义的"撤销上一轮"；
2. 模型判定（1 次调用，jsonMode）：其余一切，包括需要上下文才能判断的 retcon；
3. `fallbackInterpret`（关键词兜底）：模型不可用/解析失败时，世界仍然可用，**永不报错、永不让用户选模式**（§14）。

`WorldAction` **从不出现在 UI**。名字解析只接受真实角色名（编出来的名字被丢弃，绝不乱安）；
`silence` 是硬规则，覆盖模型给的 `requiresCharacterResponse`。

## 8. Director 实现

一次调用返回 `TurnPlan`：`narration / speakers[{characterId,intent,mode}] / sequential / worldChanges[] /
shouldSettle / suggestions[] / trace`。

硬性约束（由程序强制，不靠模型自觉）：
- speakers **只能**是在场角色，最多 2 个（用户要求交流时 3 个）；不在场/不存在的名字直接丢弃；
- 用户点名的角色**必须**出现在 speakers 里（模型漏了就补上）；
- `worldChanges` 只写真的发生过的变化；寒暄不写（因此"你好"不会产生世界事件）；
- `shouldSettle` 只在真正值得留下时为 true。

## 9. Actor 实现

每个要发言的角色**各自一次调用、各自一份提示词**。Actor 只能看到：
角色人格 + 当前关系 + 情绪 + **TA 知道的**共同记忆 + **TA 知道的**世界设定 + 当前公开内容 + Director 给的行为意图。
顺序生成（`sequential=true`）时，后一位角色的上下文里带上前一位刚说的话——**角色之间真的在互动**；
并行生成用于彼此独立回应用户，仅为降延迟。`mode=action` 的角色只说动作。

**"让他们自己聊"（§40）**：在初次回应之后按 `autoRounds`（默认 2，上限 6）继续推进小拍，
每拍 1 次调用、每拍仍只产出一个动作 + 一句对白；`shouldInterrupt()` 为真立刻停下（用户一输入就打断）。

## 10. Knowledge Isolation

**不是"嘱咐模型别说"，而是"模型看不到"**：Actor 的上下文里根本没有 TA 不知道的东西。
四道数据闸门：世界设定（可见性硬过滤）、共同记忆（可见性 + 认知 + 相关度）、
日记（可见 ∩ 可提及，与私聊同一口径）、片段（参与过 + 认知 + 可见性）。

守护者（Consistency Guard）能看到"这个世界里的秘密清单"，但它**只用来检查**，
不参与扮演；秘密本身不进任何 Actor 的提示词。

## 11. Settlement

**不是每轮都结算**（§28）。程序判定三条（缺一不可）：控制面板明确要求 / 导演认为有事发生 /
用户这句话本身就是持久世界变化（建地点、立规则、改角色事实、改写或撤销事实、有人加入或离开）。
时间跳跃、一次性氛围、结束话题**不**结算（它们只是"此刻"的变化，已由本地动作写成系统痕迹）。

一次专门调用返回：`summary / worldEvents / sharedMemories / relationshipChanges /
continuityChanges / worldFactChanges / characterStateChanges`。
校验层（复用 + 扩展）会丢弃：非法事件类型、参与者不在场的事件、`affinity` 分面、缺原因的关系变化、
涉及场外人的变化、不在场的角色状态、模型指定的认知归属。数值一律夹取（单拍好感度 ±5、心情 ±3、分面 ±10）。
**解析失败 ⇒ 世界保持原状态。**

## 12. World Facts

新表 + 自然语言层（§31–§33）。世界设定页顶部就是一句话输入框（"告诉我这个世界是什么样的……"），
每条设定是一张自然语言卡片，可编辑 / 暂停 / 恢复 / 删除。分类：`rule / location / atmosphere /
history / shared_knowledge / character_fact / custom`。

**改设定不会留下两条冲突的 Canon**（§101），两条路都只"停用"旧的那一条（历史仍可查、可恢复）：
1. 模型提出 `replaces`（原样抄写被替换的旧设定）⇒ 程序按**原文精确匹配**后停用；
2. 确定性兜底：两条同类设定共享实词、且**恰好只有一条含否定**（`contradictsRule`）⇒ 停用较旧的一条。

**世界设定不只在设置页能改**：在世界空间里说"这个世界以后没有冬天"效果完全相同（走同一条写入路径）。

## 13. Undo / Retcon

**Undo（§16）**：0 次调用。按 `worldTurn` 记录精确回收——正文（`entryIds`）、世界事件及其认知、
共同记忆、未完成的事、这一轮新写的世界设定；**反向回退**关系分面增量与 4.x 好感度/心情，
并删掉这次写下的"为什么变了"轨迹；把"此刻"（地点/时间/氛围/在场的人）还原成这一轮开始前的快照；
最后把轮次标记为 `undone`（**不删记录**——当时发生过什么依然可查）。
被这一轮**停用**的旧设定会恢复启用（不删除）。

**Retcon（§15）**：用户是世界最高权限者。改世界事实是**本地确定性写入，不等模型**
（验收里用"AI 全挂"的注入 caller 证明：模型全挂时事实上照样落库），角色不会反问"你为什么这么说"。

## 14. World Canvas

沉浸式全屏（进入后隐藏底部一级导航，§67）。结构（§9）：
顶部只显示"地点 · 时间 + 在场的人"（点击才展开地点/时间/氛围/在场/世界控制）；
中间是世界流；下面是在场人物 chips + 灵感建议 + 输入区。
输入框 placeholder 是 **"说句话，做件事，或者改变这个世界……"**，Enter 送出、Shift+Enter 换行（中文输入法组合中的 Enter 不拦）。

- **渐进式回应**：用户行动立刻落库并显示；第一位角色生成完立刻出现；看到回复就能继续输入（§57）
- **分页**：默认只渲染最近 60 条，顶部"查看更早内容"按需加载（§68）
- **滚动**：停在底部就自动跟随；正在向上阅读**绝不**强拉到底（§70），改为出现"↓ 新内容"按钮
- **键盘**：输入区固定在安全区上方，内容区自适应
- **返回键**：先退出世界空间回到「世界」（历史/片段都在，不丢）

## 15. 世界主页

`我的世界` + 一句自然描述（"古月娜、星遥与你正在共同生活。"）+ 一行弱化统计（`第 N 天 · X 位角色 · Y 段共同经历`）。

视觉核心只有一个区域——**此刻**：有活跃片段时显示"地点 · 时间 + 最后一句 + 上一次没说完的事 + [继续]"；
没有片段时显示 **"此刻很安静。没有必须完成的故事。你想做什么都可以。 [进入世界]"**

## 19. API Failure Recovery

- **用户输入先落库**：任何 AI 阶段失败都只是 `status='failed'`，用户原话与已生成的正文都还在
- **重试不重复**：复用同一轮、同一条正文，**绝不再次插入用户输入**（`retries` 计数可核对）
- **三态可用性**：`AVAILABLE` / `TEMPORARY_ERROR` / `UNAVAILABLE`；没有 Key 也没有网关时明确显示
  "当前没有可用 AI 服务，请先在「我的 → 设置」里配置模型 Key"，不让按钮一直转圈
- **解析兼容**（§63/§64）：标准 JSON / ```json 围栏 / JSON 前后有解释 / 尾随逗号 / 单引号 /
  缺非必要字段 / 纯正文，全部读得出来；坏 JSON 残骸**不会**被当成正文显示给用户

## 30. 尚存在的真实限制（不隐瞒）

1. **未做真机测试**。所有 UI 结论来自无头 Chrome（真实渲染 + 真实 IndexedDB + 真实构建 CSS）。
   必须真机复核：键盘弹出/收起时输入框是否始终可见、底部导航隐藏时机、系统返回键（先收键盘再退出）、

   我保留并让它们通过构建与回归，但**没有为它们新增专门的验收套件**。
3. **结算与自动续拍的成本是真实的**：一句"我们去海边"= 3 次调用（理解/导演/角色）+ 1 次结算；
   "你们两个自己聊聊"默认 2 拍 = 7 次。这是为体验质量付出的代价（§21/§61 已明确不以省 Token 为目标），
   但**没有做真实设备的耗时实测**，也没有做"自动续拍拍数随网络质量自适应"。
4. **一致性守护是条件性的**：有秘密在场 / 值得结算 / 涉及世界规则与改写事实时才跑（+1 次调用）。
   普通寒暄不守护，因此**理论上**普通轮次仍可能出现 OOC；这是成本与质量的显式取舍。
5. **相关性召回是词面匹配**，不是向量检索（移动端本地跑不了 embedding，也不该为此多花一次调用）。
   因此"完全换一种说法的回忆"可能召回不到；已在代码与验收里如实说明（§60 的验收用的是共享实词）。
6. **`affinity` 的撤销是"反向增量"**，不是绝对值快照还原——如果撤销之前刚好跨过了一个关系等阶门槛，
   `peakLevelFloor` 会让好感度停在新门槛上（不会跌破已达境界）。这是 4.x 既有规则的必然结果，已按原样保留。
