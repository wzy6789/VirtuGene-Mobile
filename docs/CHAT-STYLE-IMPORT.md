# 可选聊天风格学习

入口：创建角色 → 如何表达 → 学习说话方式。默认收起，不需要使用即可完成原来的创建流程；编辑已有角色也可使用，不改既有聊天记录。

## 操作

1. 粘贴文字、导入 TXT，或在 Android 版导入聊天截图。TXT 支持 UTF-8 与 GB18030；QQ 的「日期 时间 昵称(账号)」格式可识别。普通文字采用「昵称：消息」格式。
2. 核对识别结果，删除昵称、系统通知等无关内容。截图按选择顺序处理，左右只是初步识别，群聊请手工改为实际昵称。换行可直接编辑；没有可靠归属的居中内容不自动猜测。
3. 选择学习对象，至少 5 条文字，建议 20–50 条。分析只发送该对象的样本，最多抽样 100 条、18,000 字；不发送其他人的文字。
4. 明确确认后使用当前配置的模型提炼风格。可编辑规则与示例；相遇页试聊不建立会话、不写聊天消息。只填名字与学习风格，也能直接使用设定创建。
5. 可选共同记忆需另行填写、勾选。默认不导入，保存到当前用户的目标角色，接入既有统一记忆仓库与 ledger。学习风格本身不意味着继承原人物的私人经历。

## 数据与边界

- 截图在 Android 使用随安装包携带的 ML Kit 中文模型识别，不上传、不保存图片，不依赖首次下载模型。电脑预览使用文字/TXT，未接入云识图。
- 原图和原始聊天仅作为创建页的临时草稿，不落库。确认后的 `learnedSpeechStyle` 与提示词保存在人设中，各模式沿用统一角色人设。
- 模型分析仅在明确确认后发生；离线 OCR 不调用 LLM，跳过整个功能为零调用。
- 单次最多 10 个文件，文本每个 1 MB，截图每张 12 MB / 4000 万像素；长截图分块识别，接缝去重不全局删除重复消息。保留 OCR 复核环节，不承诺左右归属百分之百准确。
- 不读取微信/QQ 私有数据库，不解密备份，不自动采集其他应用。

## 验证

`chat-style` 验收覆盖目标隔离、明确授权、无原文落库、试聊、可选记忆、编辑不重复人设块；`character-create`、`character-ui`、`character-scroll` 回归。Android 原生插件经 `:app:compileDebugJavaWithJavac` 编译验证；真实截图识别需安装版真机检查清晰截图、长截图与左右归属。

复跑：`node scripts/verify/build.mjs` → `node scripts/verify/serve.cjs` → `powershell -File scripts/verify/run-all.ps1 -Suites chat-style,character-create,character-ui,character-scroll`。
