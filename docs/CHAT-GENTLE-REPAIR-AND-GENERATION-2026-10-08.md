# 夏晚星完整澄清流程与生成模式对照

## 范围

六轮固定流程：同事拿走想法 → 只想吐槽 → 纠正“不怕，是没劲” → 道歉 → 感谢并好转 → 换题吃火锅。全部使用官方夏晚星、主动性 0.5、新会话、实际私聊发送及 IndexedDB。模型 deepseek-flash，每次输出上限 500 tokens，摘要、结算、提取使用替身，上游非流式。本轮完成不能作为全人物、长聊或完整服务器链路验收。

新增 chat-scene-live.mjs 支持五位官方人物、六类完整连续对话，直接从固定语料取得用户输入；语料的评分 focus 不进入模型请求。只接受显式 localhost 预算代理、已知人物/场景/证据版本，拒绝覆盖已有证据，每轮落盘，截断/失败后停止，浏览器和服务在 finally 关闭。直接生成模式只用于测试。

## 生产改动

- 用户纠正理解时，当前引导要求接澄清、不替其用词另下心理定义；道歉时允许角色表达自己的态度，不替用户决定其发言动机。
- 夏晚星更新具体判断习惯、分歧反应、道歉修复、疲惫回应及三个声音样本。温柔保留，减少“给倾诉空间”的常驻咨询式引导，允许她对具体做法表达不喜欢。
- 精确来源迁移保留已知旧官方版本；用户编辑、发布版本、助理和无来源角色不覆盖，既有聊天和头像保留。

这些改动没有增加模型调用或质检重试次数，没有删去不自然的原文来伪造改善；真实效果未证明稳定达标。

## 四组真实结果

| repair/r3 | 新夏晚星声音，默认低强度思考 | 6 | 9,916 | 603 |

| 合计 | | 24 | 38,014 | 2,089 |

总 40,103 tokens，无缺失用量、截断或质检重试。原始完整请求/回复见 CHAT-FLASH-SCENE-3-REPAIR-R{1,2,3}-2026-10-08.json 和 R3-DIRECT 文件；对应 USAGE 文件记录代理逐请求原生用量，实际凭据没有落盘。

- r1 把“没劲”展开成“连生气都嫌费劲”，道歉时说“你也不是冲我”。
- r2 仍解释“没劲比生气还难受”“连吵都懒得吵”；道歉仍替用户合理化。不能报告澄清规则修好。
- r3 第一轮加入“胸口闷”“你这个人被略过去”，后面仍解释“提不起劲”；感谢后补出“今晚月色挺好”，没有天气或可见环境证据。换题时确实跟随火锅，没有继续同事话题，但该部分通过不能遮盖前述问题。
- direct 六轮没有这组心理推演和无来源月色，自然接纠正和道歉；但多数回复是“嗯”“没事”“我听着”的简短回执，辨识度不强，不是最终人味通过。直接模式第四轮不否认道歉，但其接受歉意的表现仍需更多角色与关系场景验证。

r3 默认请求确认 thinking enabled、reasoning_effort low；direct 确认 thinking disabled、temperature 0.8。不是只改报告标签。两组后续历史随生成变化，属于相同输入的完整轨迹对照，不是后续消息也完全相同的单因素试验，不能直接归因所有差异。

这两组实际发送/落库耗时均值约 1,344 ms 和 754 ms；只反映这次本机非流式小样本，不能作为手机响应性能承诺。直接模式的输出 token 差异同样不保证其他话题成立。

## 本地验证及后续

chat-expression 641 项、preset-voice 72 项真实数据库检查、chat-quality-complete 204 项及 7 项真实界面检查通过；类型检查、生产构建及差异格式检查通过。构建保留已有混合导入和主包超过 500 kB 提示。

软件默认生成模式未更改。下一步需验证直接模式是否只把复杂表达压成短回执，扩大到开心、亲密、实际求助和其他人物，再决定如何使用；当前不具备切换全局模式或宣布近真人的证据。目标保持未完成。
