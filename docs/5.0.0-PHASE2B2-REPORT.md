## 1. 这一阶段让用户能做什么

在聊天里**长按一条消息** → 「🧠 收藏为共同记忆」→ 这条消息成为你们**共同经历过的事**：
写进世界层，出现在世界页的「共同记忆」里，并让那个角色"知道"这件事。

```
长按消息气泡（4.x 既有的长按菜单，不新造交互）
   ├─ 📋 复制 / 💬 引用 / 💾 记住 / 🔍 查看记忆依据 / 🗑️ 删除   ← 4.x 原有，一行未改
   └─ 🧠 收藏为共同记忆                                        ← 本阶段新增
              ↓（纯本地，一个事务，零网络）
        sharedMemories（记忆本身）
        worldEvents（shared_memory 事件：年表/最近发生）
        characterKnowledge（该角色知道 ⇒ 可提起）
              ↓
        明确反馈「已收藏为共同记忆 · 去世界看看 →」（可直接跳到世界页看到它）
```

**与 4.x「记住」的分工（这是本阶段最要紧的一条边界）**

| | 💾 记住（4.x 早有） | 🧠 收藏为共同记忆（2b-2 新增） |
|---|---|---|
| 存什么 | **关于用户的事实**（"用户喜欢猫"） | **你们一起经历过的事**（那天凌晨三点） |
| 落到哪 | `memories` | `sharedMemories` + 世界事件 + 认知 |
| 谁会用 | 注入 Prompt 的「关于用户的长期记忆」区块 | 世界页 / 共同记忆 / 后续世界剧场与上下文编译 |
| 互相替代？ | **不**。两者互不迁移、互不覆盖 | **不** |

## 2. 写入规格（严格按已批准的 §5 写入路径）

| 项 | 规格 |
|---|---|
| 触发 | 用户在聊天里**显式**长按 → 收藏（不做任何自动收藏） |
| 三处写入 | `sharedMemories`（记忆）＋ `worldEvents`（`shared_memory`）＋ `characterKnowledge`（认知） |
| 事务 | **三张表在同一个 Dexie 事务里**：任何一步失败整笔回滚，绝不留"有记忆没有事件"的半写状态 |
| 幂等 | 记忆 id = `stableId('smem', userId, worldId, 'message', messageId)`；事件 id 由记忆 id 派生；重复收藏只返回原 id（`created:false`） |
| 参与者 | `u:<userId>` + `c:<characterId>`（谁经历了） |
| 可见性 | `selected` + `visibleTo=[该角色]`（**不擅自让全世界角色都知道**——与 2b-0 事件同一口径） |
| 认知 | 参与的角色获得 `full` + `canMention:true`（亲身经历）；其他角色**一条认知都不写** |
| 重要度 | 按分档：`shared_memory` = 0.7（记忆与事件一致） |
| `resolved` | `true`——"已经发生过的事"不是待办 |
| 标题/正文 | 纯函数 `splitForMemory`：标题=第一行（>40 字截断加省略号），正文=**标题没覆盖到的部分**（不重复、不丢内容）；空消息（纯图/纯语音）用如实占位，**不编造内容** |
| AI 调用 | **0**（整段是本地写入；验收里用 `window.fetch` 打点，任何一次联网都算失败） |

## 4. 三条需要你确认口径的设计裁定（都在验收里被断言）

### 4.1 写入放在"世界写入器"而不是组件里

与 2b-0 同一个理由：世界层的写入只应有一个入口，将来（世界剧场、日记可见性）再接入时不会各处漏写。
组件只做一件事——调用 `collectMessageAsSharedMemory`，并按返回值给用户**如实**反馈：

- `created:true` → 「已收藏为共同记忆」
- `created:false` → 「这条已经是你们的共同记忆」（**不假装又收藏了一次**）
- 抛错 → 「没能存下来，稍后再试」（**不假装成功**）

### 4.2 认知写了，但**目前还没有进入角色说话时的上下文**（重要限制）

本阶段写入了 `characterKnowledge`（谁知道 / 能不能提起），这是世界真实性的地基；
但**上下文编译器现在还没有读 `sharedMemories` / `characterKnowledge`**（全仓库只有世界页在读共同记忆）。
也就是说：收藏现在会影响**世界页与认知记录**，**还不会**让角色在聊天里主动提起。

这不是遗漏，是阶段划分：`sharedMemories` 进入 Prompt（"角色真的记得你们一起经历过什么"）属于
世界剧场/上下文编译器那一步（Phase 3）。**如果你希望更早，我建议在 2b-3 之前插一个小阶段专门做这件事**——
它是"VirtuGene 记住你们一起经历过什么"从"记下来"走到"说得出来"的关键一跳。

### 4.3 同一件事不在同一屏说两遍（新规则）

2b-1 已经定过一条规则：**未结束的未完成事项不出现在「最近发生」**（它由大卡与「未完成的故事」承担）。
本阶段把同一条原则延伸到共同记忆：

```
「最近发生」= 时间线（去掉：未结束的未完成事项、已在「共同记忆」区块里展示的那几条记忆）
```

**边界（刻意保留）**：只排除"**已经展示出来**的那几条"。共同记忆区块最多展示 3 条，
更早的记忆虽然没出现在区块里，它的事件**仍照常留在时间线上**——避免"看不见就等于消失"。
验收 E 组用"共同记忆 + 关系变化事件"同时覆盖两个区块，确保这条规则不是空断言。

### 4.4 反馈与「去世界看看」

世界层在另一个页面，如果收藏后什么都不说，用户会以为没生效。因此加了一条**轻量反馈**（4 秒自动消失），
里面的「去世界看看 →」按**底部一级导航 switchTab 的同一套语义**跳转：清掉"从列表/角色页推入聊天"的标记、
复位覆盖页、再切 tab。
（聊天页推入时底部导航是隐藏的，如果只 `setMobileTab('world')` 会**停在聊天页**——验收 G 组专门断言了这一点。）

## 8. 测试侧的三处自我更正 + 一个真实的测试缺陷（必须披露）

1. **一处假失败（我的断言写错了）**：P 组"正文不丢不重"原本用全 `x` 的字符串，
   而 `title` 本身就是 40 个 `x`，`title.includes(summary)` 必然为真 → 断言自相矛盾。
   改成有区分度的 `AAAA…BBBB…`，现在真的能验证"截掉的部分接在正文里"。
2. **`db.lifeEvents` 这张表不存在**：我按记忆写了 `db.lifeEvents.count()`，实际 4.x 是把生命轨迹
   存在 `characterStates.lifeEvents` 数组里。已改为从 `characterStates` 汇总，断言不变（仍要求 0 条）。
3. **断言计数口径更正**：2b-0 报告里写的"38 项"、2b-1 报告回归表里写的"46 项"都是当时的粗略标签，
   与脚本实际打印的行数不符。以**实际打印行数**为准：Phase 1 = 77、2a = 49、2b-0 = **43**、2b-1 = 32、2b-2 = 66，
   并已在 `scripts/verify/README.md` 里明确列出、注明这次更正。历史阶段报告（2b-0 / 2b-1）作为当时的交付记录**原文保留**，
   没有回头改写——但其中的计数请以 README 与本报告为准。
4. **一个真实的测试缺陷（本阶段修掉）**：harness 的 `mount()` 原本只 `root.unmount()` 而不把旧 host 从 DOM 移除，
   于是上一个组件的文案会留在 `document.body.innerText` 里——这会让"菜单里没有 X"这类断言**假通过**。
   现在 `unmount()` 会连带移除 host。这类问题不会影响产品，但会**让验收说谎**，所以单独记一笔。

## 11. 审核前置修复：可见性必须是过滤条件（L1 之前必须做的事）

**审核指出的缺陷（属实）**：`sharedMemoryRepo.listRelevant` 把"是否可见"当成**排序加分项**
（`score = overlap*2 + importance*3 + recency + visible`），而不是**过滤条件**，
并且随后的 `.filter(score > 0)` 让几乎任何记忆都能通过。
一旦上下文编译器用它召回记忆，就会把**本不对该角色可见**的共同记忆（包括 `private`）送进 Prompt。

**影响面**：本阶段之前**没有任何生产调用**（全仓库只有世界页在读共同记忆），
因此 2b-2 已交付的功能不受影响；它是 L1 的**前置修复项**。

### 修复内容

| # | 改动 | 说明 |
|---|---|---|
| 1 | 新增 `src/lib/world/visibility.ts` | **唯一一处**可见性闸门：`isVisibleToCharacter` / `isVisibleToEveryCharacter`；并明确"空角色列表 ⇒ 一律不可见" |
| 2 | `shared-memory-repo.listRelevant` | **先过滤、后排序**：可见性不再参与打分（并删掉无意义的 `score > 0` 兜底）；`characterIds` 为空直接返回 `[]` |
| 3 | `world-event-repo.listVisibleToCharacter` | 原先内联的三态判断改为调用同一份闸门（**行为不变**，只是不再各写一份） |

| 5 | `shared-memory-repo.listExperiencedWith` | 注释写清它是"谁和谁一起经历过"的叙事视角，**不得**直接用于注入上下文 |
