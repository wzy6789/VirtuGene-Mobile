## 1. 这一步解决了什么

Phase 2a 审核结论是"世界会持续生长的闭环尚未成立"。本阶段把它补上：

> **新用户和角色聊过之后，世界页真的会出现真实事件。**

做法是**不新写流程**，而是在既有流程后面接一个纯本地的"世界写入器"：

```
既有结算（每 5 条用户消息一次，4.x 早已存在）
   ├─ context-consolidator  →  未完成事件（约定/计划/话题/分歧/提醒）
   ├─ dimension 分析与好感度结算  →  关系等阶升级时写入一条「关系变化」生命轨迹
   └─ 记忆提取 → 只进 memories（用户事实），不进世界层
                       ↓（新增：纯本地派生，无网络、无 LLM）
                  world-writer
                       ↓
     worldEvents（年表/最近发生） + characterKnowledge（谁知道）
```

## 2. 写入规则（严格按已批准的 §5 规格）

| 既有来源 | 是否写入世界层 | 世界事件类型 | 说明 |
|---|---|---|---|
| 关系等阶升级（`lifeEvent.type='relationship'`） | ✅ | `relationship` | 重要度 0.7；标题即"关系进入「熟悉」阶段" |
| 未完成事件（`continuityThreads`，含既有 AI 提取与手动添加） | ✅ | `continuity` | `resolved` 仅在"已完成"时为 true；收起/稍后再说都不算已解决 |
| 约定/计划类生命轨迹（`lifeEvent.type='goal'`） | ✅ | `continuity` | 与上同源语义 |
| 普通互动（`lifeEvent.type='interaction'`） | ❌ | — | **噪音控制**：世界年表不是聊天流水账 |
| 用户「记住」（`lifeEvent.type='memory'`） | ❌ | — | 属"用户事实"，只进 `memories`；真正的共同记忆入口在 2b-2「收藏为共同记忆」 |
| 群聊创建（`source='group'`，如"进入共同场域"） | ❌ | — | **已按裁定排除**：建群是功能操作，不是关系变化（来源白名单） |

**每条事件都会带上**：
- 参与者 = `u:<userId>` + `c:<characterId>`；
- 可见性 = `selected` + `visibleTo=[该角色]`（**不擅自让全世界角色都知道**）；
- 认知 = 该角色一条 `characterKnowledge`（亲身经历 ⇒ `full` + 可提起）；
- 来源 = `sourceType` + `sourceId`（可回溯到 4.x 原始记录）；
- **确定性 id**（`userId+worldId+sourceType+sourceId`）⇒ 幂等。

## 3. 实现位置（仓库层收口，零 UI 改动）

| 文件 | 改动 |
|---|---|
| `src/lib/world/world-writer.ts`（新增，约 150 行） | 世界写入器：`syncLifeEventToWorld` / `syncContinuityThreadToWorld` / `removeContinuityThreadFromWorld`；含类型映射、重要度分档、认知写入、"失败不阻断" |
| `src/db/state-repo.ts` | `recordLifeEvent()` 在**事务之外**调用写入器（世界层是派生数据，写不进去不能影响生命轨迹本身） |
| `src/db/continuity-repo.ts` | `createMany / complete / drop / reopen / update / remove / deleteByCharacter / clearForUser` 全部同步世界层（完成→`resolved`、编辑→标题同步、删除→派生事件移除） |
| `src/db/world-event-repo.ts` | `update()` 的 patch 允许 `meta`（供状态/文案同步） |
| `src/components/world/MobileWorldPage.tsx` | 空状态文案改为**如实**列出写入来源（约定 / 关系变化 / 往后的世界剧场） |

**为什么放在仓储层而不是 UI 层**：这样"无论是 AI 提取还是用户手动操作，只要未完成事件变了，世界就知道"，
不需要在 4~5 个 UI 文件里各加一次调用（少一处就漏一处）。所有同步都包了 try/catch，
失败只 `console.warn`，绝不影响 4.x 既有行为。
