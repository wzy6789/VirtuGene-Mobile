# 私聊表达整改 · 2026-10-05

本轮落实“人味不足”审查中可由应用保证的表达载体和提示结构修复。括号动作剥离、气泡内不换行、最多三条消息的既有协议保留。没有调用付费模型或发布 APK、部署网关；测试中的模型输出为替身，不能据此宣称真人感已达到满分。

## 已实施的行为

| 问题 | 当前处理 |
| --- | --- |
| 默认生成一条完整答案 | 单条反应、直接说一句、反应后补内容及认真长说均可，按情境选择，不把“反应＋内容”固定为默认。普通非流式文本超过60字时按自然标点补分条；已上屏的流式消息保持原分条与 ID。 |
| 纯反应被质检否决 | “嗯”“嗯嗯”“确实”“哈哈哈哈”“啊？”“？？”及 emoji 可以单独成条；普通招呼不再触发客服腔重试。 |
| 问号被改成句号 | 删除问号压平，保留“？？”“？！”等强度。质检只提示连续三个实质问句，不把纯标点、反应词和引述里的问句算成采访。 |
| 重复检测消灭口癖 | 放行稳定开头和登记的口头禅；仅检查整段照搬及至少12字的重复长句片段，不再以共同的短意象强迫换开头。用户回声判断同时比较双方字符集合，避免长笑声因属于用户长故事中的字符而误判。 |
| 情绪载体缺位 | 共享契约明确示范句尾语气词、emoji、连续标点、自我纠正；一轮一两个 emoji 是引导，冷淡角色、严肃话题及用户要求优先。 |
| 角色必须接所有问题 | 允许坦言不知道、不想答、拒绝、反问或岔开，仍尊重明确求助、人物能力和真实记录。 |
| 通用规则盖过人设 | 客户端及网关复用一份12行表达契约；删除旧英文重复防护及已失效长协议。普通服务不再同时注入人物心意、单独口头禅块；声音卡预留预算、位于可选上下文之后。 |
| 前一轮问句禁止下一轮提问 | 取消自动禁问；显式“少问问题”的用户偏好仍保留。最近动作作为背景，不强制每轮轮换语气。 |
| 自建人物没有声音样本 | 新生成的人设要求2—3组短对话样本；尾部声音卡提取已有导入示例、内置预设的“用户：…你：…”、明确称呼和口癖，不把例句当作真实经历。 |
| 主动分享固定每三／五轮 | 用角色名、持久轮数和主动程度作稳定概率抽样，相邻机会留间隔；只给可选话题线索，不自动发送，不从闲聊强行制造任务。 |

情绪场景的本地温度建议由下调改为 `+0.05`。这只有在供应商支持该参数的模式下生效；当前 DeepSeek 默认思考模式会忽略温度，实际请求也不发送无效温度。不能把本地建议值变化等同于真实模型已变得更有情绪。

## 提示与数据边界

`server/chat-messaging-policy.mjs` 是客户端 BYOK 与网关的唯一普通聊天表达契约。网关再次接收已拼好的提示时替换同名块，避免叠加；助理的结构化操作规划不注入这个聊天格式契约。网关安全约束继续保留。网关系统提示限额提高至26000字符，以容纳24000字符的上下文预算、尾部声音卡和协议，不截掉卡片。

不将未经审核的原始回复直接写入对话历史。历史继续使用用户实际看到的消息，保留本轮释放的问号、emoji、口癖和反应条；被弃用的重试结果、括号动作或内部分析不回喂。这已经打断“问号压平后再学习压平语气”的回路，也避免模型误以为自己说过用户没见过的话。旧的已压平消息不会凭空恢复，新生成的表达才获得这项修复。

不迁移或自动重写旧人设，不额外生成付费声音样本。已有样本可直接提炼；没有样本的旧角色依靠现有标签、称呼、口癖和问候建立声音卡。新人物生成要求写样本属于模型输出契约，真实模型是否遵守仍需另行观察。

多于三条的 JSON 消息现合并到第三条，不再丢掉尾部改口。未增加额外模型调用，也没有让质检静默替换已上屏的流式文本。

部署网关时须一起复制 `gateway.mjs`、`deepseek-policy.mjs`、`chat-messaging-policy.mjs`；步骤已同步到 `docs/AI-GATEWAY.md`。本轮只准备代码，未进行部署。

## 第二轮：情境、判断与长聊

用户确认继续改善情境回应、人物判断和声音稳定性后，本轮增加以下处理：

- 共享契约取消“默认先反应再内容”。最近三个保存的回复轮次都采用短条加内容时，尾部仅加入一个可选节奏提示，不强制轮换，不拦口癖，不为此重试模型。按 `replyToUserMessageId` 合并气泡，避免把同一轮三条误算成三个回合；只读取现有上下文末尾40条，输出最多四轮，不增加历史扫描或数据库字段。
- 当前原话中的受挫、疲惫、开心和混合感受提供不同表达线索。否定、双重否定、引用、假设与代写请求有针对性检查；换到普通新话题后不会自动延续安慰。线索只是本地启发式提示，不是语义理解的完整替代，更不保存为用户心理事实。模型仍读取原话，用户当前要求优先。
- 声音卡将性格落实到关注点：冷静型关注事实与猜测，温柔型关注未被理解的落差，活泼型关注具体突破，尖锐型关注事情的不公平，稳重型关注现实约束与选择。具体人设中“判断习惯”“价值观”“在意的事”“关心方式”等已写明内容优先于通用标签，最多提取两行，不自动补造人物经历。
- 每轮继续使用当前人物的称呼、口癖、样本、立场与边界，历史回复不能变成新人设。实际 IndexedDB 连续流程验证了数据库重开、读取此前节奏及编辑人设后下一次请求采用最新配置；没有创建一份可能与人物编辑冲突的缓存人格。
- 新人物生成要求独立的“判断习惯”以及条数、长短不同的情境样本，仍一次生成。旧人物不自动改写；生成与普通回复中的自然程度仍需真实模型验证。

本轮修改普通角色私聊及人物生成链路；助理专用的办事回执和五档人格规则没有改动，结构化操作规划仍隔离于普通聊天表达契约。
