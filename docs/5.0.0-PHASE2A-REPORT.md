## 2. 关键设计决策

1. **手账不隐藏底部导航**：`DiaryPage` 的返回按钮是 `!IS_MOBILE` 才渲染（桌面专用），手账内部没有手机端返回入口；若照搬"推入聊天隐藏导航"，手机用户将无法退出。故选"导航常驻 + 高亮世界"。
2. **手账复用 `activeView === 'diary'`**：桌面端 `App.tsx` / `Sidebar` 一行未改。
3. **不做 Dashboard**（§6）：只有问候、弱化统计、主区域、「我的生活」入口。
4. **空状态文案纪律**：本阶段没有任何生产写入路径，因此**不承诺**"聊聊天就会留下痕迹"；等 2b-0 接线后再升级为 §7 的原始文案。

## 5. 写入路径规格（审核要求：明确"由哪些用户明确授权的动作写入世界事件"）

**总原则**：只有**用户可感知、可撤销的明确动作**，或**已经存在的用户授权链路**才写入世界层；
LLM 只负责把自然语言变成候选，**由程序校验后落库**（§31/§37）；不新增任何后台/自动 LLM 调用。

| 阶段 | 用户明确授权的动作 | 写入内容 | 新增 LLM 调用 |
|---|---|---|---|
| **2b-0**（最小闭环，优先） | 每 5 条用户消息的既有结算（**4.x 已有**：`settle → recordLifeEvent`） | 把新产生的 `LifeEvent` 同步派生为 `worldEvent`（interaction / relationship / goal→continuity）；**按重要性过滤**：只写"关系变化"与"明确约定"，普通互动按阈值聚合，避免年表被冲淡 | **否**（复用既有结算） |
| **2b-1** | 聊天中明确出现的约定/计划/话题/分歧/提醒（**4.x 已有**：`context-consolidator` 顺带产出） | `worldEvent(type='continuity', sourceType='continuity', sourceId=thread.id)` + 该角色 `knowledge`；完成/收起/重新挂起时**同步同一条事件的 `resolved`**（确定性 id ⇒ 幂等更新，不产生重复） | **否**（复用同一次结算） |
| **2b-1** | 手动「添加一件事」/「已完成」/「稍后再说」 | 同上 | 否 |
| **2b-2** | 长按某条消息 →「收藏为共同记忆」（新增入口，仅此一处） | `sharedMemory(participants=[用户,该角色], visibility='selected', visibleTo=[该角色])` + `worldEvent(type='shared_memory')` + 该角色 `knowledge` | 否 |
| **2b-2** | 长按 →「记住」（**已有**） | 只写 `MemoryItem`（用户事实）——**不进世界层**，两者分工不混 | 否 |
| **2b-3** | 日记条目 →「告诉某个角色」 | `diary.visibility='selected'` + `visibleTo=[该角色]` + `worldEvent(type='reality')` + 该角色 `knowledge` | 否 |
| **2b-3** | 日记条目 →「加入共同世界」 | `diary.visibility='world'` + `worldEvent(type='reality', visibility='world')` | 否 |
| **2b-3** | 日记条目 →「仅自己可见」（默认） | **不写世界层** | 否 |
| **2b-4** | 关系网络里添加「人物共同事件」（**已有 UI**） | `sharedStoryEvent`（已有）+ `worldEvent(type='relationship')` + `relationshipEvent` | 否 |
| **3-x** | 完成一场 World Stage | `worldEvent(type='stage')` + `worldEvent(type='life_trace')` + `sharedMemories` + `relationshipEvents` + `knowledge` 变化 + `continuity` 变化 | **是（每场一次结算调用）** |
| **3-x** | 场景中的关键选择 | 先记 `worldSceneEntries`；后果在场景结算时统一落库 | 否（复用同一次） |

**明确不做**：普通闲聊逐条写世界事件；后台自动生成；让 LLM 直接决定数据库真相；为写世界层新增任何后台调用。

**闭环判定口径（2b 完成时必须能通过）**：
新用户 → 与某角色聊 ≥5 条 → 世界页出现 ≥1 条真实事件；完成一件未完成的事 → 该条事件 `resolved` 变 true 且不产生重复行；
把一条日记「告诉某角色」→ 世界页出现 `reality` 事件，且**其他角色仍然看不到**（`knowledge` 只给该角色）。

## 6. R6 的处置（为什么本轮不改行为）

现状：`ChatWindow.tsx:611` 在全局开关打开时，把最近日记**注入每一个角色**的上下文。
- 这与 5.0 的逐条可见性（`Diary.visibility / visibleTo`）**不是一回事**，绝不能作为新的世界可见性机制。
- **本轮不改行为的原因**：Phase 1 已把所有既有日记置为 `private`，而"逐条授权"的 UI 要到 Phase 6 才存在。
  若现在就把注入改为"仅注入用户显式分享过的条目"，用户会看到一个**开着却毫无效果**的开关，属于制造"假坏"体验。
- 本轮动作：在注入点写入醒目的 R6 约束注释（说明它不是 5.0 可见性机制、Phase 6 必须替换或删除）。
- Phase 6 替换方案（已定）：删除全局注入 → 改为 §5 的"日记条目 → 告诉某个角色 / 加入共同世界"，
  角色只读取 `listVisibleFor(characterId)` 的结果；开关本身在设置页移除或降级为"新建日记的默认可见性偏好"。
- 若你希望**现在就**严格化（宁可让该开关短期无效），我可以在 2b 一并做——请明确指示。
