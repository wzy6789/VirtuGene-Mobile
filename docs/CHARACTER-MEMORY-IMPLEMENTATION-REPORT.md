# 跨场景角色记忆改造实施报告

## 结果

统一记忆方案已落入代码：原始聊天、日记、待办、朋友圈和星域数据仍由各自数据表作为事实来源；新增的记忆账本保存来源引用、修订、角色知情与使用记录，用于跨场景召回、撤权和溯源，不复制一份可脱离来源权限的私密正文。

## 实施内容

- Dexie v25 新增记忆主张、证据、角色知情关系、持久化提取任务、使用记录与来源失效标记，并为旧 `MemoryItem` 迁移来源和生命周期信息。
- 用户发言与提取任务同事务保存。任务只带消息 ID、版本、区间、会话和发言时的听众快照；后台按相同会话与听众批处理，失败采用退避重试，支持在记忆归档界面查看失败任务并重试。
- 私聊、群聊、朋友圈、日记、待办、星域回忆继续使用各自真实数据和权限规则。群聊记忆按发言时的 `witnessedBy` 限制；晚加入成员、未看过的动态、私密日记、未授权待办、未亲历或已撤回的星域内容不会因账本索引而自动变成角色记忆。
- 编辑、删除、撤回或变更授权会取消旧版提取任务或写来源失效标记；读取每轮重新核验来源、当前权限和修订。推理期间源内容变化时丢弃这批结果，避免旧摘要复活。
- 只有完整进入本轮提示词的来源才记为“实际用过”；截断、遗漏或未打开的内容不记使用溯源。来源正文不会被复制到统一账本。
- 记忆整理在后台进行，不挡住聊天请求；该后台任务会调用用户当前配置的模型，因此可能增加模型调用。召回与权限核验本身不增加模型调用。

- `tsc --noEmit`：通过。
- `vite build`：通过；仍有仓库既有的 bundle 体积和动态导入提示。
- `scripts/verify/character-memory.mjs`：真实浏览器与 IndexedDB，98 项断言全通过，无真实模型网络。
- 全量回归在重建验收 bundle 后首轮为 15/22；修正 `worldF` 长场景测试缺失的参与者快照后，该套单独复验通过（28 项）。合并后的当前结果为 16/22 通过、6 套未通过（64 条断言）。通过项包含 Phase 1（83）、2b-3（45）、2b-4（86）、2b-5（48）、2b-6（30）、3b（35）、worldA/B/C/D/E/F、记忆账本（98）、worldG、朋友圈（39）与主动朋友圈（13）。朋友圈日记权限套件将后台提取模型边界替换为固定响应，保留其网络归因测试有效。

- `git diff --check`：通过；仅有仓库的 LF/CRLF 提示。

## 明确边界

- 模型提取仍是概率性整理，不能保证从每句话里抽出所有事实；未抽取的原始对话仍留在原表，近期窗口和既有摘要可继续召回。超长历史不是无限原文搜索保证。
- 没有 `witnessedBy` 快照的旧群消息按保守策略不推断新听众；不会伪造历史在场关系。
- 撤权阻止后续召回，不会改写已经发送给模型或已经显示过的历史回复。
- 本次未构建 APK、未发布，也未替代 Android 真机长对话测试。
