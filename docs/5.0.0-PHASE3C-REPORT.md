## 1. 现在一场戏有节奏了

```
开一场戏（0 次调用）
  第一幕 ── 每个动作 1 次调用 → 旁白/对白（偶尔给出岔路口）
        │   · 你点选项 ⇒ 记下"你选了什么"，并且这一选择成为下一拍的输入
        │   · 张力到位 + 本幕够长 ⇒ 本地规则翻幕（并写下"—— 第二幕 ——"，张力重新积累）
        │   · 剧情一直平但本幕太长 ⇒ 节奏兜底也翻幕
  第二幕 …（最多 4 幕）
        ↓ 结束这场戏（1 次调用）
   结算把"你们选过的路"一起看进去 → 舞台事件 / 共同记忆 / 关系变化（带原因）/ 未完成事件 / 参与者认知
```

**用户看得见的东西**：舞台顶部的「第二幕」徽标、正文中间的「—— 第二幕 ——」标记、
以及自己选过的那条（显示成"你选的内容"，选项按钮随即消失，不会再被误点）。

## 2. 两条规则（都写成可验收的纯函数）

### 2.1 幕次推进：为什么**不让模型决定**

"现在该进下一幕了吗"是**结构化状态的真相**。让一次生成随口决定，就违反了本项目一直守的那条线
（"LLM 负责演，VirtuGene 负责记"），而且不可解释、不可验收。
所以推进交给 `src/lib/world/scene-acts.ts`（纯函数）：

| 规则 | 条件 | 结果 |
|---|---|---|
| **张力到位** | 本幕正文 ≥ 6 条 **且** 张力 ≥ 0.65 | 翻到下一幕（`reason: 'tension'`） |
| **节奏兜底** | 本幕正文 ≥ 12 条（无论张力） | 翻到下一幕（`reason: 'pace'`）—— 避免永远停在第一幕 |
| **上限** | 已到第 4 幕 | 不再推进（把收尾留给"结束这场戏"） |

- **只统计本幕**的正文（`system` 标记不算）；翻幕后张力归零、重新积累。
- 翻幕本身**0 次调用**，并且**写下一条用户看得见的标记**（不是悄悄改状态）。
- 模型侧只知道"现在是第几幕（最多 4 幕）"，它负责在幕内演好，不负责决定幕次。

### 2.2 选择分支：必须是"真选择"

| 规则 | 说明 |
|---|---|
| 选项 2~3 个 | 只有 1 个选项**不是选择** ⇒ 降级成旁白（绝不出现"假选择"） |
| 去重、去空、截断 | 空/重复/非字符串清掉；清理后不足 2 个仍降级；每个选项 ≤ 60 字 |
| 不替用户写动作 | 提示词里明确要求：给了选项就不要再替用户写 TA 做了什么 |
| 点选后可回看 | 那条选择提示被标记 `meta.chosen`（选项按钮消失），并另记一条 `choice` 条目记录"你当时选了什么" |
| 选择即输入 | 这一选择作为下一拍的 `userAction`，因此**仍然只花 1 次调用** |
| 结算看得见 | 选择条目在正文里，结算调用读的就是这份正文（验收 D 组专门断言） |

## 6. 测试抓到的一个真实缺陷（已修）

**已经选过的选择，仍然把选项显示成可点按钮**。
原因：那条条目的 `meta` 里**同时**有 `options`（当时有哪几条岔路）和 `chosen`（你选了哪个），
而我的渲染条件是"没有 options 才显示已选内容"——于是条件永远不成立，
未被选中的那个选项一直留在屏幕上（而且还能再点一次）。

验收 C② 直接抓到了它（`!text.includes('直接推门进去')` 失败）。修复：**先判断 `chosen`**，
只要选过就只显示"你选的内容"；`options` 保留在数据里只是为了"回看当时有哪些岔路"。

另外两处是我自己测试写错：
1. **忘了给"点选项"那一轮排队响应**，于是走了 jsonMode 降级重试（多 1 次调用）——这条路径本身是既有行为（Phase 3 的 E 组专门测过）。
2. **翻幕的计数算错**：我按"每轮 2 条"估算，但 `user_input`/`choice` **也算本幕正文**，实际每轮加 3 条，
   于是铺垫轮就触发了"节奏兜底翻幕"。产品是对的（规则就是那样），现在断言按**真实计数**写，
   并在失败详情里打印 `{act, tension, entries}` 便于下次一眼定位。

## 7. 已知限制

| # | 项 | 说明 |
|---|---|---|
| L1 | 幕次规则是固定阈值（6 条 / 0.65 / 12 条 / 4 幕） | 数值是我定的初始值，未做真机调优；规则与阈值都集中在一个纯函数文件里，改起来是一行 |
| L2 | 选择是"二选一/三选一"，没有分支记忆 | 选择被记进正文（结算能看到），但**没有"选了 A 之后世界永久分叉"**这种分支状态；世界层是线性年表 |
| L3 | 没有"回到某个选择重来" | 舞台是"真的发生过"的记录，因此没有回溯重演；如果你要"重演"，那需要另立一套与"真实经历"分开的机制 |
| L4 | 模型可能给太多选择 | 提示词要求"偶尔给"，但没有硬性节流（例如"每幕最多 1 次"）。若真机发现岔路太密，可以加"本幕已给过选择就不再给"的本地闸门 |
| L5 | 幕次标记不参与结算 | `system` 条目不进结算正文（结算只读旁白/对白/用户输入/选择）；这是有意的，避免"第几幕"这种元信息被当成剧情 |
| L6 | baseline 之后 12 个阶段仍未提交 git | 强烈建议尽快落一次提交 |
