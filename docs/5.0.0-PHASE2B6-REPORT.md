> **阶段**：Phase 2b-6 — R7 裁定与落地（你要求"先裁定 R7，再进 Phase 3"）
> **状态**：完成，**已停止**（Phase 3 世界舞台未开始）

> **范围纪律**：不改 4.x 好感度与结算公式、不改世界事件/认知/记忆的任何写入、不动 Prompt；
> 本阶段只是**删除第二个数值来源**并把这条裁定结构化。

---

## 1. 裁定内容（一句话）

> **"用户 ↔ 角色 的好感度"只有 `CharacterState.affinity` 一个来源**（4.x 既有结算写入、无上限语义）。
> 世界层**不再保存**好感度；它只负责 4.x 根本没有的四个分面
> （信任 `trust` / 依赖 `dependency` / 摩擦 `conflict` / 熟悉 `familiarity`），
> 并且这四个分面**只能通过带原因的事件（`applyEvent`）变化**——
> 数值变了就一定有可读的原因，这正是"关系网络可解释化"的前提。

---

## 2. 为什么这样裁定（对比三种做法）

| 方案 | 问题 |
|---|---|
| 世界层继续存 `affinity`，与 4.x 各自写入 | **两套数值必然漂移**（4.x 还会因 bump/里程碑/清理等路径变化），并且"关系页显示哪个"没有答案 |
| 世界层存 `affinity`，但只由迁移抄一次快照（**改动前的实际状态**） | 快照**立即过时**：迁移那天是 85，之后涨到 120，世界层还写着 85。任何读它的地方都会拿到错数字 |
| **世界层不存 `affinity`（本裁定）** | 数值只有一份，读的地方只有一处；世界层仍能表达"信任/依赖/摩擦/熟悉"这些 4.x 没有的维度 |

另外一条配套约束：**分面变化必须带原因**。如果允许 `overrideFacets` 悄悄改数值，
关系网络页就会出现"关系变了但说不出为什么"的黑箱；因此本阶段把"未知分面（含 `affinity`）"
改成**直接抛错**，而不是静默忽略。

## 5. 必须披露：Phase 1 里两条断言被**有意改写**（契约变更）

原来的两条断言编码的是**旧契约**（世界层继承好感度）：

```
- check('用户↔角色 状态存在，affinity 继承 4.x 好感度 85', meX.affinity === 85)
- check('状态行同时也是无上限语义（不夹到 100）', meX.affinity === 85)
```

现在改为**新契约**（并新增两条 R7 收尾断言）：

```
+ check('用户↔角色 状态存在，且**不含好感度字段**（唯一来源是 4.x）', !('affinity' in meX))
+ check('4.x 好感度仍然完好地留在 CharacterState 里（迁移没有动它）', characterStates[C_X].affinity === 85)
+ check('四个世界层分面仍在（0 = 尚无记录）', trust/dependency/conflict/familiarity 全 0)
+ check('R7 收尾：升级后世界层里没有任何好感度字段', …)
+ check('R7 收尾：全新升级没有需要清理的旧快照（该分支由 phase2b6 覆盖）', r1.legacyAffinityStripped === 0)
```

这不是"放宽标准"：旧断言要求世界层保存一个**会过时的副本**（那是缺陷本身），
新断言要求"数值只有一份 + 旧副本被清掉"，并要求 4.x 的值仍然完好（迁移没伤数据）。
**"清理旧快照"这条路径**由 phase2b6 的 B 组覆盖（它先造一条带 `affinity` 的行，再跑迁移断言被剥掉、分面保留）。
Phase 1 是 v15 → v17 的**全新升级**，本来就不存在旧快照，所以那里的 `stripped` 应为 0。
