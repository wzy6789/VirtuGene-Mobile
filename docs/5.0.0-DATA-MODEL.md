# VirtuGene 5.0.0 数据模型（Phase 1 定稿）

> 本文件是 Living World 数据层的**唯一权威说明**。术语、字段、索引、幂等键、迁移语义都以这里为准。
> 日期：2026-09-12 · 对应 Dexie `version(17)`

## 0. 术语表（避免与 4.x 已有名词混淆）

| 概念 | 表 | 一句话定义 | 与 4.x 的关系 |
|---|---|---|---|
| **World** | `worlds` | 一个世界容器；5.0.0 每用户恰好一个默认世界 | 全新（为多世界/平行世界线预留） |
| **WorldEvent** | `worldEvents` | "世界真正发生过什么"的统一记录 | 由 4.x 的生命轨迹 / 未完成事件 / 人物共同事件**派生** |
| **WorldScene** | `worldScenes` | 一场 World Stage（互动章节）+ 结构化状态 | 全新 |
| **WorldSceneEntry** | `worldSceneEntries` | 场景正文（旁白/对白/选择/用户行为） | 全新；**不复用 messages** |
| **CharacterKnowledge** | `characterKnowledge` | 某个角色知道什么 / 能不能说 / 是不是 TA 的秘密 | 全新（§15 认知边界） |
| **SharedMemory** | `sharedMemories` | 用户与角色**真正共同经历**的重要片段 | 全新；与 `memories` 分工，互不迁移 |
| **RelationshipState** | `relationshipStates` | A ↔ B **现在**是什么关系 | 用户↔角色沿用 4.x 好感度数值 |
| **RelationshipEvent** | `relationshipEvents` | 关系**为什么**变成现在这样 | 全新（可解释关系） |

**明确区分（最容易搞混的三组）**
1. `memories`（用户事实，如"用户喜欢猫"） ≠ `sharedMemories`（共同经历，如"我们一起在天台看星星"）
2. `participants`（谁经历了） ≠ `visibleTo`（谁被允许知道）
3. **可见性 ≠ 认知**：进入 `visibleTo` 只代表"允许知道"；角色**真的知道**必须有 `characterKnowledge` 行（§62：用户告诉谁，谁才知道）
4. `relationshipStates`（当前状态） ≠ `relationshipEvents`（变化历史）——关系页读当前状态，**禁止现场累加历史**

## 1. 主体标识（SubjectRef）

```
用户：u:<userId>       例 u:abc123
角色：c:<characterId>  例 c:gu-yue-na
```

- 绝不再用裸字符串 `user`（会与真实 characterId 撞名）
- `pairKey` = 两个 SubjectRef **先排序再** 用 `|` 连接：`c:gu-yue-na|u:abc123`、`c:lin-jian|c:xing-yao`
- 好处：A↔B 与 B↔A 得到同一个键；将来导入/克隆角色也不会串关系

## 2. 幂等键与确定性 id

```
幂等键 = userId + worldId + sourceType + sourceId
id     = stableId(prefix, ...parts) → "<prefix>_<16 位十六进制>"
```

- 派生数据（迁移回填、场景结算写入）一律使用确定性 id ⇒ **重复执行只覆盖同一行**
- 迁移采用"存在即跳过"语义：重复运行不覆盖运行期的新数据（`worldRepo.rerunMigration()` 已验证幂等）
- 多用户 / 多世界 / 导入恢复都不会意外冲突

## 3. 表与索引（Dexie version 17）

| 表 | 索引 |
|---|---|
| `worlds` | `id, userId, isDefault` |
| `worldEvents` | `id, userId, worldId, type, [worldId+timestamp], [worldId+type], [worldId+sourceType+sourceId], sourceType, sourceId, timestamp` |
| `worldScenes` | `id, userId, worldId, status, [worldId+status], updatedAt` |
| `worldSceneEntries` | `id, sceneId, [sceneId+index], index` |
| `characterKnowledge` | `id, userId, worldId, characterId, eventId, [characterId+eventId], [worldId+characterId]` |
| `sharedMemories` | `id, userId, worldId, [worldId+createdAt], sourceType, sourceId, [worldId+sourceType+sourceId], *characterIds` |
| `relationshipStates` | `id, userId, worldId, pairKey, [worldId+pairKey], *subjects` |
| `relationshipEvents` | `id, userId, worldId, pairKey, [worldId+pairKey], *subjects, sourceEventId, createdAt` |

> 注：`version(16)` 已被 4.1.x 的一次索引补充占用（`characterStates: [characterId+userId], userId`），
> 因此 Living World 使用 `version(17)`。**版本号永不重用。**

## 4. 关键字段约定

### WorldEventType（语义必须严格区分）
`reality` 现实生活 · `interaction` 普通有意义互动 · `shared_memory` 共同记忆 · `stage` World Stage ·
`relationship` 关系变化 · `continuity` 未完成的故事 · `knowledge` 认知变化 · `life_trace` 生命痕迹

> 禁止把普通互动或未完成事件标成 `stage`——不是所有互动都是 World Stage。

### visibility 三态（`WorldVisibility`）
| 值 | 含义 | 谁能知道 |
|---|---|---|
| `private` | 只有用户自己 | 任何角色都看不到（**旧日记升级后的默认值**） |
| `selected` | 指定角色 | 只有 `visibleTo` 里列出的角色 |
| `world` | 进入共同世界 | 世界内角色可见 |

### 关系分面
`trust / affinity / dependency / conflict / familiarity`
- `affinity` **与 4.x 好感度同源，保留无上限语义**（可 >100）
- 其余分面 0~100 区间夹取
- `0` 表示"尚无记录 / 中性起点"，不是"关系为零"
- UI 只显示语义等级（陌生/认识/熟悉/亲近/信任/依赖），**不显示数字**（数值用于 Prompt 与剧情条件）

### 秘密（暂时不单独建表）
用 `characterKnowledge` 表达：`isSecret` + `secretOwnerId` + `canMention=false`
已能覆盖：知道 / 不知道 / 只知道一部分 / 知道但不能主动说 / 属于某个角色的秘密。
等需要"秘密传播、泄密、揭穿、谎言、遗忘"时再独立建模。

## 5. 迁移语义（4.x → 5.0）

| 来源 | 产出的世界事件类型 | 其他产出 |
|---|---|---|
| `CharacterState.lifeEvents.interaction` | `interaction` | 认知（参与者角色） |
| `.memory` | `shared_memory` | 认知 |
| `.relationship` | `relationship` | 认知 + 关系变化史 |
| `.goal` | `continuity` | 认知 |
| `continuityThreads` | `continuity`（`resolved = status==='done'`） | 认知 |
| `sharedStoryEvents` | `relationship` | 认知（双方）+ 关系变化史 |
| `diaries` | **不派生** | 仅补 `visibility='private'`、`visibleTo=[]` |
| `memories` | **不迁移** | 保持"用户事实"定位 |
| `sharedMemories` / `worldScenes` | **不回填** | 由运行期产生 |

- 派生事件的 `visibility` 保守取 `selected` + `visibleTo=[相关角色]`：**不擅自让全世界的角色都知道**
- 所有派生行保留 `sourceType` / `sourceId` / `meta`，可回溯到原始 4.x 记录（§60 可追溯）
- 旧数据的数值增量不存在 ⇒ `relationshipEvents.facets = {}`，只留"原因记录"，**不编造数字**
- 旧日记绝不因为 `diarySharedWithCharacters` 曾开启而授权给角色；该开关只影响将来新建日记的默认选项（Phase 6）

## 6. 删除与清理规则

| 触发 | 世界事件 | 共同记忆 | 认知 | 关系（状态+史） | 场景 |
|---|---|---|---|---|---|
| 用户删除某个角色 | **保留历史**，只摘掉该角色的 participants/visibleTo | 保留，摘掉引用 | 随角色删除 | 涉及 TA 的全部删除 | 有正文的保留并摘掉角色；完全空白的 draft 删除 |
| 用户注销账号 | 全删 | 全删 | 全删 | 全删 | 全删（含世界本身） |
| 清空某个世界 | 该世界全删 | 该世界全删 | 该世界全删 | 该世界全删 | 该世界全删 |

理由：世界事件与共同记忆是"事情真的发生过"，不该因为角色被删而抹掉；而认知与关系依附于角色本身，角色没了就无从谈起。

## 7. 常用入口（Repository API 摘要）

```ts
worldRepo.ensureDefaultWorld(userId, username?)   // 取回/创建默认世界
worldRepo.stats(worldId)                          // 世界首页统计（只读、无副作用）
worldRepo.cleanupCharacter(userId, characterId)   // 删角色的世界层清理
worldRepo.clearForUser(userId)                    // 注销
worldRepo.rerunMigration()                        // 补偿重建（幂等）

worldEventRepo.listTimeline(worldId, {limit, before, types})
worldEventRepo.listUnresolved(worldId)            // 「未完成的故事」
worldEventRepo.listVisibleToCharacter(worldId, characterId)

knowledgeRepo.canMention(characterId, eventId)     // TA 能不能提起这件事
knowledgeRepo.listUnaware(characterIds, eventId)   // 谁还不知道（叙事张力）
knowledgeRepo.teach({...})                         // §62 告诉谁，谁才知道

sharedMemoryRepo.listVisibleFor(characterId, worldId)   // 被允许知道的共同记忆
sharedMemoryRepo.listExperiencedWith(characterId, worldId)
sharedMemoryRepo.listRelevant(worldId, characterIds)    // §39 Relevant Memory（不是 All Memory）

relationshipRepo.getStateFor(a, b, worldId)          // 当前关系
relationshipRepo.applyEvent({...})                   // 写变化 + 同事务更新状态（幂等）
relationshipRepo.listEvents(worldId, pairKey)        // 为什么变成现在这样

worldSceneRepo.createScene / appendEntry / listEntries / patchSceneState / finishScene
```

## 8. Phase 1 明确没有做的事

- 没有世界 UI、没有场景 UI、没有修改任何聊天 UI
- 没有新增任何 LLM 调用，没有改任何 Prompt
- 没有开始 World Stage 的 AI 编排（Scene Director 在 Phase 3）
- 没有做动画与素材
- 没有把 `CharacterState.affinity` 迁走（4.x 关系系统保持原样，`relationshipStates` 是并行的世界层）
