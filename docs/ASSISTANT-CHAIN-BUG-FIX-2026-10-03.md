# 助理全链路排查报告整改

## 八项修复

| 报告项 | 修复与验证 |
| --- | --- |
| 1. 每月重复跨年消失 | 删除按月份数字提前拒绝的分支，统一使用起始年月的月份距离计算间隔。覆盖跨年 1–5 月、2/3/12 个月间隔、月末与闰日，真实仓储列表、助理查询、每日整理与提醒重建均读到对应实例。 |
| 2. 创建重复提醒误拒 | 创建与修改复用 `hasFutureTodoReminder`，展开未来实例再检查提醒时间，保留系列原始起点。晚上创建早上七点的每天/每周/每月安排可保存；单次过期安排继续补问，缺重复间隔先补间隔。 |
| 3. 待办页每周星期基准错误 | 以所选到期日期计算星期；先选每周再改日期，保存时仍采用新日期。每月规则也跟随日期。用户未重选规则时保留已有自定义星期、月份日号与间隔。 |
| 4. 失败原因不持久展示 | 规划失败时将安全原因与聊天回执一起保存，聊天监听新增失败回执，收件箱读取同一原因。页面重开后仍显示；修复连接并重试后更新同一回执。恢复中断规划和导入失败记录也保留安全原因。 |
| 5. 引号剥离误伤 | 仅识别明确记录包装，例如 `帮我记一下“提醒我明天交房租”`，且只授权创建待办。来源位于引号内时仍核对外部包装。支持五种成对引号，补问时间后正常接续；第三方引述、解释、否定、无外部指令、嵌套或混合多指令不因此获得权限。 |
| 6. 重复字段定位过严 | 已验证指令范围内，重复出现且与操作字段完全相同的标题/正文/查询值可以定位；多项操作各自使用自己的指令范围。指令依据本身仍必须唯一或有明确位置，不猜测归属，不将不同字段值或日期语义当成相同文字。 |
| 7. 空星期数组变成每天 | 空、缺失或全无效的星期数组统一回退系列起始日星期；保留周间隔。有效的多星期配置保持原样。 |
| 8. 重试恢复无关补问 | 仅当重试项属于该待处理事项，且其状态为等待或暂停时恢复等待。其他已暂停、取消、结束或失效的焦点在提交、执行和恢复期间保持原状态。明确重试匹配的暂停事项仍可继续。 |

失败原因只显示本地固定文案；同步与备份中的任意错误文本会被替换为安全兜底，不直接展示服务商响应、密钥或伪造的成功声明。通知时间检查继续沿用未来一年实例的检查范围；通过检查表示有未来安排，不等于原生通知已调度或用户已收到提醒。
