# VirtuGene 角色记忆系统修复与贯通方案

> 交付对象：实现者。本文是实施规格，不代表相关修复已经完成。范围包括单聊、群聊、朋友圈、日记、待办、星域；保留原有用户数据与现有非流式单聊行为。实施时以当前代码和自动化验收为准，不得用修改测试预期代替修复。

执行要求：按阶段 A→D 连续实施并交付完整结果，不在通过某一阶段后自行宣布整个任务完成。可以自行决定内部函数名和索引形式，但不能降低本文的权限与验收标准；遇到旧数据或模型行为不确定时采用保守权限。不要在未请求时打 APK、推送代码或更新官网。

## 1. 目标与不可妥协的规则

同一角色在不同场景中保持连续经历，但不会知道自己没有见过、没有获准知道的事。每条信息必须区分四个问题：

1. **事实来源**：原文、帖子、日记、待办或星域事件究竟存在哪里、是否仍有效。
2. **获知依据**：角色亲历、亲眼看过、用户明确告诉，还是仅仅目前有权查看。最后一种不能伪装为“我之前看过”。
3. **当前使用权限**：能否放进该角色本轮模型上下文；群聊、评论、星域多人场合还要判断是否可以当众说。
4. **表达时机**：即使有权知道，也只在当前话题相关时自然使用，不能机械复述或每轮重复。

“记忆相通”不等于把全部数据合并成一段提示词。原始表仍是唯一事实来源。统一层只保存来源引用、获知记录、权限和必要元数据；每轮从原表重新核验，再按相关度与预算召回。已发出的历史回复不会因撤回而从聊天记录消失；撤回必须阻止之后的自动召回和派生内容传播。

## 2. 当前基线：先保留已有成果

- 本地 Dexie 数据库保存 sessions/messages/memories、moments 及其图片/浏览/互动、diaries、todos、worldScenes/worldSceneEntries、worldEvents、sharedMemories、characterKnowledge 等。模型调用只接收本轮构建的上下文，不是永久记忆库。
- src/lib/character-memory.ts 已有跨场景召回，能查群聊、世界与朋友圈，做账号校验、部分听众交集、数量/字数预算和来源引用。src/components/chat/ChatWindow.tsx 另行拼装长期记忆、摘要、日记、待办和世界内容；src/store/group-store.ts、src/lib/world/world-context.ts 又各用一套组合。
- 已有正向规则必须保留：用户钉住记忆优先；群消息写入 witnessedBy；日记默认私密；朋友圈删除/屏蔽/可见范围可查询；世界共同记忆与已结算场景有认知闸门；存在只带“此刻状态”的入场模式（其全部历史读取路径还需逐项验收）；图片细节未知时不能猜测。
- docs/CHARACTER-MEMORY-INTEGRATION.md 和 scripts/verify/character-memory.ts 是既有基线，但只覆盖新增召回层，不等于群聊原有摘要、星域画像、日记派生事件等旁路都安全。

## 3. 已确认缺口与优先级

### P0：可能导致错误知情或撤回失效

1. **群聊晚加入**：messageRepo.create 保存当时成员快照，但 group-store 生成回复直接读最近 20 条和整个 session.summary；maybeExtractGroupMemories 又从最近 18 条给当前全部成员提炼。新成员可能收到加入前历史的摘要或衍生记忆。须同时修实时回复、后台主动发言、群聊闲聊、长摘要和提炼，不能只修 character-memory.ts。
2. **日记软删除及编辑**：diaryRepo.softDelete 只写 deletedAt。若该日记此前以 world 级分享，派生 WorldEvent 仍可被世界检索；正文/标题编辑不会刷新事件摘要。日记授权更新跨多表顺序写入，失败可能留下不一致状态。删除、恢复、编辑、改授权都要作为一个受控写入路径处理。
3. **星域旧/撤回事实复活**：world-context.ts 与 scene-runtime.ts 读取每角色最近 18 条 MemoryItem 后直接构建隐藏用户画像，没过滤 status=withdrawn/superseded，也没复核派生来源。这与单聊的有效记忆排序规则不一致。
4. **星域历史回忆的角色闸门**：world-turn.ts 调用 findRelevantHistory 时不传 characterId，结果可能包含非公开事件，并进入结算 transcript。多人场合只能使用在场所有角色共同可知的历史；角色个人回忆应在该角色私有上下文读取，不能放进导演或公共结算输入。
5. **群聊单模型混合上下文**：任何按成员拼在同一个群聊模型请求内的私有资料，即使标着归属，也没有程序级保证模型不会借别人的嘴说出来。公共请求只给全体听众都可知的信息；确需角色私密动机时，对该角色单独生成并做输出检查。

### P1：记忆不连续、不新鲜或无法溯源

6. 待办只在单聊/星域读取未来 30 天未完成项。群聊和朋友圈评论没有受控入口；已完成事项不能作为“我们做到了”被回忆；无日期事项也缺席。要把“当前提醒”和“已发生经历”分开，不要把完成的任务继续当待办催促。
7. 朋友圈“当前有权看”和“真实看过”两种依据在不同召回路径使用不完全一致。直接询问可以查当前可见帖子，但回复不得冒称先前看过。角色点赞/评论、他人帖子评论与图片的可见性要随原帖当前权限复核。
8. 长摘要和提炼的 MemoryItem 多为自由文本。原消息被撤回、纠错或日记改权后，摘要可能继续含旧事实；群聊提炼还缺精确的原消息来源 ID。新增摘要必须绑定来源和覆盖范围；来源变化后失效或安全重建。
9. 新角色“导入聊天记忆”当前会从该账号其他角色记忆挑选摘要，缺乏逐条来源与敏感范围。继续保留用户主动选择导入的功能，但展示范围、默认保守，导入后的记忆不能反向宣称新角色亲历了原会话。
10. Message.contextTrace 有记忆、日记、世界、朋友圈引用，却无 todoId/occurrenceId；群聊、星域和朋友圈也缺统一的真实使用记录。无法可靠回答“角色为什么知道这件事”。

## 4. 统一模型：事实、获知、授权、召回分层

### 4.1 事实层不重写

继续以现有原表为准，不建立第二份私密正文库。新增索引只记录：

- sourceType、sourceId、sourceRevision、userId、createdAt、updatedAt；
- ownerCharacterId（如角色自己生活）、sceneId/groupId（若适用）；
- 内容状态 active/deleted/withdrawn/superseded；
- 是否需要原记录再验证权限。

对可编辑来源使用 revision。编辑、改权、删除必须使旧 revision 的缓存/摘要/索引失效。若既有消息或记忆没有可靠来源，不允许用文字相似度猜测原始权限。

### 4.2 获知层

为每个“角色 × 来源”记录 basis：witnessed（亲历或当时在群里）、viewed（确实看过帖子）、told（用户明确告诉）、authored（角色自己所写）、available（现在可以查阅但未必看过）。保留获知时间和相关消息/场景/浏览记录 ID。

- 群消息的 witnessedBy 是当时事实，晚加入不补写；旧消息缺 witnessedBy 时，AI 召回默认不认定新成员知情。
- 星域按条目发生时的参与者与 enteredAt 记录在场证据；“只带此刻状态”的角色不获知进场前正文。
- 朋友圈作者知道自己发过什么；观看依据来自 momentViews；仅当前可见但未观看的帖子只可在用户明确询问时以“现在能看到”模式提供。
- 日记/待办的 selected 是用户告知授权，不因为角色能打开“世界页”就推定已经亲历。
- 自动生成的故事、点赞和评论只有在真实落库且角色是作者/观众时才算经历，计划中或模型猜测不算。

### 4.3 权限层：一个入口，三种判定

实现统一查询，例如 canAccessSource({userId, characterId, sourceRef, now})、canRecall({speakerId, audienceIds, channel, sourceRef, basis})；所有入口共用：

- **可读**：账号匹配、源存在且有效、当前未被屏蔽/删除/撤回、角色满足该类型规则。
- **可忆**：有亲历/浏览/告知/创作等真实依据；仅“available”在用户明确询问时才可临时查询。
- **可说**：单聊听众是用户；群聊/评论/多人星域的公开信息必须经所有听众交集验证。角色的私人背景可影响其行为，但不能通过一个公共提示词变成可公开复述的秘密。

所有权限均在生成前重新验证；异步模型调用完成、准备落库前，再核查账号、受众、来源 revision。权限读取失败时跳过可选记忆，不放宽闸门。不得把“谁有权看”仅交给提示词要求模型自行遵守。

### 4.4 召回层

统一返回结构化候选：sourceRef、speakerId、basis、visibilityScope、claimType（事实/当事人说法/推测）、confidence、occurredAt、summary、priority、explain。先过滤权限，再按用户当前话题、钉住状态、重要性、新近程度排序；相同事件跨世界事件/共同记忆/聊天摘要只呈现一次。不得截断半条并虚报来源。

“用户明确要求记住”的条目最高优先级，但仍受撤回、纠错、当前说话场合约束。已纠正事实以新事实为准；摘要不能覆盖当前用户明确更正。每轮只取必要数条，避免角色反复提同一意象；用户转换话题时立即转向。

## 5. 各入口具体接线

### 单聊

保留现有短期消息窗口、当前 session.summary、MemoryItem、日记、待办、世界经历、朋友圈的分层优先级。替换分散的权限判断为统一入口；保留角色独享的聊天原话及明确记住的事实。显式追问朋友圈可查当前可见帖，必须区分看过/没看过。待办应区分“将要做”“已经做”“取消了”。本轮真正完整注入的 todoId/occurrenceId 进入 contextTrace。

### 群聊

构建当前成员快照后，历史消息、引用、长摘要、后台主动发言及记忆提炼都按 witnessedBy 过滤。成员变化时旧 session.summary 不得直接复用：可按成员时期重新生成限定摘要，或先禁用旧摘要，保证安全优先。提炼只写给当时见证了所有来源消息的成员，MemoryItem 保存 sourceMessageIds；不允许新成员通过现有群历史间接获得加入前内容。若用户主动分享一条私聊/日记，先在群里产生一条明确可见的分享消息，再把它作为群来源。

### 朋友圈

发帖、浏览、点赞、评论都保留各自原始记录。角色主动评论时，可用自己真实经历和全体目标听众可知的共同事实，但不能把私人日记/待办/私聊塞进公共评论。回复评论需校验被回复的真实父评论及原帖当前权限。删帖/改权/拉黑后，后续生成不得再引用该帖或其评论。删帖不自动抹去作者“确实经历过”的生活事件；若用户要让角色忘记，需单独提供忘记经历的操作和对应清理规则。

### 日记

默认 private；selected 仅指定角色可忆；world 进入共同世界，但“世界事件对谁可见”与“哪位角色被告知原文”要有明确一致的产品语义。编辑标题/正文、软删除、恢复、改权必须同步处理日记本体、认知及派生事件。建议移入回收站即停止所有新召回并撤下派生事件；恢复后默认 private，用户再次确认共享。日记若曾被用户亲口贴到群里，那条群消息是独立事实来源，日记撤权不能假装群消息从未发生；UI 应说明区别。

### 待办

沿用 private/selected，增加独立的“知情依据”。单聊和星域按事项当前状态及具体 occurrence 读取；无日期事项只在相关问题或用户明确要求时出现。群聊若想让多人知道，用户需显式选择群共享或向群发送。完成待办应生成可回忆的“完成经历”，而不继续注入“未做事项”；取消/删除立即停止提醒和未来召回。重复待办按每次发生的日期存证，避免将一次完成误判为全部完成。

### 星域

导演/旁白/公共结算只读公共世界事实和所有在场者共同可知的经历；每个角色的私人记忆只进其独立 Actor 上下文。所有读取 MemoryItem 的画像路径必须过滤 status 并核验来源。找相关往事时，公共回忆取在场者交集；私人回忆单独交给对应角色，不直接拼到结算 transcript。世界事件、场景正文和角色认知仍分开：发生过不等于每个人都知道。

## 6. 数据迁移与防复活

1. 新字段/索引以增量、幂等迁移加入，不删现有用户表、不清空消息。先备份迁移夹具并核对旧主键、行数和内容。
2. 有 sourceSessionId/sourceMessageIds、sceneId、momentId 等可靠依据的旧记忆建立引用；无可靠依据的条目仅保留原 characterId 的一对一范围，不能自动扩大到群或世界。
3. 旧群消息没有 witnessedBy 时，不能伪造在场；旧群摘要无法证明所有现成员都见证时，AI 端停用并按安全来源重建。
4. 为被删除/撤回/纠正来源留下仅含 ID、版本和状态的 tombstone，避免旧备份或迟到后台任务把授权重新写活；导入时先解决版本冲突，再重建索引。不要把 tombstone 当作模型可读正文。
5. 日记与世界派生事件、认知的写入放在同一受控事务或保证失败回滚；事务外调用模型/通知必须在提交后执行。任何半成品都不能进入召回。
6. 为已完成历史回复保留来源 ID 审计；撤权后查看依据时只显示“来源已撤回”，不再次展示私密原文。

## 7. 实施顺序与每阶段交付

### 阶段 A：封闭 P0（先于新增功能）

修群聊晚加入、群摘要与提炼；修日记软删除/编辑/授权事务；修星域画像 status 与历史回忆权限。先写能复现缺陷的真实 IndexedDB 验收，再改产品代码，确保旧测试仍绿。此阶段不重做 UI。

### 阶段 B：统一权限与来源

定义 sourceRef、basis、可读/可忆/可说判定；把现有 character-memory 与日记、待办、世界召回改成统一入口。提供调用日志或测试可读取的“入选/拒绝原因”，但不向普通用户暴露内部提示词。

### 阶段 C：六类来源贯通

按单聊→群聊→朋友圈→日记/待办→星域逐入口替换旁路。每改一个入口，验证“相关时能记得”和“没权限时绝不出现”两种方向。摘要和衍生记忆接上来源版本失效机制；新增待办与跨场景 trace。

### 阶段 D：迁移、性能、真机

跑旧版本升级、备份恢复、跨账号和大量历史数据。限定每轮本地查询数量、候选量及提示词预算；统一记忆不能显著拖慢发送。用真机测试断网、本地数据多、成员临时变动、应用切后台后的迟到任务。

每阶段提交：改动文件列表、权限矩阵、自动化测试结果、两段真实提示词捕获（获准与拒绝案例，私密内容打码）、已知限制。不得仅以 tsc/vite build 成功或模型回复“看起来正常”作为验收。

## 8. 必须覆盖的验收矩阵

使用真实浏览器、真实 IndexedDB、真实业务入口；只在 LLM 网络边界打桩，捕获实际送出的 systemPrompt 和消息，并统计不该发生的网络请求。每组同时断言 DB 状态、提示词、生成后写入和账号隔离。

1. **单聊连续性**：用户告诉 A 一件事→A 后续单聊/单人星域可用；B 不知情；A 的钉住记忆在长会话压缩后仍在。
2. **群聊晚加入**：A/B 聊旧事→C 加入→C 的回复、群主动发言、群摘要、群提炼均没有旧事；C 加入后的消息可被 C 记住；C 退出后新消息不再归 C。
3. **私密与当众说**：A 私聊知道秘密，A 在群里可保持性格但不能将秘密交给群模型公共上下文；用户明确分享到群后，群内成员才有群消息依据。
4. **朋友圈全链**：发帖→实际浏览→点赞/评论/回复→对应角色能说清真实互动；仅当前可见而未浏览的帖只能说“现在能看到”；图片未知不编细节；改权/屏蔽/删帖后下一轮零引用。
5. **日记撤回**：private 全入口不可见；selected 仅 A；改 A→B 后 A 下轮失去、B 获得；world 派生事件可见范围正确；编辑同步；移入回收站立即撤下派生事件；恢复默认私密；失败注入点不得留下半套授权。
6. **待办生命周期**：无日期、未来、重复、完成、取消、删除各状态；只给被选角色；完成后角色可回忆结果但不会继续催办；重复事项只标记对应 occurrence 完成；本轮 trace 指向准确事项。
7. **星域认知**：角色只记得亲历和获授权内容；晚入场不知进场前片段；已撤回/被纠正记忆不进画像、导演、Actor 或结算；私有往事不出现在公共回忆区。
8. **纠错与备份**：用户纠正一条事实后旧句在所有入口消失；长期摘要不复活；导出/导入后权限、删除状态和见证时间不倒退；两个账号数据永不交叉。
9. **性能与表达**：大数据量下仍能及时显示用户消息、完成本地召回；模型不因统一层额外调用多次；同一记忆不会在同一 prompt 出现多份，连续聊天不会机械重复提起。

完成定义：以上每项都有自动化断言；既有 scripts/verify/character-memory.ts、朋友圈、日记、世界、迁移套件全部回归通过；Android 真机至少手测群成员变化、日记撤回、朋友圈改权和星域回忆四条路径。未经这些验证，不宣称“所有记忆已经相通且安全”。
