# 开心场景、选择邀请与生成模式扩展验证

## 范围与发现

艾莉进行完整六轮：考试通过 → 鼓掌 → 有点空 → 不分析、放一天假 → 书店还是电影 → 用户选电影。官方人物、主动性 0.5、实际私聊发送和 IndexedDB，模型 deepseek-flash；摘要/结算/提取使用替身，上游非流式，每次最多输出 500 tokens。

默认思考和直接生成各做六次真实调用。两组都能庆祝、跟随放假和接用户选择，但仍将“空”解释成长期紧绷后的状态、自动建议休息，并给出泛化的放假处理办法。直接模式不再像上一轮夏晚星道歉场景那么短；它仍有长段比喻和心理解释。因此“小样本直接生成更好”不能推广为全局结论，软件默认模式没有改变。

同时核对第五轮实际模型输入：没有问号的“你说去书店还是在家看电影”被记录成普通交流并走换题提示，没有明确的看法邀请。本轮解决了这个本地识别缺口。

## 生产改动

- 识别以“你说、你觉得、你会选、你更喜欢、你想选、你选”询问两项选择的日常说法，不要求问号。
- 允许引号包裹选项名称；引用完整请求、转述、假设、否定以及“都行、都可以”等许可表达不当成当前选择问题。
- 明确实际帮忙的请求仍优先，不把写方案或修改内容变成单纯表达偏好。
- 选择邀请使用一份具体引导，替代同位置泛化的看法指令：说自己的偏好和喜欢的理由，不替用户评选正确答案、不分析用户状态、不替用户安排放假。用户另选一项无需角色批准。
- 不改写原消息、不授权应用操作、不增加模型规划或重试次数；原有倾听偏好不被永久重置，明确选择仍可得到回答。

## 可复用的固定前缀验证

chat-scene-live.mjs 新增 replay-first-four：只读取相同人物、场景、生成模式的 R1 真实结果；核对原流程完成、每轮只有一条正常结束的真实原始回复、人物源完全一致、四条输入完全一致，再走实际发送/落库建立相同前缀。已保存结果不覆盖，发现前缀意外付费调用即停止。

回放不算新真实模型输出；其测试数据库费用字段因无新 usage 可能记为未知，不能拿来计费。实际本轮费用以代理 USAGE 文件为准。后续两轮的历史随新回复变化，不能宣称全部请求除一个参数外完全相同。
