# 记忆系统专项审查 · 2026-09-26

## 结论

当前系统**还不能满足“同一个角色在所有模式拥有一致记忆，别的角色不会自动共享”的标准**。本轮没有修改生产逻辑，而是增加隔离复现：17 条检查中，6 条对照通过、11 条要求未通过，归为下面 9 类问题。没有 HARNESS_ERROR 或超时。

测试采用独立浏览器配置与 IndexedDB、假角色、假 API 返回；私聊的关键检查实际挂载 ChatWindow、输入并发送消息、捕获真正提交的 systemPrompt。没有访问真实模型，没有改用户聊天记录。它证明的是数据与提示词管线的问题，不是对真实模型回答质量的评测。

## 现在的记忆实际在哪里

| 层级 | 存储 / 入口 | 实际作用 |
| --- | --- | --- |
| 原始经历 | messages / sessions；worldSceneEntries / worldScenes；moments / momentViews / momentReactions；diaries；待办相关记录 | 保留原文、作者、参与者、授权及行为记录 |
| 提炼记忆 | memories，session.summary | 从原文提炼事实及压缩长对话；摘要不是独立真实来源 |
| 世界与知情记录 | worldEvents、sharedMemories、characterKnowledge | 记录事件、共同经历及角色知情范围 |
| 证据档案 | memoryClaims / memoryEvidence / memoryKnowledge / memorySourceTombstones | 记录事实、证据、知情与撤回；尚不能保证与所有原文召回路径一致 |
| 统一检索 | src/lib/character-memory.ts | 汇总各来源并按当前话题分配上下文 |
| 最终模型输入 | ChatWindow、群聊调用、world-context 等 | 仍各有补充和过滤逻辑，因此“统一服务查到了”不等于“角色真正看到了” |

主要问题不只是存储分散，而是**权限、来源失效、最终提示词组装还没有使用同一份契约**。

## 已复现的问题与整改

### 1. 高：新加入星域的角色能读入场前的他人对话

位置：src/db/world-scene-repo.ts:65，participantReadsEntry。

复现：只有 A 在场时用户说一条秘密；之后 B 以默认 memory 模式加入。B 的统一记忆结果包含那条入场前原话。

原因：memory 模式直接返回 true，不检查 witnessedBy 或入场区间。“带上自己的记忆”实际同时打开了这场星域的旧正文。这两个权限不应该等同。

修复：分离“携带自身记忆”与“获知本场历史”；正文默认按 witnessedBy / 历史在场区间授权。只有显式分享某条历史给 B 才增加 B 的知情记录。旧记录缺少快照时，使用可证明的参与区间，不能默认向新成员放开全部。

验收：B 加入后不知旧秘密；B 加入后的对话可知；明确分享之后可知；A 自己仍可回忆旧秘密。

### 2. 中：离开星域时，自己的历史记忆入口也被删除

位置：src/db/world-scene-repo.ts:147、229；场景召回使用当前成员集合。

复现：A 听到秘密后离开星域，同一角色显式追问旧事，统一检索不再返回原话。

原因：removeParticipant 同时删除 characterIds 和 state.participants，而历史搜索依赖这些字段。代码注释说认知与历史不受影响，但查询路径没有兑现。

修复：当前在场与历史亲历分开存。离开关闭一个在场区间，不删除历史见证者；重新加入建立新区间。历史召回按原条目的见证与授权判断，不按“现在是否还在场”。

验收：A 离开后记得自己经历；离开期间新发生的内容不能知道；重返后不会填补离场期间的空白。群聊退出路径也应按此标准补充审查。

### 3. 中：已结束星域的细节在统一服务里存在，却被私聊丢掉

位置：src/components/chat/ChatWindow.tsx:988、1009；src/lib/character-memory.ts:276。

复现：用户在星域说要去“商场东门”，结算摘要仅保留“聊了一会儿”。统一服务能返回目的地原话；真实私聊发送“我等下打算去哪里？”时，systemPrompt 没有该原话。

原因：私聊把 world 引用排除，认为独立星域区块会补齐。但独立区块补的是事件摘要与活动场景，不覆盖统一服务召回的最近已结束场景原话。

修复：最终提示词只消费统一服务的已选引用；如果保留专用渲染器，必须按 source + id 去重，不能整类丢弃。每条引用需要得到“已完整注入 / 部分 / 未注入”结果。

验收：活动、暂停、结束、离场四种状态中，同一个角色都能获得自己确实听到的相关细节；未参与角色不能获得。

### 4. 中：旧的已授权日记在不同调用参数下召回不一致

位置：src/lib/character-memory.ts:411–422；ChatWindow.tsx:815、988。

复现：同一旧日记授权给 A，再新增 9 条日记。直接传 worldId 可以查到；传 scene.worldId 查不到。真实私聊追问这条旧日记，提示词也没有正文。

原因：日记知情过滤只使用顶层 p.worldId，私聊实际传 scene.worldId；私聊独立日记区块又只取最近 8 条，再筛取少量记录。

修复：入口一次规范化 effectiveWorldId = worldId ?? scene.worldId；所有日记授权、目录、正文回查使用相同值。旧日记应按话题检索，而非只靠最近 N 条。

验收：两个参数形式结果一致；旧授权日记可查；撤回后立刻不可查；其他角色始终不可查。

### 5. 中：更正留下旧的有效 claim；旧原文还可重新带回错误

位置：src/db/memory-repo.ts:395、482；src/lib/character-history-recall.ts:33。

复现：把提炼记忆中的“住南京”改成“住苏州”，账本中旧南京 claim 仍有效。随后删除该记忆，再追问南京，历史原文检索仍返回旧南京措辞。

原因：更正更新 MemoryItem 并同步新内容，没有撤回旧 claim 的对应证据；墓碑挂在 memory id 上，而旧原文检索不识别这条更正/遗忘规则。

修复：更正需原子停用旧 claim 的本记忆证据，并写 replacement；原文可以留作审计，但模型输入应标明“过去曾这样说，现已纠正为苏州”，不能当当前事实。用户显式选择遗忘时，建立按角色与事实的召回抑制，所有来源回查都执行。

产品口径需区分“删除一条提炼结果”与“让角色忘记此事”。本测试按代码现有承诺“删除后角色不会再想起来”检查；如果仅删除提炼结果，应修改承诺并明确提供真正的遗忘操作。

### 6. 中：摘要请求完成太晚，会重新写回已经失效的内容

位置：src/db/session-repo.ts:48；ChatWindow.tsx:1455、1522。

复现：以消息 revision=1 构造待写摘要，随后修改消息至 revision=2，再调用真实摘要写入函数提交旧摘要及旧 revision，旧内容成功落库。

原因：写入函数保存来源 revision，却不校验其是否仍是当前版本。私聊异步摘要 await 返回后也没有提交前校验。

修复：提交摘要与提炼结果必须在事务中核对 source revision / offsets / 删除状态，并校验会话摘要生成版本。任何依赖变化时拒绝旧结果，重新排队；防止较早请求覆盖较新结果。

验收：编辑、删除、纠正、撤回发生在 AI 请求期间时，旧结果均不可写回。应通过可控制 Promise 的真实异步测试补足；本轮已验证 repository 接受旧版本的缺口，并核对了生产调用路径。

### 7. 中：批量提炼的每条事实错误地绑定整批消息

位置：src/lib/memory-jobs.ts:125–151；src/db/memory-repo.ts:156–197。

复现：批次含“备用手机号”和无关天气寒暄，真实 worker 提炼一个手机号事实，把两条消息都挂为来源。删除手机号原话后，提炼记忆依然 active，因为天气寒暄被当作幸存证据。

修复：提炼返回每条事实的 evidenceSourceIds，验证 id 属于本次批次，并准确绑定支持该事实的原文。模型未提供可靠逐条证据时，按单来源提炼或保守地把批次依赖视为整体，任一必要来源变化即重新核验，不能把任意剩余消息当独立证据。

验收：删除唯一真实来源使事实失效；独立重述事实的来源可保留；无关消息不能撑住事实；摘要整体依赖与事实的独立证据不可混为一谈。

### 8. 中：角色自己发过的朋友圈，被实际私聊过滤掉

位置：ChatWindow.tsx:1009；统一服务的 moment 来源与私聊独立动态区块。

复现：A 发布一条买到绝版诗集的动态。统一服务读到原文；真实私聊问 A 发的诗集动态，systemPrompt 不包含该动态。

原因：私聊整类排除 moment 引用；独立动态区块主要针对用户动态，不能替代角色自己的帖子及互动行为。

修复：统一接入“本人发布、本人看过、本人点赞、本人评论、本人被回复”的来源，按权限和话题排序。本人动作要保留 actor 与 target，不能只传帖子正文，避免把“看见”当“亲历”。

验收：自己的帖子可回忆；问点赞与评论能够读到真实动作；未看过且无授权的他人内容不能借互动目录越权。

### 9. 中：长星域普通追问不回查旧正文，加特定词才会检索

位置：src/lib/world/world-context.ts:214–222；src/lib/character-memory.ts:321。

复现：星域早期说“这盒桂花糕是给你的”，再加入 65 条正文。“桂花糕给谁的？”上下文中没有旧原话；改成“还记得桂花糕给谁的吗？”就出现。

原因：当前场景被 excludeSceneId 排除出 live 部分，又没有传 liveSegments；深层片段检索仅在明确回忆意图或 liveSegments=true 时启动。

修复：当前场景增加轻量话题匹配，普通相关追问也可查较早正文，不依赖“还记得”触发词。近期窗口、早期关键事实和查到的片段统一去重；不需要每次增加 LLM 调用。

验收：同义问法、指代、话题恢复均可获得相关已知原话；无关闲聊不塞满旧事；离场与新加入权限保持一致。

## 修复顺序

1. **权限与失效先行**：1、5、6、7。防止不该知道、已改正或已删除的内容继续作为事实使用。
2. **互通闭环**：2、3、4、8、9。先修检索和最终提示词差异，不应靠扩大 token 或额外生成摘要掩盖断点。
3. **统一最终编译**：每个入口使用同一份规范化角色身份、知情过滤、事实状态、来源列表；每条来源只渲染一次，溯源只记录完整注入的内容。
4. **全入口验收矩阵**：私聊→星域、星域→私聊、群聊→私聊、朋友圈→私聊、日记/待办→各模式，以及各方向的撤回、编辑、退出、重入、旧数据升级。相同角色应一致，其他角色应无新增知情。
