# 存量声音样本、四条分条与验证闭环

本轮延续已经完成的私聊表达契约、标点保留、纯反应条、口癖豁免、emoji 与尾部声音卡，只落实剩余 A/B/C/D。括号动作剥离、单气泡内不换行以及读取实际落库消息的历史策略继续保留。没有新增 `rawContent` 字段。

## A：存量角色声音样本

- `Character.voiceSamples` 是独立、可选、非索引字段，不增加 Dexie 版本，不改原 `systemPrompt`。
- 首次成功回复之后异步调用任务模型，当前聊天不等待补全。下一轮组装上下文时读取数据库缓存；任务尚未结束时继续使用原声音卡。
- 称呼、判断习惯各一行，另有两到三组对话样本，因此实际为 **四到五行**。每行最多 240 字；不完整、带动作描写、代码围栏、自有块标记或明显指令覆盖说明的输出不缓存。
- 使用现有 `taskChat` 和默认任务模型，一次 JSON 生成。网关也透传 JSON、650 token 预算、关闭思考和取消信号。只发送该角色的设定与表达字段，不发送用户聊天原文或生活记录。生成会产生一次正常任务模型用量。
- 缓存修订是来源哈希，按**相等**检查，不比较大小。名字、人设、标签、签名、开场白、口癖或边界改变后旧缓存无效。正在生成的结果另用完整来源快照核对，避免覆盖后来改动。
- 同账号同角色的并发请求合并；失败保留 30 秒冷却，避免每条消息都额外请求。后续聊天可以再试；手动补全不受后台冷却限制。
- 账号切换立即撤销生成。写入前重新核对账号、角色存在、归属、来源和角色类型；删除不会复活，助理和公共预设不自动生成。已有有效缓存不会被迟到任务覆盖。
- 用户人设原本有声音示例时优先使用原文。生成缓存回退包在 `[角色声音样本]…[/角色声音样本]` 内，仅进入声音卡；提供整体剥离工具，不把标记块追加到用户设定。
- 编辑普通角色可点击“补全声音样本”，预览、放弃或采用。采用仍是本地草稿，点击“保存角色”才落库。生成期间编辑来源会使迟到预览失效。主保存按最终字段重新核对修订。
- 同步与备份沿用完整角色对象，保留可选缓存；导入后仍要通过来源与格式校验。同步导入不会触发生成或聊天。

实现：`src/lib/character-voice.ts`、`src/lib/ai/character-voice-generator.ts`、`src/lib/chat/voice-sample-cache.ts`、`src/components/character/VoiceSamplesEditor.tsx`，接入人设编辑页、`chat-humanizer.ts` 和共享角色发送链路。

## B：净化差异率与重试统计

模型传输返回后、动作剥离之前通过一次内存回调捕获原文。共享发送链路用实际已保存的全部气泡计算差异，包括流式和非流式。原文仅在当前请求内参与计算，没有第二份聊天记录。

指标对 JSON `messages`、分条分隔符和空白做格式归一化，保留汉字、emoji、问号和叹号。按 Unicode 字符的编辑距离除以两边较长字符数计算。大段完全不匹配的文本使用标明 `approximate` 的上界，避免平方计算拖慢聊天。

每账号本地最多保存最近 200 条**数字统计**，重开应用仍保留；不保存消息、人设、密钥或模型原文。账号切换后不读取其他账号统计。超过 15% 的实测样本标记 `alert`；没有传输原文回调的替身或桌面代理样本标记 `captured:false`，不计入实测均值与报警。

浏览器 / WebView 调试入口：

```js
window.virtugeneChatQuality.report()
// samples、turns、measuredTurns、alerts、retryTriggers、retryRate、averageDifference
window.virtugeneChatQuality.clear() // 仅清除当前账号的数字观测
```

`retryTriggers` 统计共享发送链路的质检重试次数；`retryRate` 是已保存轮次中触发质检重试的比例，不冒称供应商网络恢复重试率或全部请求失败率。统计窗口是最近 200 个保存轮次，不是账号终生总数。合法的括号动作剥离也可能超过 15%，报警意味着需要人工观察，不自动改变清洗或历史策略。

## C：四条分条与超限合并

共享契约、默认分条、流式 ID 数量和最终批次保存统一为最多四条。保持原总等待预算 3500ms。

**完整缓冲回复**超限时反复合并相邻组合中总长度最短的一对，相同时选前一对。保留顺序和全部内容，中文不引入空格，英文单词边界必要时保留空格。不能把不相邻的“全场最短两条”抽出来拼接，因为会改变意思的顺序。

**已上屏的 SSE 回复**保留原气泡 ID 与前面三条内容；超出的第五条及以后续入第四条。它是明确的流式稳定性例外：收到后面的文本时，不把已经看过的第二条突然拼入第三条、不重排旧气泡。完整缓冲和流式终稿保存分别使用与显示一致的策略。

新增验证覆盖五条相邻合并、非相邻短条、同长规则、四个流式 ID、第五条迟到、实际四条上屏与落库、批次大小和差异率零损失。

### 暂缓的十五轮实机 / 真实模型对照

按此前用户要求，本轮没有进行实际模型与 Android 完整验收。下面是可执行的观测流程，不能把替身测试当作人味评分。

1. 固定同一角色、人设、主动性、模型及设置。旧角色等样本补全后再开始正式对照。
2. 开始前保存旧版报告作为基线；新版单独调用 `clear()`。十五轮期间不穿插其他角色聊天或助理代发，避免账号级统计混入别的轮次。
3. 轻松、真实倾诉、疲惫、庆祝、关切、设定外提问交替安排，保留同样的话题顺序；不要在用户指令里强迫 emoji、分条或口癖。
4. 每轮记录实际气泡、是否重试以及人工判断；十五轮后保存 `report()` 数字快照。净化报警和 `approximate:true` 样本回到实际聊天人工核对，连续几天观察再决定是否修改历史策略。
