# VirtuGene 5.1.0 Living World · Phase 2 世界脉冲

## 目标

让世界在用户离开应用时仍然拥有连续时间。用户重新进入世界后，VirtuGene 先推进本地世界时钟，再让角色对这段离线时间提出有限、可验证的行动建议。世界事件只在通过本地校验后写入。

## 已完成

- `WorldPulse` 记录一次从旧世界时间到新世界时间的结算，具备 `pending / completed / failed` 状态。
- 进入世界每 15 分钟最多自动触发一次脉冲；用户也可以明确点击“让世界走一步”触发手动脉冲。
- LLM 只负责提出 `move / interaction / wait`，不能指定用户行为、关系数值或角色认知。
- 行动只能引用当前用户的角色和地点；每个角色每次脉冲最多一项行动，最多四项。
- `interaction` 必须满足所有参与者已在同一地点且处于在场状态，隔空相遇会被丢弃并计入 `rejected`。
- `wait` 只更新角色的世界目标/下一意图，不伪造世界事件。
- 通过的移动和相遇写入 `worldEvents`（`sourceType=pulse`、`worldTime`、`locationId`、`pulseId`），并同步当前位置与代理状态。
- 世界页首屏显示世界天数、地点、在场人数、最近脉冲状态和地点状态；脉冲在后台执行，不阻塞首屏交互。
- 同步与加密备份现在包含地点、在场、代理状态和脉冲表，旧备份字段缺失时按空数组兼容。

## 真实性与安全边界

1. 脉冲推进的是本地逻辑时钟，不代表服务器在后台运行；应用关闭期间不会偷偷联网或执行代码。
2. 模型输出解析失败、Key 不可用、超时或违反位置规则时，脉冲标为 `failed` 或完成但无事件，绝不生成占位剧情。
3. 提示词只包含当前用户的世界设定、地点、角色人设摘要、代理状态和世界公开事件；不会读取私聊消息、私密日记或其他用户的数据。
4. 世界事件使用确定性来源键 `pulse:<pulseId>:<index>`，重复处理不会产生重复行。
