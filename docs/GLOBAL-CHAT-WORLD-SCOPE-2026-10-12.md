# 共用记忆的世界归属边界

状态：世界资料跨上下文路径修复；通用扮演身份隔离和全局质量尚未完成。

## 实际证据

world/world-context.ts 为演员构建记忆时已传 scene.worldId，character-memory.ts 将其转为请求 worldId，但此前两个世界读取循环未使用该值，遍历账号下全部世界。角色在平行世界也有 full + canMention 知情行时，另一世界的事件和现场片段能进入当前世界演员上下文。

新增对抗检查先在原代码上实跑，失败为“现代同伴 scoped world excludes parallel-world event and live entry”，记录在 release/global-chat-world-scope-before-2026-10-12.log，不是只根据文本推测。

## 修复

- 有明确 worldId 或 scene.worldId 的读取先验证世界存在、账号归属和范围一致；无效范围返回空，不回退全账号资料。
- 世界事件、历史片段、共同经历和结构化目录沿同一世界筛选，不给角色姓名写分支。
- 没有 worldId 的旧人物共同事件不被自动归入当前世界；仍保留在数据库及既有无指定世界的私聊读取中，不猜测归属、不重迁移数据。
- 注入记录的来源核验也检查世界归属，避免调用方直接传一条别的世界引用时记录成当前上下文使用过。
- 未指定世界的普通私聊仍沿用此前已获知、已授权的跨世界召回。这是明确的入口差异，不表示跨身份资料隔离已经完成。
