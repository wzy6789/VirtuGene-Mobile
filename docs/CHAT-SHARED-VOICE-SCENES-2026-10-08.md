# 群聊与主动消息的声音样本接续

## 发现与改动

私聊已经向声音样本选择器传入当前用户消息，但共享 `buildCharacterVoiceCard` 没有传入情境，导致群聊和主动问候仍采用跨情境样本集合。默认共享声音卡现在采用日常情境：保留称呼、判断习惯、日常样本，排除没有当前依据的疲惫、亲密等专属样本和反应字段。

群聊 `buildBriefs` 将本轮用户原话传给声音卡；自主群聊没有当前用户消息，采用日常情境。两个私聊主动消息入口仍调用共享声音卡，不把历史用户情绪或人工生成的问候指令当成当前用户情绪。

群聊具体发言角色新增与私聊相同的 `directChatGuidance`，包含限定判断范围、观点邀请和发消息方式。它只使用群里用户消息及这个角色自己的群回复，不读取其他角色的私聊，不进入共享导演请求。现有隐私审查、单消息协议与重试预算保持独立。

## 验证

- `node scripts/verify/chat-expression.mjs`：474 项通过。新增共享声音卡的日常/疲惫选择、主动消息初次与重试请求、群聊发言请求范围与导演隔离检查。模型返回使用替身。
- `node scripts/verify/chat-quality-complete.mjs`：199 项逻辑与模型边界、7 项质量面板 UI 通过。
- TypeScript 类型检查与生产构建通过。构建仍报告已有静态/动态导入和大包警告。
- 本轮没有付费模型调用，也没有增加生产模型调用次数。

## 未证明的部分

样本筛选仍采用已有本地情境识别，无法保证所有复杂多意图表达都判定正确。完整人设正文保留，正文已有的全部样本没有被删改；本次修复针对额外声音卡的情境权重。限定判断提示已经接线，但不能证明真实模型必然遵守。群聊与主动消息的自然程度、角色辨识度需要真实输出对照，不能以本地绿灯宣称达到近真人目标。
