# 连续小测与生产注意力逻辑对齐

整体人味目标仍未完成。本轮没有真实模型调用，修复的是连续小测与生产提示之间的差异，以及小测暴露的两处实际表达控制缺陷。

## 小测原有差异

`runExpressionEvaluation` 原先只使用角色正文、历史消息和隐藏节奏，没有生产会话中保存的回复方式与话题状态。因而刚修好的“先听、少问、改口”逻辑不会在设置里的连续小测中得到验证；最近分条回复也没有按轮进入节奏提示。

现在每个被测角色拥有独立、仅在内存中的注意力状态。请求前调用同一个 `updateChatConversationState`，使用共享 `compileChatContext` 将注意力置于人物声音卡之前；成功后更新状态，记录本轮状态快照，并将清洗后的分条按轮用于后续节奏指导。失败、空回复或截断不会推进成功状态，仍立即停止后续调用。

小测仍不读取用户实际会话或生活记录、不写数据库、不自动重试。它只对齐了共享注意力、声音和编译部分，不能称为完整生产链路验收：生活记忆检索、数据库恢复、原生提醒和流式 UI 仍需要独立验证。报告中的 attention 来自此次小测的合成输入，而不是用户真实历史。

## 小测暴露并修复的实际问题

- “行，明天再弄，晚安啦”原先没有进入短收尾。现在只允许一个简短延后子句加独立告别；“明天三点开会，晚安”“明天再弄之前帮我看看开头”等带新事实或请求的句子仍不会被吞成告别。
- 固定澄清轨迹里的“别给我讲怎么处理，我就是想吐槽一下”没有保存为倾听偏好。生产偏好提取现在覆盖这一明确拒绝方案的表达，使之后的澄清仍收到先听提示。

## 验证

聊天表达 452 项通过。质量完整链路 199 项、真实质量面板 UI 7 项通过；模型边界使用替身，付费调用为零。

新增断言覆盖注意力在六轮中的继承、不同角色独立起步、成功计数、真正收尾、偏好进入下一轮请求、共享编译顺序，以及自然拒绝方案后接续澄清。人工观察重点仍不会传给角色模型；每次输出上限与测试调用预算保持不变。

这些证据证明验证工具现在更接近生产条件，不能证明人物辨识度或真实模型输出已达标。后续真实对照必须保留不通过、截断和未知结果，不能挑选好回复当整体结论。
