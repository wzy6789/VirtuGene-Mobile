# 触感反馈 × 共享元素转场 · 技术预研方案

> 状态：审阅修订稿；2026-10-04 已实施应用代码、依赖和 Android 集成，实施及验证结果见 [实施记录](HAPTICS-SOUL-HANDOFF-2026-10-04.md)。
> 核对日期：2026-10-04；依据当前工作区与 Capacitor v8 官方文档、插件源码。
> 目标：补齐触觉反馈与角色头像的空间连续性。
> 设计约束：沿用临界阻尼、无过冲、安静、克制的动效语言；触感只在操作成立或落位时出现。

## 一、审查结论

方案可行，先实施触感基础设施，再接入会话头像正向转场。共享元素的第二条入口与反向路径需要单独设计；图片接力调整为动态缩略图到图片预览。

原稿需要修正的关键点：

| 原判断 | 核对结果与修订 |
| --- | --- |
| 轻反馈映射到 `Haptics.selection()` | v8 没有此方法；应使用 `selectionStart/selectionChanged/selectionEnd`，由封装管理生命周期。 |
| 一次手势最多一次，同时字号尺逐格震动 | 两者冲突。本稿优先遵守一次手势一次：拖动字号时只在有效松手、最终值改变后反馈；逐格模式留作后续可选实验。 |
| 插件没有权限要求 | Android 插件声明 `android.permission.VIBRATE`，需要合并进 Manifest；属于普通权限，无需运行时权限弹窗。不能写成完全没有权限。 |
| 在 ChatInput 中发送成功就震 | ChatInput 的 `onSend` 当前返回 void，点击不代表消息已保存。确认反馈应挂在实际用户消息提交成功处。 |
| 会话头像是 Avatar 组件 | 当前会话行实际分支为 img/span；两支都需标记。Avatar 组件也尚未提供共享元素属性透传。 |
| 角色列表直接打开聊天 | 当前角色行先打开资料 Modal，再从资料页进入聊天；需要给实际提交入口提供可见源元素，不能拿被弹窗遮住的列表头像飞行。 |
| settleFrames 可直接生成 x/y/scale | 当前只输出单轴位移和透明度。应提取同一阻尼进度采样函数，再生成共享元素所需的多通道 Keyframe，保留原调用行为。 |
| 朋友圈封面到动态详情 | 现有封面是展开/收起背景，动态详情是评论弹层，没有对应封面目标。替换为真实存在的“动态图片缩略图 → ImagePreview 当前图片”。 |
| body 挂载 vg-layer-page 即可 | 页面头像可在页面层内处理；资料 Modal 和图片预览需要按实际所在层定位，不能统一放在 Modal 遮罩下面。 |

API 与权限核对来源：[Capacitor Haptics 文档](https://capacitorjs.com/docs/apis/haptics)、[官方 Android Manifest](https://github.com/ionic-team/capacitor-haptics/blob/main/android/src/main/AndroidManifest.xml)、[Android VIBRATE 权限等级](https://developer.android.com/reference/android/Manifest.permission#VIBRATE)、[官方 Android 选择反馈实现](https://github.com/ionic-team/capacitor-haptics/blob/main/android/src/main/java/com/capacitorjs/plugins/haptics/Haptics.java)。

## 二、触感反馈

### 2.1 现状与接入边界

项目使用 Capacitor 8，尚未安装 `@capacitor/haptics`。目前 `VoiceMorphControl` 在录音开始时裸调用 `navigator.vibrate?.(12)`，没有统一偏好、节流和静默策略。

保留现有按压光晕和手势物理，不把触感加入每帧动画，也不加入通用按钮全局监听。反馈只由明确的业务或手势提交点主动请求。

### 2.2 三档语义

| 档位 | 场景 | Native 映射 | Web 降级 |
| --- | --- | --- | --- |
| 呼吸 | 选择成立、开关变化、滑动越过阈值 | 完整选择生命周期内的一次 selectionChanged | vibrate(4) |
| 确认 | 用户消息已提交、长按菜单实际激活 | impact Light；长按可用 Medium | vibrate(10) |
| 共鸣 | 用户明确确认的破坏操作、解锁结果、符合静默策略的里程碑 | notification Success/Warning/Error | 可用短脉冲；初始候选为 [14,40,14] |

数值仅是 Web 初始候选，不代表不同 Android 设备能呈现相同强度。浏览器不支持或拒绝振动时直接静默，界面功能仍然完整。原生与 Web 使用互斥分支，不在一次请求中双重调用。

### 2.3 频率与静默规则

1. 一次 pointer/touch 手势最多请求一次反馈。左滑首次改变预计落点后记录已反馈；随后反复跨阈值不再请求。
2. 字号尺拖动期间不反馈；正常松手且最终值不同于按下时，反馈一次。取消、无值变化、程序定位不反馈。键盘每次有效按键视为一次独立操作。
3. 全局使用单调时间节流，间隔至少 60ms。只即时接纳，拒绝的事件不排队、不延后补震。
4. `hapticsEnabled` 默认 true，独立于减少动效。减少动效关闭视觉动画，仍可保留明确操作的触感。
5. 后台、当前用户的流式回复进行中、自动消息及自动重试不反馈；回到前台不补发之前丢弃的反馈。
6. 发送确认发生在用户消息成功保存后、模型流式输出开始前。生成结束和每个 token 都不反馈。
7. 里程碑若发生在后台或流式静默期间，本轮跳过触感，只保留现有视觉提示；不为庆祝绕过静默策略。
8. 偏好关闭、页面卸载、账号切换、touchcancel 或窗口失焦时清理正在使用的选择生命周期。selectionEnd 属于资源清理，不应被反馈开关拦截。
9. 一次手势若同时触发多个语义，只由最终提交方调用。滑动 Tab 走确认，点按 Tab 走呼吸，不能在共用 switchTab 中再次产生第二次反馈。
10. 60ms 节流限制的是逻辑反馈事件；选择生命周期中的 start/end 不是额外震动事件。

“流式静默”必须使用请求生命周期或显式静默令牌维护。当前 ChatWindow 的 sending 和请求集合属于组件本地状态，没有可供所有触点读取的全局 streaming 布尔值。建议由实际请求拥有者取得/释放静默令牌，计数支持并发请求，释放幂等；不扫描 DOM、不轮询流式文本、不逐 token 更新 React 状态。

如果插件需要异步加载或桥接，真正执行前再次检查偏好、前后台、用户身份与静默条件；过时反馈丢弃。业务操作不等待触感 Promise，异常在封装内消化。

### 2.4 基础设施职责

拟新增 `src/lib/haptics.ts`：

- 对外维持 `breathe()`、`confirm(medium?)`、`resonate(kind)` 三种语义。
- 内部管理 60ms 节流、Native/Web 互斥调用、偏好与静默判断。
- 选择反馈提供受管理的 start/change/end 生命周期。一次性 breathe 也要正确配对；取消与插件拒绝后用 finally 清理。
- 懒加载 Native 插件时共享加载 Promise，检查是否注册；加载失败或不支持设备时静默，不形成未处理的 Promise rejection。
- 不记录聊天内容、PIN、联系人姓名或图片数据。测试统计只使用事件类别和次数。
- 替换录音控件裸 vibrate，不扩大录音权限或改变录音流程。

设置入口仍放在“外观与阅读”的动效组：

> 触感反馈  
> 点按与滑动到位时的轻微震动。

新增偏好使用现有设置 persist，老用户缺少字段时采用 true；备份、导入及默认值归一化也要一并核对。关闭开关后本次关闭操作静默；开启后可给一次轻反馈。设置搜索的静态标签索引随现有流程生成。

实施时选择与当前 Capacitor 8 相容的 Haptics 8.x，并由 lockfile 锁定实际版本。先完成 renderer 构建，再执行 Android 同步，检查合并后的 Manifest 和插件注册；本稿不执行安装、构建或同步命令。官方插件使用 `>=8.0.0` 的 core peer 范围，具体发行版本仍以安装时核验为准。[官方包配置](https://github.com/ionic-team/capacitor-haptics/blob/main/package.json)

### 2.5 触点清单

| 优先级 | 触点 | 挂接点与反馈 | 取消/去重要求 |
| --- | --- | --- | --- |
| 1 | SettingsSwitch | 实际 onChange 后呼吸一次 | 未变化、禁用、程序更新不反馈；注意开关自身关闭反馈的顺序。 |
| 2 | SwipeActionItem | 手势第一次使 projectedOpen 相对起点翻转时呼吸 | 每手势最多一次；记录在 gesture 对象，重复 rAF 不调用。取消不另补反馈。 |
| 3 | Tab 滑动 | usePageSwipe 的提交回调真正执行且导航成立时确认 | 回弹、touchcancel、提交前中断不反馈；排除滑动返回，避免给所有页面返回加震动。 |
| 4 | 底部导航点按 | 用户切到不同一级 Tab 时呼吸 | 相同 Tab 不反馈；区分点击与滑动来源。 |
| 5 | 长按消息菜单 | MessageBubble 菜单由关闭转为打开时确认 Medium | 长按后系统 contextmenu 重复到达不重复反馈；流式消息继续不可打开菜单。 |
| 6 | 字号尺 | FontRuler 正常松手、最终值变化后呼吸 | 不在 landing 渲染或每次 onChange 中调用；键盘只在有效改变值时反馈。 |
| 7 | 用户消息 | ChatWindow 实际保存用户消息后确认 Light | 不放 ChatInput void 回调；失败、被请求锁拒绝、自动重试、自动代发不冒充用户发送反馈。 |
| 8 | 关系里程碑 | 前台且非流式静默时共鸣 Success | 按里程碑事件标识去重，防止 StrictMode/重复挂载双发；不积压过期事件。 |
| 9 | 破坏操作 | 明确确认真实删除/注销时共鸣 Warning | 会话行“删除”目前只是隐藏且保留聊天，不按不可逆删除处理。不要给所有红色按钮统一强反馈。 |
| 10 | 日记 PIN | DiaryLockScreen 得到实际校验结果后 Success/Error | 单次校验一次；关闭、账号变化或旧 Promise 到达时丢弃。 |
| 11 | 语音录音 | 录音实际开始后确认；上滑真正取消时 Warning | starting 转 recording 一次；取消失败或取消尚未成立时不提前宣告。 |

明确不加入反馈：普通页面进出、弹窗开合、滚动、文本输入、骨架屏、流式输出、连续主动消息。

键盘 Enter 发送属于输入路径，不给按键本身反馈；若消息确实保存，由第 7 项统一给提交确认。

## 三、共享元素转场：灵魂接力

### 3.1 范围与协议

首批只处理角色头像。沿用 WAAPI 和现有阻尼采样，不使用整屏 View Transitions，不新增动画库。

源和目标共享稳定标识 `data-soul-key="avatar:{characterId}"`，同时提供角色标识区分：

- source：当前可见、用户实际操作的入口。
- destination：新页面中实际显示的头像。
- ghost：无交互的动画副本，不参与源/目标查询。

查询限定到当前活动页面或明确注册的 Modal；排除 `.vg-motion-snapshot`、离场层、inert 区域和 ghost。同一 key 并不等于任意匹配元素都可作目标。

会话列表的 img/span 两个头像分支都加标记。聊天头部补 32px Avatar；保持返回和菜单的触控区域，先在 320/390/430px、长姓名、助理状态文案下验收布局，不能直接往现有绝对居中标题里塞头像造成遮挡。

Avatar 的标记通过明确的 props/ref 或固定包装元素提供，不引入改变现有 img/span 布局的多余块。

### 3.2 生命周期与导航归属

建议控制器返回可取消的接力句柄，并由移动端导航拥有：

1. **准备**：在任何会卸载源节点或切换身份的提交前，读取可见源的 rect、当前用户和角色 ID。只准备一份头像副本，不复制整行、消息或资料表单。
2. **提交**：导航确认发生后激活接力。异步选角失败、用户换账号或后一次点击覆盖前一次请求时，丢弃旧句柄；不让旧请求把新角色头像带入聊天。
3. **注册目标**：目的头像挂载时用 layout effect/ref 向控制器注册。rAF 仅作短暂补偿；300ms 是寻靶硬超时，不用 React 状态逐帧寻靶。
4. **匹配与几何**：匹配当前用户、角色、导航代次及真实目标节点，计算其最终静止 rect，不能直接使用正在入场位移中的屏幕 rect。
5. **飞行**：使用同一阻尼进度生成 x/y/等比 scale 与透明度，飞行不超过 320ms，仅改变 transform/opacity；落地后恢复真实头像。
6. **退出**：无目标、尺寸不合法、图片未就绪、视口变化或导航取消时，立即恢复真实内容并移除/短淡出 ghost。完整页面继续使用原转场，不等待接力完成。

300ms 寻靶上限与 320ms 飞行上限是两个不同预算，不能把它们宣称为全程 320ms。接力不阻塞页面挂载、点击或返回。如果目标已正常绘制可见，不再晚到隐藏它并启动飞行；优先降级为原页面转场。

当前会话入口会先启动异步 selectCharacter，再立即 openChat；角色资料入口则 await selectCharacter 后再导航。实施时需要携带明确的目标角色和导航代次，不能等到了 openChat 再从可能已变化的 store 或失效的 event.currentTarget 猜源头像。

### 3.3 几何与物理曲线

`settleFrames` 当前把临界阻尼 progress 内联在函数中，输出 x 或 y 的 translate3d。共享元素需要新增“采样进度 → Keyframe”能力：

- 抽取同一归一化进度采样，原 settleFrames 委托给它，旧页面、弹窗和左滑曲线保持原值。
- 固定使用视口坐标系；body 挂载的 ghost 使用 position:fixed，transform-origin:left top。
- 只消除目的页面“入场动画”的临时变换，不误删标题居中的静态 translate。测量方法需显式识别动画拥有者，并与其最终姿态对应。
- Avatar 在 48px 与 32px 之间等比缩放。不同圆角需要先规定视觉策略，避免矩形源落成圆形目标时最后一帧突然跳形。
- 不在飞行中逐帧读 getBoundingClientRect，也不逐帧 setState。
- 内容变化、字体或头像改变、resize、视觉视口 resize/scroll 时取消本次接力，恢复最终头像；不能沿用过期几何。

共享元素反向飞行不是“把 direction 取负”就完成。返回前需捕获当前聊天头像；列表挂载并恢复原滚动位置后再注册目标。若列表重新排序、过滤、隐藏或目标不在视口内，跳过接力，绝不自动把列表滚到该行。

现有页面快照保留离场视觉的 scrollTop，不等于新挂载的真实列表恢复了 scrollTop。若当前返回路径尚无实际列表滚动恢复能力，需要先实现并验证；仅有 restoreSnapshotScroll 不满足反向目标定位。

### 3.4 副本、隐私与清理

头像副本上限建议：源显示尺寸每边不超过 200 CSS px、只允许已知 img/span 或少量安全包装节点，节点数量有独立上限。显示尺寸限制不等于限制图片解码内存；不复制大 data URL 字符串或重新生成位图。

副本需要固定必要的外观角色，避免移到 body 后因失去祖先样式而改变背景、字体或圆角。移除 id、name、role、tabindex、autofocus、contenteditable、共享查询标记及表单/交互属性；设置 inert、aria-hidden 和 pointer-events:none。不复制资料字段或密码节点。

源与目标的可见性由句柄拥有：

- 准备期间不隐去源；导航激活后才隐藏参与接力的真实头像。
- 离场快照中的头像也要遵守副本策略，避免源、页面快照与 ghost 同时出现三份。
- 目标隐藏应发生在其首次绘制前；所有成功、异常与取消路径恢复目标。
- 不能用 visibility:hidden 误伤头像旁的身份文字，或复写与接力无关的原有透明度。
- 一次只保留一个接力；新请求先幂等清理旧请求，不允许旧动画 onfinish 清理新头像。
- 不保留已离开的页面、用户资料或账号外的 DOM 引用。

减少动效启用时整条接力短路；运行期间偏好变化、后台、页面卸载、账号切换、resize、视觉视口变化、重新导航或实际手势接管都取消并清理。

现有 `vg:swipe-handoff` 是页面提交时对手势祖先派发的局部、默认不冒泡事件，本次合法页面切换也会触发。不能简单在 window 监听它，也不能把本次导航的 handoff 当作取消。应由导航代次区分预期交接和后续打断，并明确实际订阅目标。

层级按场景安排：页面头像在页面之上、Modal 遮罩之下；来自资料 Modal 的头像则协调 Modal 离场；图片接力归预览层自身管理。优先使用已有层级，若确需新增角色，再在 theme-tokens 中登记，避免额外的魔法 z-index。

还要核对实际 stacking context：mobile-layout 使用 isolation，通知目前在布局内渲染，Modal 则 portal 到 body。body 内数字较低的 ghost 也可能压住布局中的高层通知。因此宿主选择和层级必须一起设计；验收时同时打开新消息提示、Modal 与接力，确认头像副本不盖住通知或操作控件。

### 3.5 实际路径

| 路径 | 首期策略 | 边界 |
| --- | --- | --- |
| 会话列表 → 聊天 | 48px 行头像到 32px 页头头像 | 相同角色与当前导航代次；缺图、未就绪或源不可见直接降级。 |
| 聊天 → 会话列表 | 返回前捕获，列表真正恢复滚动后寻靶 | 不为接力改变列表排序、搜索或滚动位置。 |
| 角色资料 → 聊天 | 使用资料 Modal 中当前可见的头像 | 角色列表先打开资料；源与 Modal 退场必须协调，关闭但未进入聊天不飞行。 |
| 动态图片 → ImagePreview | 使用该张图片的稳定媒体 ID，不以数组位置作长期身份 | 需处理 object-cover 到 object-contain、真实图片显示 rect、首图 decode 与当前索引；单独验收。 |

朋友圈封面展开仍使用自己的局部过渡。本轮规划不为共享元素新增一个不存在的“封面详情页”。

图片路径不能直接套用 Avatar 的等比圆角方案：长图与横图的裁切、contain 留白和预览手势接管必须单独处理。预览中左右换图或下拉关闭开始时，应取消入场接力并立即交还图片控制权。

## 四、实施顺序与验收

| 阶段 | 内容 | 完成门槛 |
| --- | --- | --- |
| Phase 1 | Haptics 封装、偏好、录音裸调用迁移、触点 1–5 | Native API 生命周期正确；全局节流；单手势去重；点按与滑动不重复；关闭与静默条件生效。 |

| Phase 3b | 实际列表滚动恢复与头像反向接力 | 返回保持原列表位置；过滤/排序/不在视口时安全降级。 |
| Phase 4 | 角色资料入口、动态图片预览接力 | Modal 层级正确；图片裁切连续；新手势能接管；账号变化立即清理。 |

触感与共享元素可以分别验证和上线，但不把真实设备触感验收与浏览器转场验收混在一起。

### 4.1 自动化验证计划

复用现有验证工具，并补针对本功能的实际场景。以下是待执行的验收标准，不是已通过的测试计数。

触感：

- 注入 Native/Web 测试替身，记录实际反馈次数；核对 60ms 节流、互斥分支、插件缺失/异常与无振动浏览器。
- SettingsSwitch 有效变化一次，关闭后零反馈；减少动效启用但触感开关开启时仍可反馈。
- 左滑多次跨阈值只一次；轻微拖动、回弹、touchcancel 不附加反馈；滑动 Tab 被提交前中断时零确认。
- 字号拖动多格仅正常松手一次；取消、相同值、程序定位零次；键盘边界不震。
- 用户消息保存失败、锁拒绝与自动代发零确认；真实保存仅一次，流式输出/完成零反馈。
- 前后台、并发请求静默令牌、账号切换和延迟插件加载无过时反馈；StrictMode 无重复里程碑事件。

共享元素：

- 使用真实会话列表、聊天头部、资料 Modal 和图片预览，检查源/目标 key、最终 rect 与样式；排除快照假目标。
- 320/390/430px、长名字、助理状态、不同列表滚动位置，标题与触控目标不被头像挤压。
- 前进、返回、快速反复导航、异步选角失败/过期、寻靶超时、目标不可见和图片未加载均不留隐藏目标。
- resize、visualViewport、后台、账号变化、减少动效中途启用、手势接管后：ghost、动画、timer、rAF 与监听全部释放。
- 返回不意外滚动列表；飞行期间 React 不逐帧提交；不增加整页快照或聊天历史 DOM 克隆。

实施后按改动范围重跑现有 `run-settings-ui.cjs`、`run-settings-motion.cjs`、`run-touch-fluidity.cjs`、`run-page-motion.cjs`、`run-modal-motion.cjs`、`chat-stream-ui.mjs`，以及 TypeScript 和生产构建。文档修订本身不需要重新运行 App 测试。

### 4.2 真机验收

Android APK 需要重新构建安装；仅 renderer 热更新不能注册新 Native 插件。至少覆盖一台普通 Android 和一台触感能力较强设备，记录实际型号、系统及安装版本。

验收真实力度、60ms 快速操作是否连震、后台/系统设置下是否静默、低性能设备的头像飞行与流式聊天帧时间。浏览器的 vibrate 替身通过不代表 Native 触感可用；截图或主观“高级感”也不能代替帧时间和中断清理检查。
