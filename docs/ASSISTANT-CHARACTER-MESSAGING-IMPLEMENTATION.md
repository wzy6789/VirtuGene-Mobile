# 助理给角色代发消息：首版实现与验证

日期：2026-10-03。

## 本次交付

单个当前账号已添加的普通角色、即时文字消息、真实角色回复，形成完整办理闭环。用户留在助理聊天里，不需要切换角色才能发送。入口位于助理聊天的“更多 → 代发消息”，也可以直接说：

- `给小月发：我今晚晚点回来。`
- `告诉小月我晚上晚点到。`
- `帮我跟小月说一下我明天再来。`
- `给小月发个消息说不用等我。`
- `帮我给小月写一段道歉的话，再发给她。`
- `给小月发消息。` → 补问正文 → 下一句话接续办理。
- `再给她补一句：不用着急。`
- `她回我什么了？`

能够在当前原话中定位正文、角色唯一且授权明确时直接办理。拟稿或用户要求先预览时保留草稿，确认当前版本后才发送。拟稿的收件人和正文可以在卡片里修改；“发送这一版”批准当前展示的内容。同名角色要求用户选择，未知或未添加的角色不会被自动替换成其他对象。

## 本轮连续体验优化

- 卡片增加“保存草稿”，只保存、不发送；允许先保存缺收件人或缺正文的草稿，恢复后按实际缺少字段补充。
- “先放着”同时保存当前收件人和编辑正文；再次打开卡片仍能看到这些内容。暂停中再次保存保持暂停，“继续编辑”恢复办理但不批准发送。
- 未发送时可以说“正文改为：明天见。”“再补一句：你先休息。”或“不是给小月，是给小星。”。改稿与换收件人撤销旧批准，保留当前正文，确认后才发送。明确写进正文的“算了，不用了。”不会被误当取消。
- 缺正文时回答“正文：明天见。”会提取正文，不把字段提示词一起发给角色。
- 回复失败或模型不可用时，“只重试回复”接续原办理项，不新增用户消息。已有部分实际回复时保留原文，不覆盖重做。
- “发出去了吗？”与“她回了吗？”读取真实办理状态，不再次发送或调用模型。
- 尚未选模型时仍能修改正文或收件人；选模型时绑定最终目标与最终正文，模型选择和批准一起保存，不修改原先收件人的会话配置。

本轮在原74项代发检查上增加33项，当前88项数据库/连续流程与19项真实界面检查全部通过，包括保存、暂停时未保存的输入、组件重新打开、空正文禁止发送、自然改稿、收件人纠正、模型选择边界及320px编辑卡片。

助理本人、其他账号角色、未添加的角色模板和群聊不成为收件人。原话正文中的“不要等我”等否定保持为消息数据；外层禁止发送、引用举例和取消不提供发送授权。

## 回复与界面

目标角色使用自己的设定、关系、记忆及会话模型。助理只传话，不冒充目标角色生成回复。角色回复是本次逻辑轮次的真实数据库消息，默认在卡片中展示短摘录，展开可看完整内容，也能打开原聊天。即便同一个角色后来有了更新的聊天，会打开本次代发关联的会话。

目标聊天里的用户气泡标明“由某某代发”，正文保持原样。代发和查看助理回执不会切换当前页面、清除目标未读、生成开场白或推断声线；用户主动打开目标聊天后才沿用普通进入聊天的行为。

卡片分别展示待选角色、待补正文、草稿、待选模型、排队、回复处理中、角色已回复、回复失败、模型连接不可用、中断、暂停及取消。无模型连接时只能说消息已记录、回复未生成。保存了部分实际回复时保留原文与中断标记，不悄悄覆盖或重新生成。

五种性格影响补问和拟稿预览语气，操作状态及角色原话不随性格改变。倾诉或明确转去办理生活事项时暂停未补完整的代发；开始代发也暂停原先等待补充的生活事项，避免短答案写入另一件事。

| `src/lib/secretary/archive.ts` / `src/lib/sync.ts` | 备份恢复清除旧发送批准与执行尝试，不导入可自动生效的代发焦点。 |

首版没有再建立单独的代发表：直接把持久办理数据放在已有 `SecretaryTask.results[].dispatch`，任务 ID 是稳定操作 ID，后续消息的回执引用同一办理项。目标正文与回复继续使用原 `messages` 表。这样收件箱、账号归属、任期、删除及备份处理可以沿用现有记录体系；不复制整段角色历史，也不额外复制目标回复正文。

办理数据包含原请求和后续字段来源的消息版本、目标角色、目标会话、正文来源、拟稿修订、批准修订、用户消息 ID、实际回复 ID、执行尝试和租约。更新回执只批量读取该办理项的关联回执，不扫描所有任务。回复按父消息索引检索，重开恢复不依赖最近 200 条历史窗口。

## 连续性与可靠性

- 未发送时取消或暂停不创建目标消息；暂停后能明确恢复，同一正文继续办理。
- 排队项在目标会话空闲前不进入聊天历史，防止上一轮模型看到下一条消息。
- 正文与办理凭证原子提交；网络请求在数据库事务外。一次提交使用稳定用户消息 ID，失败时只生成这条消息的回复。
- 原请求被编辑、删除、撤回，或目标会话/角色不可用时，校验阻止旧操作及旧模型回复落库。目标资料变化时保留正文，让用户重新核对角色。
- 回调提交再次校验账号、助理任期、来源、目标消息和执行尝试；取消、编辑及更换助理后的迟到结果不能覆盖新状态。
- 已完成的代发不会因为取消用语而删除或撤销真实聊天；停止正在生成的回复保留已提交或实际收到的部分内容。
- 解雇助理停止本地办理，未发送内容保留并作废批准，已发送聊天保留。旧任期不会自动取得新任期的执行资格。
- 重开应用只核对记录并恢复状态；有未到期租约时延后复核，过期后从实际回复恢复。不会自动发送排队草稿或调用模型。
- 恢复备份不会自动发送；未知资料来源继续遵守原有日记锁保护。
- 助理拟稿保留 `composed` 来源，不自动把拟稿里的“记住”或猜测变成永久用户事实；记忆队列与情绪/结算输入排除这类内容。用户亲自编辑的正文保留 `edited` 来源。
- 角色回复只作为交流数据展示，不提供继续代发、发布或修改生活记录的权限。
