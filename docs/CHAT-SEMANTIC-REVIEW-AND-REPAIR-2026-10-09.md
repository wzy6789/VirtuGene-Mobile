# 内容评审与草稿修订校准

日期：2026-10-09。本轮继续目标开发；没有重新打包或发布。

## 代码与范围

- 内容评审改用原回复片段编号，应用从原文提取引文，避免模型重写引文时失败；保留旧引文格式的严格兼容。未知编号、矛盾引文、缺理由、无效类别仍返回未知。
- 将用户原话单独列出，为历史逐项标注 user-statement 或 assistant-unverified。旧角色回复不能作为用户原因、习惯或自身经历的独立证明。
- 区分当下偏好、一般习惯与实体动作，保留短反应、自然玩笑、明确创作及已有来源。
- 新增纯函数草稿修订入口，只有来源引文合法的 revise 结果可以生成修订请求；通过、未知或无效评审不能触发。它仍是诊断工具，未接到生产发送、未增加正常聊天调用。
- 新增八例评审校准工具、按明确样本选择的修订/复查工具。保存原始结果，报告不覆盖；截断、未知结果与问题类别不一致不能算正确。
- 共享聊天契约补充来源规则：自己此前生成的猜想不能证实用户原因、时间或习惯。该原则进入客户端和网关共用契约；尚未以新的一整段生产对话证明其内容效果。

## 修订实验及反例

R1 修订四份草稿，使用思考模式。两份 generation=length，不做后续评审；另外两份完整输出并被复查放行。实际仅 6 次调用，8,808 tokens。

其中习惯草稿把“我一般会找甜的”换成“我找点苹果片这类吧”，是用新的实体动作替换旧习惯；复查仍放行，证明形式去掉“一般”不等于事实问题解决。后续修订与评审明确加入该边界。

R2 限定重测“用户原因”和“角色自身习惯”，关闭思考仅用于诊断修订。两份完整输出，2 次生成 + 2 次复查，5,374 tokens；复查均 pass。

开发侧逐句检查发现原因改稿仍说“刚考完，脑子还没反应过来要干嘛”。用户仅说考试通过和有点空，未提供刚考完的时间、当前认知状态或空落原因；这是用新推测替换旧推测。模型复查 pass 不能证明这份修订合格。习惯改稿不再说自己通常取零食，但仍有泛化身体体验式措辞，未做更大范围验收。

另有输出含字面量 `\\n` 的格式问题，诊断生成不等于实际气泡效果。工具结果只能反映该原始候选与任务协议，没有经生产发送链路验收。

报告：`CHAT-REVIEWED-REPAIR-R1-2026-10-09.json`、`CHAT-REVIEWED-REPAIR-R2-2026-10-09.json`。

## 消耗与验证

- 本轮真实调用 **34 次**，合计 **46,312 tokens**。其中截断仍计入真实消耗，不能算可用输出。
- 使用 `deepseek-flash`。诊断的直接模式不改变正常角色的生产思考设置。
- 每批明确限制调用次数及最多 450 输出额度，代理已全部关闭，无存活测试任务。
- 内容评审协议与修订条件 36 项本地检查通过；聊天表达 787 项通过；类型检查及生产构建通过。

## 当前结论

来源归属和定位机制得到实测校准，能在这批数据上检出之前的漏放，但内容闭环仍未可靠。只按“模型评审通过”替换生产回复会造成新的误导，且可能增加等待与成本。当前诊断工具不作为生产拦截器或自动改稿器。

下一步应使用未参与规则调整的场景校准漏判、误伤与人物表达，并在真实连续发送中验证来源规则；同时比较如何减少角色根本不需要生成的心理解释和新经历，而非仅增加审核步骤。原始近真人、情感自然、人物鲜明的完整目标仍未达到。
