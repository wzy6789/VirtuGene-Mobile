# 6.0.0 评审整改：按需加载与小球产品口径

日期：2026-10-04。已修改正式 App，未调整版本号或宣称通过真机发布门槛。

## P1：真正切断启动依赖

世界首页、沉浸空间、关系/时间线/记忆/设定、角色页、我的页、朋友圈和聊天页改为按需加载。移动端保留消息列表及底部导航；触控按下、悬停或键盘聚焦导航时，提前请求对应页面。不在启动时预下载所有 Tab。

助理执行器保持动态导入，结果卡片、收件箱、每日整理、管理及更多菜单各有独立加载边界。欢迎/聘用弹层只在实际打开时挂载，避免关闭的弹窗提前拉入助理模块。桌面侧栏也不再静态引入入口。

聊天/群聊 store 只在相关动作发生时加载记忆上下文、群聊生成、图像、声线及朋友圈清理。平台 API 门面只在调用时加载各 AI 实现；同步的模型选择独立于网络协议代码，保持 `llm.ts` 的旧导出兼容。没有用 `manualChunks` 把仍然必需的静态依赖改个文件名。

异步加载返回后重新核对账号；后台任务还核对效果生命周期与前台状态。关闭页面或切换 Tab 后，迟到的页面下载不能把用户送回旧页面。保留原来的后台朋友圈任务处理，不因用户尚未配置模型而阻止本地队列处理。

加载反馈放在页面内部，导航及过渡容器继续挂载。实测发现 Chromium 会在当前文档内缓存失败的模块请求：仅创建新的 `React.lazy` 无法恢复。因此模块下载失败明确提供“重新加载应用”；用户恢复连接后主动重载，再进入原页面。已保存的数据仍在 IndexedDB，普通渲染错误提供局部“重新打开”。没有自动刷新并丢弃用户输入。

## 构建与真实首屏口径

单位为十进制 KB/MB；gzip 是本地压缩计算值，不是真机网络传输或解码耗时。

| 范围 | 修改前 | 修改后（约） |
| --- | ---: | ---: |
| 入口 index JS | 1.90 MB / gzip 655 KB | 484 KB / gzip 161 KB |
| 入口及全部静态 JS 依赖 | 2.22 MB / gzip 755 KB | 775 KB / gzip 254 KB |
| 消息首页实际请求 JS，含动态种子初始化 | 约 2.48 MB / gzip 941 KB | 1.035 MB / gzip 440 KB |

修改前实际首页一栏由旧静态依赖和同轮旧种子包相加估算；修改后用禁用 HTTP 缓存的正式构建实际请求集合核验。首屏仍会请求约 260 KB / gzip 186 KB 的种子初始化包；未把它藏在静态口径之外当作“无需下载”。React 和 Dexie 是首屏所需的基础依赖。

验收预算同时覆盖入口（小于 500,000 字节）、静态图（小于 850,000 字节，gzip 小于 280,000 字节）和含种子的首页请求（小于 1,100,000 字节，gzip 小于 470,000 字节）。自动检查世界引擎、助理执行器、设置页、聊天界面及拼音词库均不在首屏静态图，也不在消息首页实际请求中。

## P2 / P3：产品承诺与细节

- 保留 12 种表情。产品引导只介绍待机、思考、忙碌、完成、遇到困难这五个核心状态；其余是可选互动表现，不承诺小尺寸全部可辨。`SOUL_ORB_CORE_STATES` 明确该集合，聘用引导同步说明，具体结果以事项状态和办事记录为准。
- 今日前三张卡片隐藏重复的“设为今日重点”；任务列表仍允许手动设置，已手动标记的任务仍可取消重点。排序、统计和持久数据语义保持原有契约。
- 6.1 待办：统一跟进补记和共享编辑器的日期选择视觉。需保留键盘/读屏支持、日期上下限、深浅色、小屏和 Android WebView 的可用性；当前继续使用已经通过功能验收的原生日期输入。
